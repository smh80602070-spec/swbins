# saga-unity 실기 테스트 방법

이 문서는 **사람이 직접 Unity 에디터를 켜서 손으로 조작해 보는 법**이다.
세션들이 해 온 "Saga/Playtest ... (Headless)" 메뉴 검증은 컴파일 오류·
씬 로드·수치 계산이 안 깨졌는지만 확인하는 것이고, **화면이 실제로 어떻게
보이는지·조작 손맛이 어떤지는 여전히 사람이 직접 봐야 한다.** 그게 이
문서가 다루는 "실기 테스트"다(같은 목적의 `saga-godot/docs/
HOW_TO_PLAYTEST.md`와 짝을 이룬다 — 두 프로젝트는 병행 트랙이라 별개
문서다).

---

## 1. Unity 에디터 준비

이 PC에는 이미 **Unity 6000.3.24f1**이 Unity Hub 경유로 설치돼 있다
(`C:\Program Files\Unity\Hub\Editor\6000.3.24f1`). 다른 PC에서 이
문서를 보고 있다면 버전이 다르거나 없을 수 있다 — 없으면 [Unity
Hub](https://unity.com/download)를 먼저 설치하고, Hub의 **Installs**
탭에서 이 프로젝트와 같은 버전(6000.3.24f1, 없으면 6000.3.x 최신)을
받는다.

설치 확인만 하고 싶으면:
```bash
find "/c/Program Files/Unity/Hub/Editor" -maxdepth 1
```

## 2. 프로젝트 열기

**새 PC(새 클론)면 열기 전에 사실 몸부터 받는다**(PLAN 110 ④). 사람 몸(Mixamo)은
공개 저장소에 못 올려 `Assets/Art/CharactersRealistic/` 가 비어 있다 — 그대로 열면
사람·괴물이 전부 캡슐로 서고, 빌드는 자산 검사(`SagaAssetGate`)가 막는다.

```bash
bash tools/realistic-pack.sh pull             # 구글 드라이브 gdrive:saga-assets 에서 받아 md5 대조 → fetch (rclone, 아래)
bash tools/realistic-pack.sh fetch            # 드라이브 없이: 조각을 보관함(기본 ~/saga-assets)에 두고 · 다른 자리면 fetch <폴더>
bash tools/realistic-pack.sh verify           # 언제든: 목록과 같은지 (OK 면 이 PC 빌드 = 다른 PC 빌드)
```

`pull` 은 PC 마다 한 번 준비가 필요하다: `winget install Rclone.Rclone` → 새 셸에서 `rclone config create gdrive drive scope=drive`(브라우저에서 구글 승인).

몸을 새로 받거나 고친 PC 는 `manifest` → `pack` → `push`(드라이브) → 목록(`tools/realistic/`) 커밋을 같이 한다.
이미 열어 둔 Unity 가 있으면 닫고 받는다(폴더를 통째로 바꾼다).

1. Unity Hub를 실행한다
2. **Projects** 탭 → **Add** (또는 **Open**) 버튼 클릭
3. `C:\swbins\saga-unity` 폴더를 선택 (프로젝트 폴더 자체를 고른다,
   `.unity` 파일이 아니다)
4. 목록에 "saga-unity"가 추가되면 클릭해서 연다
5. 처음 열 때는 스크립트 컴파일·에셋 임포트로 시간이 좀 걸린다 —
   에디터 우하단 진행바가 끝날 때까지 기다린다

## 3. 씬 열고 실행하기

에디터 좌하단 **Project** 창에서 `Assets/Scenes/` 안의 `.unity` 파일을
더블클릭하면 그 씬이 **Scene** 뷰에 열린다. 그 상태에서 위쪽 가운데
**▶ Play** 버튼(또는 **Ctrl+P**)을 누르면 **Game** 뷰에서 실제로
조작해 볼 수 있다. 다시 누르면(또는 Ctrl+P) 정지한다.

**씬이 비어 보이거나 코드 변경분이 안 보이면** — 이 씬들은 절차적으로
지어진 것이라(코드가 지형·건물·NPC를 배치), 에디터 메뉴 **Saga →
Build <씬이름> Scene**(아래 표의 "재빌드 메뉴" 칸)을 한 번 실행해
다시 지은 뒤 **Ctrl+S로 저장**하고 Play한다. 평소엔 이미 지어진 채로
커밋돼 있어 그냥 열고 Play만 해도 된다.

## 4. 게임별로 열 씬

| 게임 | 열 씬 (`Assets/Scenes/`) | 재빌드 메뉴 (Saga →) |
|---|---|---|
| 사가고 (GO) | `TestVillage.unity` | Build TestVillage Scene |
| 사가블로 (DUNGEON) | `TestDungeon.unity` | Build TestDungeon Scene |
| 사가의숲 (FOREST) | `TestVillageForest.unity` | Build TestVillageForest Scene |
| 사가스토리 (STORY) | `TestField.unity` | Build TestField Scene |
| 사가국지 (REALM) | `TestCity.unity` | Build TestCity Scene |

(`SampleScene.unity`는 Unity 템플릿 기본 씬 — 이 프로젝트와 무관, 안 연다)

**Saga 메뉴의 나머지 항목("Playtest ... (Headless)", "Simulate ...")은
사람이 쓰는 게 아니다** — 세션이 코드 검증용으로 배치 모드에서 돌리는
자동 확인이다. 에디터에서 직접 눌러도 동작은 하지만(창 없이 로그만
찍고 끝난다), 실기 테스트에는 위 "Build ... Scene" 항목만 쓴다.

## 5. 공통 조작 (다섯 판 대부분 같다)

**타이틀·흐름(2026-09-26, PLAN 110 ②)**: 빌드나 `Assets/Scenes/Title.unity` 에서 시작하면 타이틀이 뜬다 — 판 카드에서 **이어하기**(저장 있을 때)·**새로 시작**(저장이 있으면 지울지 묻는다). 판 안에서 **Esc**(안드로이드는 뒤로 가기) 또는 오른쪽 위 설정·저장 줄 왼쪽의 **Ⅱ 단추**(110 ⑤c, 컷 동안은 숨음) = 일시정지 메뉴(계속하기·저장·타이틀로·게임 종료). 타이틀 아래 **설정** = 언어(한국어/English)·전체 음량(0~100% 다섯 칸)·배경음·효과음·진동(폰만)을 **다섯 판에 한꺼번에**(판 안의 설정으로 한 판만 바꾼 값은 "판마다 다름"으로 보인다). 영어로 바꾸면 타이틀·일시정지 메뉴·판 설정 창·목표판·첫 화면 단추가 영어(110 ⑤c-2c-1 — 대사·도감·퀘스트·알림은 아직 한국어). 패널 배치(110 ⑤c-2a): GO 지도는 왼쪽 지도·오른쪽 글과 닫기, STORY 무예(K)는 가로 판에 두 열, REALM 성 목록은 3열 격자를 위아래로 끌어 넘긴다. 타이틀로 갈 때·앱을 뒤로 보낼 때·끌 때 자동 저장. 판 씬을 바로 열어도 되지만 그땐 타이틀로 가기가 빌드 씬 목록에 타이틀이 있을 때만 보인다(지금은 있다).

| 키 | 동작 |
|---|---|
| W A S D / 방향키 | 이동 (`Move` 액션) |
| Shift | 달리기 (`Sprint` 액션) |

사가고·사가블로·사가의숲 셋은 이 표대로 CharacterController로 걷는다.
사가스토리는 가로 이동만(아래 6절), 사가국지는 걸어 다니는 캐릭터가
없어(경영형) 이 표가 적용되지 않는다(6절 참고).

## 7. 세이브 파일 위치

다섯 판 모두 `Application.persistentDataPath`(이 PC·이 프로젝트 설정
기준 `%USERPROFILE%\AppData\LocalLow\SAGA Games\SAGA\` — 2026-09-27 회사명을 바꾸기 전엔 `DefaultCompany\SAGA`, 그때 있던 저장·에디터 설정은 새 자리로 복사해 둠)에 판마다
다른 JSON 파일로 저장한다 — 이름이 겹치지 않으니 한 폴더에 다 있어도
안전하다:

| 게임 | 파일명 |
|---|---|
| 사가고 | `save.json` |
| 사가블로 | `save_dungeon.json` |
| 사가의숲 | `save_forest.json` |
| 사가스토리 | `save_story.json` |
| 사가국지 | `save_realm.json` |

메모장으로 열어 손으로 고칠 수 있다 — 정확한 필드 이름·타입은 각 판의
`Data/*SaveState.cs`의 `SaveData` 클래스를 보고 맞춘다(saga-godot의
JSON 세이브와 달리 필드가 아직 자주 바뀌는 중이라 이 문서에 예시를
박아 두지 않는다 — 최신 필드는 코드가 정본).

### 12-6. 사가국지 시나리오 카드 (PLAN 109-16, 2026-09-30)

## 13. Playtest 쓰는 법 — `PlaytestKit` (tasks U-0001)

`Assets/Editor/PlaytestKit.cs` 가 Playtest 마다 따로 하던 세 가지를 맡는다. 본보기 = `PlaytestDungeonHeadless.Run()`.

- `PlaytestKit.Begin("[이름표]")` — 실패 수를 0 으로. `Check(cond, msg)`·`Fail(msg)` 로 세고 `Summary(name)` 이 `[name] OK`/`FAIL n` 한 줄을 남긴다.
- `using var s = PlaytestKit.IsolatedSaves("save_dungeon.json")` — 실제 세이브를 잠깐 치웠다 Dispose 에서 되돌린다(이름 없으면 `save*.json` 전부). 플레이 모드로 여러 프레임 도는 진단은 객체를 들고 있다가 끝날 때 Dispose. 프로세스가 죽어 남은 백업(`_playtest_saves_backup`)은 다음 호출이 먼저 되돌린다.
- `using var e = PlaytestKit.ErrorCounter()` — Error·Exception 로그를 `Fails` 에 센다(`Fail` 이 남긴 로그·에디터 검색 색인 로그는 제외).

- 세이브 칸 `tutDone`(GO v29·DUNGEON v15). 옛 세이브는 전부 끝난 것으로 읽는다(GO `MigrateStep(28)`·DUNGEON `version >= 15 ?`). **세이브 버전을 올리면 Playtest 가 하드코딩한 `"version":N` 도 같이 올려야 한다**(`grep -l 'version.*:29' Assets/Editor/*.cs`).
- 목표판 첫 줄을 검사하는 진단은 첫 프레임에 `Enabled = false` 로 끈다(`PlaytestHeadless`·`PlaytestDungeonHeadless`). 진단 `PlaytestTutorial.Run` → `[PlaytestTutorial] OK`.


## 18. 배경음 — `Saga.Core.Bgm` (tasks U-0014)

- 다섯 판의 `*Audio.PlayBgm`·`RefreshBgmVolume`(PlayerPrefs `…_vol_bgm`·설정 BGM 켜기/끄기)는 그대로 두고 재생만 `Bgm` 이 맡는다. 곡 찾기 = `Resources/Audio/Bgm/<판>-<장면>`(판 id `go·dungeon·forest·story·realm`, 장면 `main·field·battle`) → 없으면 부트스트랩이 준 곡(`Assets/Art/Audio/CC0_BGM/`) → 없으면 무음(오류 0). 곡이 바뀌면 1.5초 교차 페이드.
- 새 곡 넣는 법: `Assets/SagaCore/Resources/Audio/Bgm/<판>-<장면>.ogg` 로 두고 **같은 커밋에서 `SagaCredits` 표에 줄 추가**. GO 는 `GoBgmScene` 이 싸움 중이면 `go-battle`, 아니면 `go-main`. 다른 판의 장면 전환은 `Bgm.SetScene("battle")` 을 부르는 폴러를 붙이면 된다.
- 진단 `PlaytestBgm.Run` → `[PlaytestBgm] OK`(가짜 곡·주입 `Bgm.Loader`로 페이드·폴백·끄기·소리원 재생성·무곡 오류 0).
