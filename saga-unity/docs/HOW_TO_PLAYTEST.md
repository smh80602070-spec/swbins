# saga-unity 실기 테스트 방법

이 문서는 **사람이 직접 Unity 에디터를 켜서 손으로 조작해 보는 법**이다.
세션들이 해 온 "Saga/Playtest ... (Headless)" 메뉴 검증은 컴파일 오류·
씬 로드·수치 계산이 안 깨졌는지만 확인하는 것이고, **화면이 실제로 어떻게
보이는지·조작 손맛이 어떤지는 여전히 사람이 직접 봐야 한다.** 그게 이
문서가 다루는 "실기 테스트"다(같은 목적의 `saga-godot/docs/
HOW_TO_PLAYTEST.md`와 짝을 이룬다 — 두 프로젝트는 병행 트랙이라 별개
문서다).

---

## 1. Unity 에디터 준비

이 PC에는 이미 **Unity 6000.3.23f1**이 Unity Hub 경유로 설치돼 있다
(`C:\Program Files\Unity\Hub\Editor\6000.3.23f1`). 다른 PC에서 이
문서를 보고 있다면 버전이 다르거나 없을 수 있다 — 없으면 [Unity
Hub](https://unity.com/download)를 먼저 설치하고, Hub의 **Installs**
탭에서 이 프로젝트와 같은 버전(6000.3.23f1, 없으면 6000.3.x 최신)을
받는다.

설치 확인만 하고 싶으면:
```bash
find "/c/Program Files/Unity/Hub/Editor" -maxdepth 1
```

---

## 2. 프로젝트 열기

**새 PC(새 클론)면 열기 전에 사실 몸부터 받는다**(PLAN 110 ④). 사람 몸(Mixamo)은
공개 저장소에 못 올려 `Assets/Art/CharactersRealistic/` 가 비어 있다 — 그대로 열면
사람·괴물이 전부 캡슐로 서고, 빌드는 자산 검사(`SagaAssetGate`)가 막는다.

```bash
bash tools/realistic-pack.sh fetch            # 보관함 기본 ~/OneDrive/saga-assets (동기화 끝난 뒤) · 다른 자리면 fetch <폴더>
bash tools/realistic-pack.sh verify           # 언제든: 목록과 같은지 (OK 면 이 PC 빌드 = 다른 PC 빌드)
```

몸을 새로 받거나 고친 PC 는 `manifest` → `pack` → 목록(`tools/realistic/`) 커밋을 같이 한다.
이미 열어 둔 Unity 가 있으면 닫고 받는다(폴더를 통째로 바꾼다).

1. Unity Hub를 실행한다
2. **Projects** 탭 → **Add** (또는 **Open**) 버튼 클릭
3. `C:\swbins\saga-unity` 폴더를 선택 (프로젝트 폴더 자체를 고른다,
   `.unity` 파일이 아니다)
4. 목록에 "saga-unity"가 추가되면 클릭해서 연다
5. 처음 열 때는 스크립트 컴파일·에셋 임포트로 시간이 좀 걸린다 —
   에디터 우하단 진행바가 끝날 때까지 기다린다

---

## 3. 씬 열고 실행하기

에디터 좌하단 **Project** 창에서 `Assets/Scenes/` 안의 `.unity` 파일을
더블클릭하면 그 씬이 **Scene** 뷰에 열린다. 그 상태에서 위쪽 가운데
**▶ Play** 버튼(또는 **Ctrl+P**)을 누르면 **Game** 뷰에서 실제로
조작해 볼 수 있다. 다시 누르면(또는 Ctrl+P) 정지한다.

**씬이 비어 보이거나 코드 변경분이 안 보이면** — 이 씬들은 절차적으로
지어진 것이라(코드가 지형·건물·NPC를 배치), 에디터 메뉴 **Saga →
Build <씬이름> Scene**(아래 표의 "재빌드 메뉴" 칸)을 한 번 실행해
다시 지은 뒤 **Ctrl+S로 저장**하고 Play한다. 평소엔 이미 지어진 채로
커밋돼 있어 그냥 열고 Play만 해도 된다.

## 4. 게임별로 열 씬

| 게임 | 열 씬 (`Assets/Scenes/`) | 재빌드 메뉴 (Saga →) |
|---|---|---|
| 사가고 (GO) | `TestVillage.unity` | Build TestVillage Scene |
| 사가블로 (DUNGEON) | `TestDungeon.unity` | Build TestDungeon Scene |
| 사가의숲 (FOREST) | `TestVillageForest.unity` | Build TestVillageForest Scene |
| 사가스토리 (STORY) | `TestField.unity` | Build TestField Scene |
| 사가국지 (REALM) | `TestCity.unity` | Build TestCity Scene |

(`SampleScene.unity`는 Unity 템플릿 기본 씬 — 이 프로젝트와 무관, 안 연다)

**Saga 메뉴의 나머지 항목("Playtest ... (Headless)", "Simulate ...")은
사람이 쓰는 게 아니다** — 세션이 코드 검증용으로 배치 모드에서 돌리는
자동 확인이다. 에디터에서 직접 눌러도 동작은 하지만(창 없이 로그만
찍고 끝난다), 실기 테스트에는 위 "Build ... Scene" 항목만 쓴다.

## 5. 공통 조작 (다섯 판 대부분 같다)

**타이틀·흐름(2026-09-26, PLAN 110 ②)**: 빌드나 `Assets/Scenes/Title.unity` 에서 시작하면 타이틀이 뜬다 — 판 카드에서 **이어하기**(저장 있을 때)·**새로 시작**(저장이 있으면 지울지 묻는다). 판 안에서 **Esc**(안드로이드는 뒤로 가기) 또는 오른쪽 위 설정·저장 줄 왼쪽의 **Ⅱ 단추**(110 ⑤c, 컷 동안은 숨음) = 일시정지 메뉴(계속하기·저장·타이틀로·게임 종료). 타이틀 아래 **설정** = 언어(한국어/English)·전체 음량(0~100% 다섯 칸)·배경음·효과음·진동(폰만)을 **다섯 판에 한꺼번에**(판 안의 설정으로 한 판만 바꾼 값은 "판마다 다름"으로 보인다). 영어로 바꾸면 타이틀·일시정지 메뉴·판 설정 창·목표판·첫 화면 단추가 영어(110 ⑤c-2c-1 — 대사·도감·퀘스트·알림은 아직 한국어). 패널 배치(110 ⑤c-2a): GO 지도는 왼쪽 지도·오른쪽 글과 닫기, STORY 무예(K)는 가로 판에 두 열, REALM 성 목록은 3열 격자를 위아래로 끌어 넘긴다. 타이틀로 갈 때·앱을 뒤로 보낼 때·끌 때 자동 저장. 판 씬을 바로 열어도 되지만 그땐 타이틀로 가기가 빌드 씬 목록에 타이틀이 있을 때만 보인다(지금은 있다).

| 키 | 동작 |
|---|---|
| W A S D / 방향키 | 이동 (`Move` 액션) |
| Shift | 달리기 (`Sprint` 액션) |

사가고·사가블로·사가의숲 셋은 이 표대로 CharacterController로 걷는다.
사가스토리는 가로 이동만(아래 6절), 사가국지는 걸어 다니는 캐릭터가
없어(경영형) 이 표가 적용되지 않는다(6절 참고).

## 10. 폰 성능·발열 측정 (PLAN 110 ③, 2026-09-26)

측정용 APK `saga-unity/Build/Android/SAGA-perf.apk` — 보통 빌드와 같고 화면 아래에 한 줄(fps · 프레임 ms · 1% 낮은 fps · 배터리 온도 · 발열 단계 · 메모리 · 씬)과 타이틀 오른쪽 위 **자동 측정**·**성능 기록** 단추만 더 있다. 안드로이드 7.1 이상·64비트(arm64). 앱 id 는 아직 유니티 기본값이다(110 ⑥ 에서 바꾼다).

1. **설치** — 둘 중 하나.
   - APK 파일을 폰으로 옮겨(USB·클라우드·메신저 나에게 보내기) 눌러 설치 → "출처를 알 수 없는 앱" 허용.
   - USB 디버깅을 켠 폰을 PC 에 꽂고 `"C:\Program Files\Unity\Hub\Editor\6000.3.24f1\Editor\Data\PlaybackEngines\AndroidPlayer\SDK\platform-tools\adb.exe" install -r saga-unity\Build\Android\SAGA-perf.apk` (꽂아 두면 Claude 가 대신 깔고 기록 파일도 꺼낼 수 있다).
2. **자동 측정(약 5분)** — 충전기를 빼고 폰을 식힌 채 타이틀에서 **자동 측정**. 다섯 판을 차례로 열어 가만히 둔 채 판마다 몸풀기 10초 → 30fps 상한 그대로 30초("상한") → 상한 풀고 15초("풀기") → 타이틀로 돌아와 기록표가 뜬다. 자동 측정은 세이브를 안 건드린다.
3. **직접 놀기(발열)** — 판마다 5분쯤 실제로 놀고 타이틀로(Esc/뒤로 가기 → 타이틀로). 기록표에 "놀이" 줄이 남는다(판 이름·초·평균·1% 낮은·최장 프레임·최고 온도·발열 단계·메모리).
4. **보내 주기** — 타이틀 **성능 기록** 화면을 찍어 보내면 된다(최근 14줄). 파일은 폰의 `Android/data/<앱 id>/files/perf_log.json`.

읽는 법: "상한" 평균이 30 에 붙어 있고 1% 낮은 fps 가 25 위면 그 판은 버틴다. "풀기" 평균이 여유(40 이면 33% 남음). 발열 단계 0~6(3 이상이면 폰이 스스로 속도를 줄이기 시작). 온도는 배터리 기준.
