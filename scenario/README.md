# saga 다섯 판 시나리오 — 공통 설계 (정본)

다섯 판(사가고·사가블로·사가의숲·사가스토리·사가국지) 이야기의 **정본**이 이 폴더에 있다. 이 문서는 모든 판이 따르는 틀이다.
세 트랙(사가웹 `saga-web/<판>`, 사가고돗 `saga-godot`, 사가유니티 `saga-unity`)이 같은 시나리오 문서를 보고 **각자 구현**한다. 세 트랙은 코드를 공유하지 않는다.

| 판 | 시나리오 | 한 줄 |
|---|---|---|
| 사가고 | [saga-go.md](saga-go.md)·[10부~](saga-go-part10.md) | 청하 마을에서 시작해, 시대를 삼키는 시간 틈을 따라 별배 선장을 찾는 모험(1~9부 32장 구현(사가고돗) — 8부 1차 결말, 9부 굳은 거리, 10부 갈무리 벌 35장까지 구현, 11부 세갈래 고을 38장까지 구현 = 2차 결말) |
| 사가블로 | [saga-dungeon.md](saga-dungeon.md) | 모루골 굴혈 밑의 "이름을 먹는 틈"과 아홉 지역을 다섯 막으로 내려가는 부대장 |
| 사가의숲 | [saga-forest.md](saga-forest.md) | 하늘 금에서 시대 손님이 떨어지는 숲 마을 — 사계절 동안 "사라질 숲"을 "이어진 숲"으로 |
| 사가스토리 | [saga-story.md](saga-story.md) | 이름 없는 떠돌이가 네 번 전직하며 신야성에서 검각 암굴의 난세 문까지 |
| 사가국지 | [saga-realm.md](saga-realm.md) | 군웅 할거에 균열·폐허·묘역과 시간 틈 사람이 겹친 천하 — 조건으로 열리는 열전 사슬 |

## 0. 읽는 법

- 이 폴더는 **설계 층**(SAGA-DESIGN §9)이다. 날짜 세션 기록을 넣지 않는다. 이력은 각 트랙 HANDOFF·HISTORY 에 쓴다.
- 판별 파일은 한 벌에 30KB 까지만. 넘으면 부마다 파일을 나눈다(`saga-go-part6.md` 식). 목차를 먼저 grep(`grep -n "^## \|^### "`)한다.
- 이미 구현된 장은 **그 트랙 데이터가 정본**이다. 여기는 줄거리·뼈대만 둔다. 대사 전문을 이 폴더에 옮겨 적지 않는다.
- 아직 구현 안 된 장은 이 폴더가 정본이다. 구현하면서 바뀐 것(단계 수·보스·자리)은 여기에도 고친다.

## 1. 원칙 — 다섯 판 공통

1. **판마다 독립된 이야기.** 다섯 판은 세계관을 공유하지 않는다. 같은 낱말("시간 틈" 등)이 나와도 판마다 뜻이 다르고, 인물이 판을 건너가지 않는다.
   이름이 우연히 겹치는 것(사가고 반디·사가의숲 도깨비불 반디, 사가고 달음·사가의숲 택배 기사 달음)은 **별개 인물**이다.
2. **세 트랙은 같은 줄거리.** 한 판의 장 순서·인물·결말은 웹·Godot·유니티가 같다.
   트랙 사정에 따라 다를 수 있는 것은 (a) 단계 수(한 트랙에 없는 조작이면 대체 단계), (b) 무대 자리(그 트랙 지도의 가장 가까운 고정 지역), (c) 보스 몸(그 트랙에 있는 몸)이다.
   다른 점은 판별 파일 "트랙 메모"에 적는다.
3. **이름 정책**(루트 CLAUDE.md): 실존·원작 인물 실명 금지. 여기 인물은 전부 가상이다. 역사 인물은 그 판 도감 가명으로만 부른다.
   실제 사건 이름도 대사에 쓰지 않는다. 땅 이름은 쓸 수 있다.
4. **전체 퓨전 — 시나리오의 기본 문법**(SAGA-DESIGN §13, 사용자 지시 "시나리오는 과거·현대·미래 퓨전").
   모든 부·장에 과거·현대·미래가 **셋 다** 들어간다(사가블로·사가국지는 신화·이계를 더할 수 있다).
   장 카드의 "시대 섞기" 칸에 세 시대가 각각 무엇으로 나오는지(인물·적·무대 소품·장치 중 하나 이상) 적는다.
   한 칸이라도 비면 그 장은 기준 미달이다.
   부의 중심 시대는 하나로 두고 나머지 둘을 섞는다. 중심 시대는 부마다 돌려 한 판 안에서 한 시대로 치우치지 않게 한다.
5. **고정 특색 지역**(SAGA-DESIGN §12): 무대는 그 판의 이름 있는 고정 지역이다. 무작위 땅에 이야기를 세우지 않는다.
6. **원작 문법만.** 원작의 줄거리·대사·인물을 옮기지 않는다. 가져오는 건 "장 구조·단계 종류·보상 방식" 같은 문법뿐이다.
7. **막히지 않게.** 이야기는 기존 시스템(사냥·채집·전쟁)을 **시키는 길잡이**다. 새 시스템이 있어야만 풀리는 장은 그 시스템을 먼저 만든다. 없으면 "대체 단계"를 적어 둔다.
   실제 달력을 기다리게 하지 않는다(사가의숲 행사 장은 대체 조건을 둔다).

## 2. 짜임 — 부 · 장 · 단계

```
판 시나리오
 └ 부(部) / 막(幕) / 열전(列傳)   큰 줄기. 새 무대·새 적·새 동료가 하나씩 열린다
    └ 장(章)                     한 번 앉아 끝낼 크기(10~25분). 열리는 조건 하나 + 보상 하나
       └ 단계(step)              한 가지 행동. 아래 §3 단계 어휘 중 하나
```

- 부 머리에는 **무대(고정 지역) · 새로 나오는 인물 · 부의 적 · 끝나면 얻는 것**을 적는다.
- 장 카드 필드는 아홉이다. 판별 파일의 표가 이 순서를 따른다(표가 넓어지면 "시대 섞기"만 표 밑 줄로 뺄 수 있다).

| 필드 | 뜻 |
|---|---|
| id | 장 id — §4 규칙. **한 번 정하면 안 바꾼다** |
| 제목 | "제N장 · 제목" 의 제목 |
| 무대 | 고정 지역 이름(그 판 표 이름 그대로) |
| 열림 | 조건 — 레벨·앞 장·계절·층·달 등 |
| 줄거리 | 두세 줄 |
| 시대 섞기 | **필수** — 과거 · 현대 · 미래 각각 무엇으로 나오는가(예: 과 옛 제단 / 현 관측원 / 미 조종 기계) |
| 단계 뼈대 | §3 어휘로 차례대로(예: talk → kill → seal → duel → talk) |
| 적·보스 | 이 장의 보스(있으면)와 그 판 적 명단 |
| 보상 | 재화·해금·동료·칭호 |

## 3. 단계 어휘 — 다섯 판 공통 이름

모든 트랙이 같은 이름을 쓴다. 트랙은 자기 엔진에서 이 이름을 그대로 단계 type 으로 쓴다.
- **공통 단계**는 다섯 판 어디서나 뜻이 같다.
- **판 고유 단계**는 그 판에만 있다. 새 단계가 필요하면 이 표에 먼저 한 줄 더한 뒤 쓴다.

**공통 단계**

| 단계 | 뜻 | 사가고 구현 |
|---|---|---|
| talk | 인물 곁에서 말 걸기 → 대화(고르는 줄 있음) | 있음(세 트랙 중 Godot·웹) |
| go | 그 자리 반경 안에 들어가기 | 있음 |
| kill | 그 자리에 임무 적 무리(되살아나지 않음·전리품 없음) — 다 쓰러뜨리기 | 있음 |
| duel | 이야기 보스 하나 | 있음 |
| boss | 그 판에 이미 있는 보스(들판·층·지역 보스) 쓰러뜨리기 | 있음 |
| gather | 그 채집물 n 번 | 있음 |
| deliver | 물건을 그 인물·자리에 가져다주기 | — (사가고는 talk 로 대신) |
| follow | 인물이 길을 걷고 따라가기 | 있음 |
| chase | 달아나는 것을 따라잡기 | 있음 |
| defend | 장치·제단을 물결에서 지키기 | 있음 |
| climb | 높은 자리에 서기 | 있음 |
| choice | 고르는 대화 — 고른 쪽이 **세이브에 남아** 뒤 장 대사·보상이 갈린다 | — (사가고의 고르는 줄은 대답만 다르다) |
| wait | 시간 흐름(게임 시간·날·달) — 실제 시계를 기다리게 하지 않는다 | — |

## 4. id · 세이브 — 나중에 끼워 넣을 수 있게

- **장 id**: `ch<번호>` 는 사가고만 쓴다(이미 구현 — 인덱스 진행).
  나머지 넷은 **이름 id** `<부약자>_<낱말>` 을 쓴다(예: 블로 `a1_moru`, 숲 `sp_move`, 스토리 `p1_sinya`, 국지 `r194_start`).
  번호는 표시용이고, 진행은 id 로 저장한다. 그래야 가운데 장을 나중에 끼워 넣어도 세이브가 안 밀린다.
- **진행 세이브 필드 이름 `scenario`** — 세 트랙 공통, 읽는 쪽 기본값(없으면 처음부터 — 마이그레이션 불필요).
  ```
  scenario = { cur: "<장 id>", step: <단계 번호>, done: ["<장 id>", …], picks: { "<choice id>": <고른 번호> } }
  ```
  - 사가고는 이미 `story = { ch, step }`(웹 `save.story`·Godot `PartyState.story`)이라 **그대로 둔다**. 새 필드를 만들지 않는다.
  - 웹 사가스토리의 `save.side.story` 는 "첫 발 장면을 봤다" 표다. 시나리오 진행은 따로 `save.scenario` 에 둔다.
  - Godot 는 그 판 세이브 상태 파일에, 유니티는 그 판 `SaveState`(`SaveVersion` +1, 옛 버전은 빈 `scenario` 로 읽기)에 넣는다.
  - **세이브 키·앱 id 불변**(루트 CLAUDE.md). 필드 추가만 한다.
- **choice id**: `<장 id>.<낱말>`. 고른 것이 뒤 장을 가르면 그 장 카드 "보상"에 `picks` 조건을 적는다.
- **인물 id**: 판 안에서 영문 소문자(`hanbyeol` 식). 표시 이름만 바꿀 수 있고 id 는 안 바꾼다.

## 5. 추가하는 법 — 확장 규칙

1. **새 장**: 판별 파일 그 부 표에 한 줄(§2 아홉 필드 — 시대 섞기 세 칸 필수)을 쓴다. 끝에 붙이는 게 기본이다. 가운데 끼워도 id 진행이라 괜찮다.
   다음 장의 "열림" 조건은 새 장 id 로 고친다.
2. **새 부**: 판별 파일에 `## N부 · 이름` 절을 더한다. 머리 네 가지(무대·새 인물·적·얻는 것)부터 쓴다.
   판별 파일마다 **"다음 부 자리"** 절이 있다. 거기 적힌 실마리 중 하나를 골라 부로 올린다.
3. **곁가지(세계 임무·인물 사연)**: 본편 밖 짧은 사슬은 판별 파일 "곁가지 자리" 표에 id `side_<낱말>` 로 둔다.
   본편 진행과 따로 저장한다(`scenario.done` 에 같이 넣되 본편 `cur` 는 안 건드린다).
4. **새 단계 종류**: §3 표에 먼저 더한다. 그 뒤 트랙마다 엔진에 칸을 연다.
5. **트랙이 구현하면**: 아래 §7 진행표 칸을 고친다. 장 카드와 다르게 구현된 점은 판별 파일 "트랙 메모"에 한 줄 적는다.
6. **이름 새로 지을 때**: 가상 이름. 한 판 안에서 겹치지 않게 판별 파일 인물표에 먼저 올린다.

## 6. 트랙 구현 지도

| 판 | 사가웹 | 사가고돗(Godot) | 사가유니티 |
|---|---|---|---|
| 사가고 | `saga-go/js/story.js`(단계 엔진·1~9장) · `worldquest.js` | `games/saga_go/data/story.gd`(표) · `world/story_quest.gd`(엔진) — **정본 구현** | 없음. `Data/QuestState.cs` 한 건뿐 → 새 `Data/ScenarioData.cs`(표)·`ScenarioState.cs`(진행) |
| 사가블로 | 퀘스트 `js/data-quest.js`·`quest.js` 에 MAIN·CHAINS | 없음. 방 일곱 슬라이스 | `Data/QuestState.cs` 3단계 |
| 사가의숲 | 부탁 `js/data-village.js` QUESTS · `mail.js` · `visitor.js` | 부탁·하트(`world/villager_builder.gd`) | 택배·축제만 |
| 사가스토리 | 사명 `js/data-quest.js` · 첫 발 장면 `js/story.js`+`data-side.js` STORY | 사명 `data/story_combat.gd` QUESTS | 목표 둘 `Data/StoryQuestState.cs` |
| 사가국지 | 사연 `js/event.js` · 시나리오 `data-force.js` SCENARIOS | 특성 사연 `data/realm_events.gd` | 서사 카드 `Data/RealmEventState.cs` |

**트랙별로 넣는 자리(권장)**

- **사가웹**: 각 판에 `js/data-scenario.js`(표)와 `js/scenario.js`(엔진)를 새로 둔다.
  - 엔진은 사가고 `story.js` 의 단계 엔진(대화 창·금빛 기둥·목록·추적 줄)을 **복사해** 그 판 단계만 남긴다. `data.js` 처럼 복사본이다. 합치자고 하지 않는다.
  - 손잡이는 `scenario.on`. `sw.js` VERSION 을 올리고, `build-pc.bat` 목록에 더하고, `_test.html` 진단 항목을 둔다.
- **사가고돗**: 사가고는 지금 틀 그대로 이어 간다(`story.gd` CHAPTERS 끝에 덧붙임).
  - 다른 판은 `games/<판>/data/scenario.gd`(표)와 `world/scenario_runner.gd`(엔진)를 둔다.
  - 대화 창·카메라는 사가고 `story_quest.gd` 를 보고 그 판에 맞게 새로 짠다(판 사이 공용화는 saga_core 에 대화 창만 — 결정은 그 트랙 PLAN).
  - 점검은 `tools/probe_scenario_<판>.gd`.
- **사가유니티**: 각 판 `Data/ScenarioData.cs`(정적 표 — 이 폴더 장 카드를 C# 로 옮김)와 `Data/ScenarioState.cs`(진행·이벤트)를 둔다.
  - 기존 `QuestState` 는 1장 안의 단계로 흡수한다(보상 중복 방지 — 이미 끝낸 세이브는 그 단계를 건너뛴 것으로 본다).
  - 대화는 판별 기존 말 걸기(`VillagerTalk` 등)를 넓힌다. 헤드리스 점검은 `Assets/Editor/Playtest*` 에 항목을 더한다.

## 7. 진행표 — 판 × 트랙 (구현된 장)

구현할 때마다 이 표만 고친다(날짜 기록은 그 트랙 이력에).

| 판 | 장 총수(설계) | 사가웹 | 사가고돗 | 사가유니티 |
|---|---|---|---|---|
| 사가고 | 29 (8부 1차 결말) | 1~9장 | 1~29장 | 0 |
| 사가블로 | 16 (5막) | 1~16장(5막 전부 — `js/data-scenario.js`·`scenario.js`) | 0 | 0 (기존 3단계 퀘스트 — 1막에 흡수 예정) |
| 사가의숲 | 16 (사계절) | 1~16장(사계절 전부 — `js/data-scenario.js`·`scenario.js`) | 0 | 0 |
| 사가스토리 | 16 (4부) | 1~16장(1~4부 전부 — `js/data-scenario.js`·`scenario.js`, 첫 발 장면은 장 안 대사로 흡수) | 0 | 0 |
| 사가국지 | 16 사슬 (6막) | 6막 열여섯 카드 전부(`js/data-scenario.js`·`scenario.js` — event.js 사연 카드에 얹음) | 0 | 0 |

**권장 구현 순서**(사용자 결정 전 제안): 한 판씩 한 트랙에서 1부(1막)만 먼저 넣어 손맛을 본다. 그 뒤 나머지 트랙으로 옮긴다.
- 사가고는 웹 10장~, 유니티 1장~ 이식이 남았다.
- 나머지 넷은 **Godot 또는 웹 한 곳에서 1부부터**. 어느 판·트랙부터 할지는 사용자 결정이다.
