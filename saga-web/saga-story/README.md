# 사가종횡 (saga-story)

> 시리즈 전체 인계(다섯 게임 표·지시 이력·함정·다음 할 일)는 **`../../SAGA-HANDOFF.md`** 다.

**메이플스토리식 2D 사이드스크롤.** 뛰고, 썰고, 오른다.

**장기 지향점**: 맵과 맵 사이 로딩 없이 걸어서 이어지는 오픈월드 사이드스크롤을
목표로 한다.

```
run.bat          →  http://127.0.0.1:8794
start_server.bat →  같은 것, 브라우저를 열지 않는다 (허브 워치독용)
_test.html       →  자가진단 79항목
_demo.html       →  스크린샷용 데모 상태 (#boss · #hunt · #camp · #field · #dex · #log)
```

## 앞으로 — 3D 로 옮긴다 (`PLAN.md`)

이 폴더의 **`PLAN.md`** 가 앞으로의 방향이다. 이 README 의 나머지는 **지금까지 만든 것**이니,
손대기 전에 둘을 같이 본다.

가는 곳은 **3D 횡스크롤 액션 RPG** 다. 2D 를 3D 로 갈아 끼우는 것이 아니라, 옆으로 걷는
놀이에 **공간의 깊이**를 넣는 쪽이다 — Background / Midground / Foreground 레이어와,
실제로 놀이가 되는 Gameplay Depth.

**Phase 1~6** 으로 잘라 간다 — 현재 분석·3D 기반 → 몬스터·기본 공격 → 스킬·콤보 →
맵 확장·플랫폼 → 성장(레벨) → 콘텐츠(NPC).

계획 맨 앞에 **토큰 절약**이 규칙으로 박혀 있다 — 파일을 통째로 읽지 말고 필요한 곳만
찾아 읽기, 고친 곳만 짧게 보고하기. 큰 작업이라 그렇다.

## 자가진단

```
chrome --headless=new --disable-gpu --virtual-time-budget=45000 --dump-dom   http://127.0.0.1:PORT/_test.html        → RESULT n/n
```

**무작위는 씨앗으로 고정돼 있다.** `_test.html` 이 게임 스크립트를 불러오기 **전에**
`Math.random` 을 mulberry32(씨앗 20260824)로 갈아 둔다. 그래서 자동 순행을 몇 분치
굴려 보는 항목도 **매번 같은 수치**가 나온다 — 전에는 그 항목들이 드물게 실패했다
(같은 코드로 24/25 → 25/25). 게임 코드는 손대지 않았으니 실제 플레이는 그대로 무작위다.

세 번 돌려 결과가 **한 줄도 다르지 않은지**로 확인한다. 시각 기반 값(프로필 id 등)은
결과 문구에 넣지 않는다 — 넣으면 매번 달라져서 "무엇이 바뀌었나" 를 눈으로 못 쫓는다.

**어드민은 따로 본다.** 눌러야 도는 화면이라 `_test.html` 이 붙지 못한다:

```
chrome --headless=new --disable-gpu --dump-dom "http://127.0.0.1:PORT/_admin.html?selftest"   → ADMIN n/n
```

**소리가 실제로 나는지도 따로 본다.** 진단은 아무것도 누르지 않아 브라우저가 소리를
늘 잠가 두기 때문이다(그 규칙이 맞다). `_sfxcheck.html` 이 `unlock()` 을 스스로 부른다:

```
chrome --headless=new --disable-gpu --dump-dom http://127.0.0.1:PORT/_sfxcheck.html   → SFX unlock=true · 낸 소리 n/n
```

실루엣을 진하게 두른다. 작은 그림에는 안쪽 선을 긋지 않는다(그으면 형태가 선에
먹혀 검은 덩어리가 된다). 넥슨의 실제 에셋은 쓰지 않는다 — **그림 문법만** 옮기고
그림은 이 저장소의 코드가 그린다.

## 이 게임만의 것

- **내 몸은 앞에 세운 인물** — 그 인물의 능력치가 체력·공격력이 된다(`side.power`).
  도감에서 다른 인물을 앞에 세우거나 승급하면 세진다
- **물리** — 중력 1900 · 점프 760 · 달리기 270. 발판은 **위에서만** 밟힌다
  (아래에서 올라갈 때는 통과한다 — 사이드스크롤의 기본 감각)
- **줄과 문** — 밧줄·사다리는 **↑↓ 로 오르내리고**(줄 위에서 Space 는 손 떼기),
  ↓+Space 로 밟고 선 발판을 빠져나간다. 사냥터 끝의 **문 앞에서 ↑** 를 누르면
  옆 사냥터로 걸어 넘어간다 — 체력·기력·주운 금은 그대로 이어진다.
  좌표는 `data-side.js` 의 `ropes`(`[x, 위, 아래, 종류]`) · `portals`(`[x, 갈 곳]`)
- **직업과 무예** — 처음엔 **무명**(연참·횡소·기탄·기합 넷 고정).
  **Lv.10 에 1차 전직**(무사·궁수·협객·방사), **Lv.25 에 2차**(장군·신궁·자객·도사),
  **Lv.45 에 3차**(원수·비장·귀영·진인 — 2026-08-26),
  **Lv.70 에 4차**(전신·궁성·명왕·천존 — 2026-09-10, 갈래의 끝).
  되돌릴 수 없다. 윗자리로 오르려면 **아랫자리 무예 하나를** 2차는 5, 3차는 8,
  **4차는 10(만렙)** 이상 익혀야 한다. **갈래는 넷 그대로**다 — 다섯으로 늘리면
  인물 능력치와 무기가 따라가야 한다. 대신 각 갈래를 두 단 더 높였다.
  **각 갈래 네 단마다 다섯째 무예도 얹었다**(2026-09-10 — 무사=관통(bolt)·
  궁수=물러나며 쏘기(dash)·협객=발차기(aoe)·방사=축지(dash), 그 갈래에
  없던 효과를 새로 안 만들고 골라 채웠다). 직업 **17** · 무예 **80**
- **무예 점수(SP)** — 레벨마다 3점. **세이브에 담지 않는다** — 총점 (레벨-1)×3 에서
  찍은 레벨의 합을 뺀 것이 남은 점수다(파생값이라 옛 세이브에도 그냥 맞는다).
  **찍은 무예만 조작 띠(1~8)에 놓인다** — 원작 그대로.
  띠는 여덟 칸이고 **윗자리 무예부터** 놓는다(4차까지 열리면 한 갈래가 열다섯이라
  아래에서부터 채우면 새로 얻은 무예가 영영 자리를 못 잡는다 — 4차 넷 + 3차 넷이
  이미 여덟을 정확히 채우므로 띠를 더 늘릴 필요는 없다)
- **무예의 효과 아홉** — `melee`(앞) · `aoe`(주위) · `bolt`(관통) · `arrow`(첫 하나) ·
  `volley`(여러 발) · `dash`(밀고 나가며) · `rain`(앞쪽에 쏟기) · `buff` · `heal`.
  데이터(`data-job.js`)는 무엇을 할지만 적고 **어떻게 하는지는 `side.js` 에만** 있다.
  **3차·4차 서른여섯을 넣으며 효과는 하나도 안 늘렸다** — 늘리면 규칙을 두 곳에
  적게 된다(진단 '무예 예순넷은 side.js 가 아는 효과 아홉만 쓴다')
- **사냥터 4곳** — 허창 들판(Lv.1) → 오림 숲(Lv.5) → 한중 굴혈(Lv.12) →
  **호로곡(葫蘆谷)(Lv.25)**. 적은 던전 게임과 같은 `data-enemy.js` 를 쓴다
- **멀리서 쏘는 적** — **든 무기가 곧 사거리다.** 활(`bow`)·조총(`staff`)을 든 적은
  사거리(360·420)에 들면 **멈춰서 쏜다**. `data-enemy.js` 는 던전 게임과 나눠 든 같은
  파일이라 거기에 `ranged` 칸을 만들지 않았다 — 규칙은 `data-side.js` 의 `rangedOf()`
- **장비** — 부위 일곱(무기·투구·갑옷·전군·전화·수갑·망토) × 네 단(Lv.1·5·12·20).
  낀 것이 **인물의 힘 위에 얹힌다**(`side.power()` 가 `gear.bonus()` 를 더한다).
  방어는 맞는 값을 깎되 **6할까지만** 막는다 — 넘게 두면 후반에 아무것도 안 아파진다
- **주문서** — 원작의 그 물건. 100%·60%·10% 셋. **실패해도 물건은 터지지 않고**
  업횟(`left`)만 닳는다. 초기 원작도 그랬다
- **가방 24칸 · 저자(상점)** — 차면 못 줍는다(그 답답함이 규칙이다). 파는 값은 산 값의 3할
- **사명(使命)** — 원작의 퀘스트. 열셋(되받는 것 셋 포함). **받은 뒤부터** 센다.
  장비·무예·금처럼 **보면 아는 것은 세어 두지 않고 그때그때 읽는다** —
  세어 두면 장비를 벗었다 껴도 수가 남아 어긋난다. 사냥터 시트 안에 있다
- **앉아 쉬기** — ↓ 를 누른 채 가만히 있으면 앉아 체력 2%/초 · 기력 5.5%/초를 채운다.
  곁에 적이 오면 일어선다 (원작에서 의자에 앉던 그 자리다)

  좁게 잡은 것은 걷다가 잘못 눌리지 않게 하려는 것이다

  │   위 45%  ↑ / 점프   │   줄·문 앞이면 오르기·들어가기, 아니면 점프
  ├──────┬───────┬──────┤

- 규칙 값은 모듈이 **켜질 때 한 번** 읽는다. 바꾼 뒤에는 게임 창을 새로고침해야 듣는다
- **자가진단·데모는 손잡이를 읽지 않는다**(`DG_NO_TUNE`) — 진단 83 항목 중 넷이 그 못이다
- 세이브를 고치면 `POKE_KEY` 를 두드린다. 게임 창이 열려 있으면 그것을 보고 다시 읽는다
  (게임이 틈틈이 저장하므로, 안 그러면 어드민이 고친 값이 곧 덮인다)
- **게임에서 되돌릴 수 없는 것을 되돌린다** — 전직이 그렇다. 어드민의 몫은 "그 상황으로
  곧장 가는 것" 이지 규칙을 지키는 것이 아니다. 규칙(`job.canJoin`)은 한 줄도 안 건드렸다
- 사명을 채우는 방법은 **갈래마다 다르다.** 쌓이는 것(적·보스)은 세이브의 수를 올리면
  되지만, 보면 아는 것(장비·무예·금)은 세어 두지 않으므로 **실제로 그 상태를 만든다**
- 어드민은 PC 단독판에도 `sw.js` 캐시에도 안 들어간다(빌드가 `index.html` 만 훑는다)

## 몸짓 마저 — 회피·마심(dodge·interaction) (2026-09-10, 이어서)

공격 몸짓을 잇고 나서, `asset3d.js` 몸짓 표(`SLOTS`)에 남아 있던 자리를
마저 세어 봤다 — `dodge`·`interaction`·`death` 셋이 더 있었다. 사가나락를
포함한 **다섯 판 전부 dodge·interaction·death는 여태 아무도 안 부르고
있었다**(공격조차 사가나락 하나뿐이었다). 이번엔 이 판이 먼저 간다.

- **회피** — `dodge()`가 이미 있던 `DODGE_INVULN`(0.35초, 구르는 무적
  시간)과 같은 길이로 `p.dodgeAnim`을 켠다. 공격과 동시에 겹칠 수 있어
  (연속 조작 시) 몸짓 우선순위를 **맞음 > 회피 > 공격 > 마심/대화 > 걷기·
  가만있기** 순으로 정했다 — 회피가 공격보다 위인 건 몸이 실제로 움직이는
  동작이 정지 동작보다 더 커 보여야 자연스럽기 때문이다.
- **마심·대화(interaction)** — 탕약(Q)을 마실 때 `p.drinkAnim`(0.4초)을
  새로 켜고, 마을 사람과 대화 중(`run.talk`가 살아 있는 동안)에도 같은
  자리를 쓴다 — 둘 다 "그 자리에 서서 뭔가 한다"는 결이 같다.
- 셋 다 **자리가 없는 몸이면 자동으로 옆자리로 물러난다**(asset3d.js의
  `FALLBACK` 표 — dodge 없으면 run/walk, interaction 없으면 idle) — UAL1에
  진짜 해당 클립이 있는지 몰라도 최악의 경우 이전과 똑같이 보일 뿐이라
  안전하게 켤 수 있었다.
- **death는 이번에도 건너뛰었다** — 이유가 attack/dodge와 다르다. 죽은
  적은 `kill()`이 `run.enemies`에서 즉시 지우고, 화면의 `enemyPool`은
  **배열 인덱스로** 그 자리를 다음 적에게 바로 물려준다(죽은 모델이
  머물 자리가 아예 없다). 죽는 순간의 시늉은 이미 2D `fall` fx(화면
  층, 2·3D 공통)가 맡고 있다 — 스러지는 몸을 3D에서 따로 붙잡아 두려면
  적 풀을 판정 배열과 분리하는 손질이 필요해, 다섯 판 어디에도 없는
  새 구조를 이번에 혼자 만드는 셈이라 미뤘다.

## 마법형(魔法型) 몬스터 — PLAN §13 마지막 유형 (2026-09-10, 이어서)

앞서 "구조 추측이 필요해 보류한다"고 적었던 걸 사용자가 만들어 달라고
해서 이어 만들었다. **다섯 판이 나눠 쓰는 `data-enemy.js`는 이번에도
안 건드렸다** — 근접형 잡졸 하나를 굴려서(12%, `MAGIC_CHANCE`) "마법형"
역으로 바꿔 쓴다(희귀·미니보스와 같은 결). 이걸로 §13의 다섯 유형
(근접·원거리·돌진·탱커·마법)에 희귀·보스형까지 **일곱 다 갖췄다.**

  플레이어의 높이를 서서히 따라온다(`MAGIC_HOME`, 세로로만 — 가로는
  그대로 직선). **같은 높이면 피하기 쉬웠던 원거리와 달리, 발판을
  바꿔도 계속 쫓아오니 자리를 크게 옮기거나 회피/기탄으로 받아쳐야

  잡졸이라는 결 — 새 이름·새 그림이 필요 없다).
  3D에서는 보랏빛(`#6a4fc0`, 희귀=금빛·미니보스=자주와 안 겹치는 색)으로
  물들이고, 2D 화면(`side-view.js`)에서는 구슬을 옅은 보라 이중원으로
  그려 활(줄+화살촉)·조총(주황 점)과 구별한다.
- 공격 몸짓(`e.atkAnim`)도 그대로 물려받는다 — 새로 만든 게 아니라
  원거리형과 같은 자리에서 켠다.
- 자가진단 147 → **148**(높이 달라도 발사하는지 확인), 세 번 동일.

## 몸짓 마지막 하나 — 북돋움 중 run (2026-09-10, 이어서)

몸짓 표(`SLOTS`)를 다시 훑다 하나 더 찾았다 — **북돋움(buff, §12 무예
효과)이 걸린 동안 실제로 더 빠르게 걷는데**(`side.js`의 속도 배수

`side-view3d.js`가 `p.buff`를 직접 읽어(내보내는 함수 하나 안 늘리고
`buffOn()`과 같은 만료 조건만 그대로 베꼈다) buff 중 걷고 있으면
`run`으로 바꿔 그린다. `run` 전용 클립이 없는 몸이면 `walk`로 조용히
물러난다(asset3d.js FALLBACK 표, 새로 손댈 것 없음).

- 이 항목은 `_test.html`에 안 실린다 — `side-view3d.js` 자체가 진단
  하네스에 로드되지 않는 화면 전용 파일이라(3D 캔버스는 원래 자가진단
  대상이 아니다) 자가진단 수치는 148 그대로다. `sw.js` → `side-v0.45.1`.
- **실기기 확인 전** — 북돋움 걸고 달릴 때 run 몸짓이 눈에 띄게 다르게
  보이는지 다음 세션 손맛부터 물어볼 것. **이걸로 asset3d.js 몸짓 표
  아홉 자리 중 death·sprint 둘만 남았다** — death는 위에 적은 이유로,
  sprint는 이 판에 3단계 속도가 없어서(걷기/북돋움 둘뿐) 보류한다.

## 몬스터 death 몸짓 — 적 풀을 판정 배열과 분리 (2026-09-11, 이어서)

지난 "몸짓 마저" 절에 "**death는 이 이유로 보류한다**"고 적어 뒀던 것을
채웠다. 막혔던 이유: `kill()`이 죽은 적을 `run.enemies`(판정 배열)에서
그 자리에서 바로 `splice`하고, 화면(`side-view3d.js`)의 `enemyPool`은
**배열 인덱스로** 배우(mesh)를 재활용한다 — 그래서 death 몸짓이 도는
몇 프레임 사이에 뒤 적들의 인덱스가 하나씩 당겨져, 죽어가던 자리에
**다른 살아있는 적의 모습**이 불쑥 끼어들었을 것이다.

`run.dying`(판정과 분리된 새 목록)을 얹어 풀었다 — `kill()`은 여전히
`run.enemies`에서 즉시 빼지만(auto.js 타게팅 등 기존 소비자는 한 줄도
안 건드림), 죽는 순간의 모습(위치·종류·색)을 `uid`와 함께 `run.dying`에
따로 적어 둔다. `update()`가 `dur`(잡졸 0.55~0.7초·보스 1.1초, 기존
`fx` 'fall' 연출과 같은 길이)만큼 들고 있다가 치운다. 화면 쪽은
`enemyPool`과 나란한 `deadMeshes`(uid → mesh 맵)를 새로 둬 인덱스가
아니라 **uid로** 배우를 붙든다 — 죽는 도중 다른 적이 그 자리를 이어받을
수가 없다. `asset3d.js`의 `death` 몸짓 자리(진작부터 있었다, `hit`→`idle`
순으로 대체)를 처음 실제로 불러 쓰고, 한 번만 돌고 마지막 자세에서 멎게
(`clampWhenFinished`+`LoopOnce`) 손봤다 — 안 그러면 쓰러진 채 다시
일어서는 꼴이 된다. GLB를 못 받아 도형인 채면(다른 배우와 같은 규칙)
`death` 클립이 없어 조용히 가만히 서 있다가 사라진다.

`_test.html`에 `run.dying`이 uid로 등록되고 `dur`가 지나면 정리되는지
보는 진단을 추가했다(148 → **149**). `sw.js` → `side-v0.46.2`.
**아직 실기기 확인 전** — 실제 GLB 사람 팩에 죽는 클립이 있는지, 있다면
자연스럽게 도는지 다음에 물어볼 것(없으면 hit/idle로 대체되어 "짧게
휘청하고 사라지는" 정도로 보일 것이다).
