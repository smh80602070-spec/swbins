# 42. 소리(音) — 절차적 효과음 신설 (2026-09-10)

다섯 판 중 사가블로(`sfx.js`, 33종)·사가고(`audio.js`)·사가스토리(`sfx.js`+CC0
BGM)는 이미 소리가 있는데 **이 판만 여태 무음**이었다 — 계절·낚시·채집·유성·
편지 등 "삶의 결" 콘텐츠가 다섯 판 중 가장 풍부한데 정작 무음이라 손실이
크다는 판단으로 최우선으로 뽑혔다(다른 판에서 빌려올 기능 후보 조사, 1위).

**사가블로 `js/sfx.js`를 그대로 본으로 삼았다** — WebAudio 로 절차적으로
낸다(에셋 없음), 겹은 tone·noise·chime 셋, 첫 입력 전엔 못 낸다(`unlock()`이
스스로 문서에 건다), 요청은 꺼져 있어도 `_tail()`에 남는다(판정 층과 소리
층을 가른다), 같은 소리는 최소 간격, `AudioContext`는 한 번만. 소리 스무 가지:
발소리 다섯(흙길·돌길·물길·풀밭·모래펄, 공사 다섯 갈래와 같은 이름) · 낚시
셋(입질·놓침·건짐) · 곤충 셋(벌떼·달아남·채집) · 문 둘(집·굴, 다른 잔향) ·
레벨업 · 계절 전환 · 유성 · 편지 · 기증 · 선물 둘(그냥/아주 반김).

**`village.js`·`animal.js`·`weather.js`·`town.js`는 한 글자도 안 건드렸다.**
두 갈래로 듣는다 — ① 이미 있는 이벤트(`village:fish`·`village:bug`·
`village:home`·`village:cave`·`levelup`)를 `js/sfx.js`가 스스로 구독 ②
판정 파일엔 없지만 **읽기 전용 공개 함수로 값이 드러나는 것**(발소리 지형·
계절·유성)은 `js/sfx.js`가 220ms마다 폴링해서 값이 바뀔 때만 운다
(`village.raw()`·`village.tileAt()`·`villageData.season()`·`town.starNow()`
전부 이미 있던 읽기 전용 함수라 판정을 안 건드리고도 듣는다). 딱 세 자리에만
한 줄씩 보탰다 — `mail.js`의 `put()`(새 편지가 오면 알아야 하는데 그런
이벤트가 없었다) · `ui.js`의 기증·선물 결과 처리(이미 결과가 난 다음의 UI
반응 지점이라 안전하다).

상단 🔊(`#btn-sound`, `game.js`의 `bindTopbar()`가 다른 아이콘 버튼과 같은
결로 잠금·해제) 로 끄고 켠다(`core.save.settings.sound`, 다른 판과 같은 이름).

검증 — `_test.html`에 소리표 완결성·꺼져도 기록됨·이벤트 연결·계절/유성
폴링(값을 잠깐 바꿔치기해 "바뀌었을 때만 운다"를 확인, `season()`이 실제
달력 달을 읽어 진단 중엔 못 바꾸기 때문) 항목 여덟을 더했다. 자가진단
237→245(3회 동일). `_sfxcheck.html`(스무 소리를 하나씩 내 보는 확인용
페이지, `unlock()`을 직접 불러 브라우저 제스처 없이도 들어볼 수 있다)도
새로 두었다.

**실기 확인 전이다** — 실제로 소리가 나는지·거슬리지 않는지는 사용자가
직접 들어봐야 한다. `_sfxcheck.html`을 열어 스무 소리를 순서대로 들어보고,

# 43. 퓨전 방향 선언 + 첫 콘텐츠 셋 (2026-09-10)

> "괴물이 나와도 되고 캐릭터가 달라도 되고"
> "퓨전이야"
> "현대적이어도 되고 중세적이어도 되고 미래적이어도 되고"
> "더 추가할 사항 있나 보고 원작보다 너 좋으면 좋겠어"

2절이 이미 "특정 게임의 그래픽을 그대로 복제하지 않는다"고 적어 뒀지만
그건 그림체 얘기였다. 이번 지시는 더 넓다 — **콘텐츠·캐릭터·시대 배경도**
동물의숲 틀에 안 갇혀도 된다. 목표는 원작 재현이 아니라 **원작보다 나은
것**이다. §4(에셋 구조)의 `characters/monsters/`, §20(랜덤 이벤트)의
"몬스터 습격", §10(고정 배치)의 "보스 지역"·"폐허"는 이제 다 정당한
확장 후보다.

**지키는 것은 그대로다** — 실존 인물 실명 금지(다섯 판 공통 정책, 이 지시와
무관), 원작사의 실제 에셋 금지, 공개 저장소 라이선스 정책(CC0 우선,
재배포 불가 자산 금지). "퓨전"은 콘텐츠·시대 자유를 뜻하지, 라이선스·
저작권 원칙을 느슨하게 한다는 뜻이 아니다.

첫 콘텐츠 셋(전부 크로스게임 CC0 자산 재사용, 새 전투 시스템 없음):

# 44. 3D NPC "안 보인다" 재신고 — 진짜 원인은 안개였다 (2026-09-10)

2026-09-09에 카메라~플레이어 거리를 늘려 "고쳤다"고 남겼지만 사용자가
"아직도 안 보임"으로 다시 신고했다. 실제 좌표를 재 보니(Node로 `village.js`를
그대로 불러 좌표만 계산) 숲 NPC 여섯이 마을 중심에서 **67~113m** 떨어져
있는데, `village-view3d.js`의 안개 먼 끝(`FOG_FAR`)이 **160m**뿐이었다 —
맑은 날에도 절반 넘게 안개에 덮이고 비·눈이면 80~136m로 더 좁아져 가장 먼
NPC는 거의 안 보였을 것이다. NPC는 거리 컬링이 없어(원래부터 그렇게
설계됐다) 장면엔 계속 서 있었다 — 안개가 시각적으로 삼켰을 뿐이다.

`FOG_FAR` 160 → 320(`FOG_NEAR` 30 그대로). fog는 셰이더 블렌딩 값이라
렌더 비용이 늘지 않는다. 자가진단 259/259 그대로(세 번 동일, fog는 픽셀
검사가 아니라 새 항목 없음). `sw.js` → `village-v0.54.0`.

**곧바로 사용자가 "안개는 중요 하지 않으니 제거 하던지 옵션에 키고
끄는걸 추가해 끄는게 기본이고"로 위 수치 조정 자체를 되돌렸다.** 안개
거리를 맞게 늘렸는지 다투는 대신, **안개를 아예 옵션으로 빼고 기본을
꺼짐으로** 정하는 쪽이 더 단순하고 확실하다 — 꺼져 있으면 거리와 무관하게
NPC·모든 사물이 또렷이 보인다. `village3d.fog` 손잡이(`core.tuned`/`setTune`,
새로고침해도 유지, `village3d.quality`와 같은 결) 신설, 기본값 0(꺼짐).
`init()`의 `scene.fog` 생성과 `syncSky()`의 안개 갱신을 `FOG_ON()`/`scene.fog`
존재 여부로 감쌌다 — 꺼져 있으면 `scene.fog`가 아예 `null`이라 안개 계산
자체가 안 돈다. ⚙️ 설정 시트(그래픽 품질 옆)에 켜짐/꺼짐 버튼 신설
(`ui.js`의 `fog-toggle`). 위 `FOG_FAR` 320 값은 **죽지 않았다** — 사용자가
직접 안개를 켜면 그 넉넉해진 거리로 켜진다. 자가진단에 기본값·손잡이
왕복 확인 하나 추가, 259 → **260**(세 번 동일).

**실기 확인 전.**

# 44-2. 3D NPC "아직도 안 보인다" — 진짜 빠진 건 residents였다 (2026-09-11)

§44의 안개 진단은 틀리지 않았지만(안개를 꺼도 여전히 신고가 이어져), **정작
사용자가 마주치는 "NPC"는 숲 고정 여섯(`village.js`의 `npcs`, §44가 다룬
대상)이 아니라 마을 한복판을 어슬렁대는 **주민 다섯**(`residents`,
`buildResidents()`가 HEROES 로스터에서 뽑는다, `folk.js`가 매 프레임 걷게
한다)이었다. 2D(`village-view.js`)는 `drawResident()`로 이 다섯을 그리고
있었는데, **`village-view3d.js`에는 이들을 세우는 함수 자체가 없었다** —
`syncNpcs()`가 숲 여섯만 돌고, `step()`엔 residents를 다루는 호출이
한 줄도 없었다(grep으로 확인, `resident`라는 문자열이 이 파일에 아예
없었다). 안개·거리를 아무리 고쳐도 애초에 안 세워지는 인물이라 신고가
안 사라진 것이 당연했다.

`syncNpcs()` 바로 아래 `syncResidents()`를 새로 만들어(같은 `asset3d().build
('hero', {id: res.id}, cb)` 조합, `res3d` 라는 별도 창고, `step()`의
`syncNpcs(dt)` 다음 줄에 호출 추가) 마을 주민도 3D에 실제로 선다. 주민은
`folk.js`가 실제로 걸어 다니게 하므로(숲 NPC 여섯은 고정 자리라 회전이
없었다) `syncScatter()`의 짐승 처리(TURNING_KIND)와 같은 결로 이동 방향으로
몸을 트는 것과 idle/walk 몸짓 전환도 같이 얹었다. 진단 전용
`residentMeshCount()`를 `npcMeshCount()` 옆에 추가(둘 다 init 전엔 0).

**실기 확인 전** — 위 원칙(§"Claude Code 최종 작업 원칙")대로 지금 바로
확인을 요청하지 않는다. 다음에 실기 확인할 때 마을 안 3D 화면에서 다섯
주민이 걸어 다니는지, `DG.villageView3d.residentMeshCount()`가 5를
돌려주는지 확인할 것.

# 45. 다음 큰 방향(아직 미착수, 설계만) — 맵 크기 대비 빈 밀도 + "다른 마을" + 배달 아르바이트 (2026-09-10)

**아직 코드는 하나도 안 건드렸다.** 사용자가 여러 메시지에 걸쳐 낸 아이디어를
그대로 받아 적고, 실현 가능성을 확인한 뒤 하나의 설계로 정리해 둔다 — 다음
세션(이 대화 맥락이 없어도)이 바로 시작할 수 있게.

## 사용자 발언 그대로

> "맵이 큰거에 비해 npc가 없고 다른 마을도 있다는 걸 추가하려고"
> "새로운 이벤트가 있는 거지 다른말은 현대 미래 과거 일수 있고"
> "예를 로봇트랑 논다던지 택배를 한더지 같은 우체국 처럼 여러 마을을
> 돌아 다닌 거지 배달 알바같은"
> "우주 여행도 있고" / "여러가지" / "생각해봐"

## 진단 — 왜 "크기에 비해 빈다"고 느끼나

`forestMargin` 기본값이 2026-09-09에 20→32로 늘면서 세계가 커졌는데
(바깥 경계까지 반지름 약 100타일 ≈ 300m대), 그 안의 **고정 콘텐츠는 여섯
NPC·캠프 둘·동굴·폐허 하나**뿐이라 인구 밀도가 넓이를 못 따라간다. 게다가
NPC는 원래 거리 컬링이 없어(§44) 늘 그 여섯 자리 그대로다 — 늘어난 땅
대부분은 그냥 바이옴 장식(나무·바위 등)만 있는 빈 걸음이다.

## 설계 — "택배 아르바이트"로 다른 마을들을 잇는다

**핵심 루프**: 우체통(`mail.js`가 이미 "편지함"으로 가진 개념)에서 소포를
받아, 다른(멀리 떨어진, 시대색이 다른) 마을까지 걸어가 전해주고 보상을
받는다. **반복 가능한 일**이라 "배달 알바" 표현과 맞고, 넓은 지도를 걷는
이유를 계속 만들어 준다(한 번 발견하고 끝나는 랜드마크가 아니다).

- 데이터 하나(`DELIVERIES` 같은 표: `from`·`to`·`item`·`reward`)로 정한다
  (PLAN 19절 "복잡한 시스템은 안 만든다" 그대로 따른다). 소포는 가방에
  들어가되 못 팔게(`giftOnly` 같은 플래그) 막는다.
  픽업·배달 둘 다 기존 `focus()`/`interact()` 표에 한 줄씩 끼우면 된다 —
  새 상호작용 프레임워크가 필요 없다.
- 첫 목적지는 **1~2곳**만 — 한 번에 다 짓지 않는다(PLAN "절대 하지 말 것"
  원칙 그대로).

# 46. 우주기지 · 배달(택배 알바) 첫 목적지 — §45 설계를 실제로 지었다 (2026-09-11)

§45가 설계만 하고 멈췄던 것을 사용자가 "진행해줘"로 승인, 세 질문(고정
마을·남서 더 먼 대각선·무제한 반복)에 답을 받고 그대로 지었다. **PLAN
"절대 하지 말 것" 원칙대로 첫 목적지 하나만** — 우주기지 하나, 현대·과거
목적지는 여전히 미착수(§45 표 그대로 다음 몫).

## 지은 것

- **`village.js`**: `spaceBaseSpot()`/`inSpaceBase()`(다른 다섯 고정 자리와
  같은 결의 spot 함수, `SPACEBASE_MIN_MARGIN=20`·비율 0.7/0.75로 "더 먼"을
  좌표에 그대로 반영) 신설. `buildProps()`의 바이옴 장식·채집 노드 제외
  루프, `buildAnimals()`의 짐승 제외 조건에 각각 `inSpaceBase()` 한 줄씩
  보탰다(다른 네 자리와 같은 자리에 나란히). `tileAt()`은 이 구역만 이미
  있는 `sand` 타일을 돌려준다(새 타일 종류를 안 늘렸다 — TILES·
  terrainColors() 손 안 댔다).
- **소품**: crate(보급 상자, `mail`과 같은 `box_small.gltf.glb`를 새 키로
  재등록)·fence·cart(둘 다 asset3d.js에 **등록만 되고 여태 3D scatter에
  안 이어져 있던 것** — 다리(bridge)가 그랬던 것과 같은 결로 처음 이었다)·
  lantern(기존 그대로 재사용) 다섯을 deco:true로 놓았다. **새 GLB는 하나도
  안 받았다** — 전부 이미 저장소 안에 있던 파일의 재사용/재등록.
- **택배 접수대(`courierPost`)**: 마을 안, 우편함(`mail`) 곁에 있는 **새
  프롭**(우편함과 다른 kind — mail.js의 편지·이사 상태를 안 건드리려고
  일부러 갈랐다). deco 아님(손이 닿는다), 소포가 없을 때만 하나 내준다.
