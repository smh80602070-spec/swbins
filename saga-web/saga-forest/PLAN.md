## 1. 정체성

- **한 줄**: 역사 인물(가명) 105명이 **주민**으로 사는 마을에서 걷고, 모으고, 나누는 생활 게임. 마을 밖으로 숲·호수·동굴·폐허·우주기지까지 끊김 없이 걸어 나가는 작은 오픈월드.
- **원작 오마주**: 동물의숲(투영·하루·계절·주민·박물관·순무 장). 원작에서 가져올 큰 축은 2026-08-26 에 전부 끝났다(README "다음에 채울 것"). 안 넣기로 한 것: 마이디자인 도트 편집, 여럿이 한 마을(서버).
- **차별점**: ① 화면이 **구면 투영**으로 굽는다(원작 감각의 핵심) ② 주민이 다섯 판 공통 인물이라 성격·대사에 역사 오마주가 묻어 있다 ③ **퓨전** — 동물의숲 틀에 갇히지 않는다: 괴물(포자괴물·성간충)·보스방·시대 혼합 목적지(우주기지·13세기 탑성 폐허)가 정당한 콘텐츠다. "완전 모방 할 필요 없어, 원작보다 나으면 좋다"(사용자, 2026-09-10).
- **인물이 되는 것**(SAGA-DESIGN §5): 주민 5(`residents`, HEROES 로스터에서 뽑음) + 숲 NPC 7. 이 판의 성장은 **내 힘이 아니라 마을과 관계**가 자란다.
- **플레이어 판타지**: "내가 돌보는 마을이 매일 조금씩 달라지고, 주민이 나를 알아본다."
- **전투 없음.** 손맛(§3-C)은 채집·낚시·나무 흔들기·문 열기의 반응으로 재정의한다.

## 2. 반드시 지킬 것

루트 `CLAUDE.md` 공통(세이브 키 `yeoksa-village/save/<프로필>` 불변·펫/인물 id 불변·실명 금지·다섯 벌 복사·원작 에셋 금지)에 더해, 이 판 고유:

1. **구면 투영을 평평한 탑다운으로 되돌리지 않는다.** `village-view.js` 의 `project()`/`unproject()` 가 심장이다. **집 안(`projIn`)만 일부러 안 휜다.** 탭 좌표는 `V.indoors()` 로 갈라 되짚는다.
2. **좌표 해시로 세계를 만든다.** 같은 마을은 늘 같은 모습(`core.hash2`, 부호 없는 시프트). 지형 개조는 타일 표가 아니라 **덮개층**(`terrain.js`) — 안 고친 마을은 세이브가 한 자도 안 는다. **절벽은 넣지 않는다**(투영에 높이 축이 없다).
3. **시간은 실제 시계다.** 계절 = 실제 달, 시간대(dawn/day/even/night) = 실제 시, 행사 = 양력 고정 날짜, 날씨 = 날짜 해시(`VD.weatherOf`). 가상 시계로 바꾸지 않는다. 진단은 구멍(`VD.season`·`_setStar`·`_setOpen`)으로 붙든다.
4. **프레임마다 도는 것은 공용 `Math.random` 을 먹지 않는다**(`bug.js`·`folk.js` 는 제 난수). 이사·편지는 `rollDay()` 에서만.
5. **복잡한 시스템을 새로 만들지 않는다.** 데이터 표 하나(`QUESTS`·`EVENTS`·`DELIVERIES` 식) + 기존 `focus()`/`interact()`/`talkNpc()` 분기 한 줄. 새 상호작용 프레임워크·새 전투 체계 금지. 프로젝트 전체 재작성·정상 기능 삭제·무거운 프레임워크 추가 금지.
6. **코드로 그리지 말고 에셋으로**(다섯 판 공통, 2026-08-28 사용자 지시). 3D 소품·인물뿐 아니라 초상·카드·아이콘까지. 못 구하면 "이래서 막혔고 대신 이것을 할 수 있다" 로 보고. 되돌림 길(옛 그림)은 손잡이로 남긴다. 출처는 `assets/ASSET_LICENSES.md`, CC0 우선, 재배포 불가 자산 금지.
7. **적은 수의 좋은 에셋을 배치·스케일·바이옴으로 다양하게.** 나무 GLB 5개로도 충분하다. 모바일 최적화 없는 고해상도 텍스처·거대한 단일 맵 모델·모든 동물 상시 AI·수백 개 독립 파티클 금지.
8. **모바일 세로·가로 둘 다.** Safe area, orientation 재계산, 한 손 조작. 성능 문제는 그래픽을 낮추기 전에 중복 로딩 제거→풀링→인스턴싱→LOD→거리 활성화→DPR→그림자 순서.
9. **파일을 늘리거나 고쳤으면 `sw.js` VERSION 을 올린다**(지금 `village-v0.55.1`). 안 올리면 한 화면에 세대가 섞여 죽는다.
10. **실기 확인은 배치 끝에 한 번만.** 기능마다 "실기 확인 전" 표시는 남기되 그때마다 요청하지 않는다. 개발 중 헤드리스 스크린샷 금지(루트 CLAUDE.md).
11. **다른 네 판·`saga-godot`·`saga-unity` 는 여기서 안 본다.** CC0 자산은 저장소 안 다른 판에서 md5 동일 복사로 재사용할 수 있다(출처 절 링크).

## 5. 게임성 확장 — 후보 8 (우선순위 순)

9필드: 참고 / 표준 / 왜 / 메커니즘 / 수치 / UI·조작 / 세이브·마이그레이션 / 진단 / 범위·우선순위·충돌. 세이브는 전부 **`s.village.*` 에 칸 추가(additive)**, `v:1` 유지, 빠진 칸은 `auto.js` 의 `st()` 처럼 읽을 때 기본값으로 채운다 — 옛 세이브 마이그레이션 코드가 따로 필요 없다.

### 5.1 오늘의 일과판 (목표판 + 일일·주간)
- **참고**: 원신 일일 위탁, 포켓몬GO 리서치, 스타듀 "오늘 할 일" 메모. **표준**: A·H.
- **왜**: 달력 콘텐츠(행사·계절 채집·순무 장·편지)가 이미 있는데 안 보여서 "할 게 없다"고 느낀다. 새 콘텐츠 0으로 A·H 를 채우는 가장 싼 후보.
- **메커니즘**: 매일 `rollDay()` 가 날짜 해시로 **일일 3개**(채집 1·주민 1·탐험 1) + **주간 1개**(월요일 갱신) 를 `TASK_POOL` 표에서 뽑는다. 풀 예: "복숭아 3 모으기(계절)", "○○에게 선물", "폭포 다녀오기", "물고기 2종 기증", "잡초 5 뽑기", "택배 1회", "정령 1(§5.5)". 완료 즉시 다음 줄 채움(당일 최대 6). 행사날은 1줄이 행사 과제로 고정. 보상은 🪙 소량 + **도감 진척**(꽃/물고기 힌트) — 강제 없음(놓쳐도 벌칙 0).
- **수치**: 일일 3(각 🪙 80~150), 주간 1(🪙 600 + 옷/가구 1). 과제 소요 ≤3분 설계. 연속 7일 달성 시 "부지런한 사람" 깃발 장식.
- **UI**: 상단 목표판 3줄(접기 가능, 세로 모드 기본 1줄 + 펼침). 완료 시 줄이 ✓ 로 0.4s 빛나고 밀려 나간다. 게시판(`board`) 상호작용이 전체 목록 시트를 연다(기존 `SHEET_TITLE` 에 `tasks` 추가).
- **세이브**: `s.village.tasks = { day: 'YYYY-MM-DD', list: [{id, n, done}], week: 'YYYY-Www', weekly: {id, n, done}, streak }`.

## 6. 그래픽·에셋 (SAGA-DESIGN §6·§7 적용분)

### 6.1 이 판의 렌더 두 겹
- **2D 구면 투영**(`village-view.js`, 기본 화면의 절반): 후처리 없음. 적용할 것은 **팔레트 스냅**(스프라이트·타일 색을 §6.3 팔레트로, 로드 후 캔버스 1회)과 §5.8 반응만. SSAO·비네트·톤매핑은 **넣지 않는다** — 캔버스 구면 왜곡 위에 화면 공간 효과를 얹으면 가장자리에서 어긋난다.
- **3D**(`village-view3d.js`, three r169): SAGA-DESIGN §6.1 그대로 — `MeshToonMaterial` 3단 램프 + 뒤집힌 헐 외곽선(1.03), ACESFilmic·노출 1.0, 안개는 **기본 꺼짐 유지**(사용자 결정) — 켜면 near 30/far 320·색은 `FOG_COLOR` 바이옴별. 그림자는 high 만(기존). 초목 InstancedMesh 8종 유지·상한 2000. 픽셀 비율 상한 1.5(`QUALITY_PRESET` 에 이미 있음).
  **재질** — `js/toon3d.js`. 땅 배경판·타일 8종(물 제외)과 `asset3d.js` `delam()`·`primitive()` 가 `world3d.toon`(기본 1)으로 Toon/Lambert 를 고른다. 물(`waterMaterial()`, HDRI 반사 PBR)은 툰 대상이 아니다. `/realistic/` 사진측량은 §10-Q3 대로 툰이 켜져 있으면 `toonifyRealistic()` 로 덮는다(꺼지면 PBR 그대로). **외곽선은 배우(주민·NPC·짐승)만** — `toon3d.addOutline(root, width)`(메시마다 1.045배 BackSide 복제, SkinnedMesh 는 skeleton 재바인딩), 손잡이 `world3d.outline`(툰을 따라간다), `loadHeroRecipe().assemble()`·`buildGeneric()` 짐승 분기에서 부른다. 땅은 안 건다(격자 전체가 테두리로 덮인다). 후처리 자동 끔(§8-6)은 해당 없음 — `post3d.js` 가 없다.
  **림 라이트(2026-09-19, "원신 느낌" 요청분)** — `toon3d.js`의 `applyRimLight()`. 지오메트리를 안 늘리는 프레넬 항 하나를 `onBeforeCompile`로 `MeshToonMaterial` 셰이더(공용 청크 `common`·`worldpos_vertex`·`dithering_fragment`)에 더한다 — 외곽선과 달리 드로우콜이 안 늘어 땅·소품·배우 전부(즉 `toonify()`·`lambertLike()`를 타는 모든 것)에 건다. 손잡이 `world3d.rim`(기본 1, 외곽선처럼 툰이 꺼지면 같이 꺼진다). 색·강도는 `applyRimLight()` 안에 고정값(따뜻한 흰빛 0xfff4d6, 세기 0.35, 프레넬 지수 2.2) — 손잡이 표로 노출은 아직 안 함. **검증은 `node -c`와 청크 이름이 실제 vendor three(r169, `js/vendor/three.iife.js`)의 MeshToonMaterial 템플릿에 그대로 있는지 소스 대조까지만** — GLSL 컴파일 자체·번지는 두께가 과한지는 WebGL 컨텍스트가 있어야 해 실기 확인 몫이다.
  **하늘 그라디언트·반딧불이 반짝임·물비늘(2026-09-19, "원신급" 요청 ③환경 레버)** — 셋 다 `village-view3d.js`. (1) `makeSkyDome()`: 카메라를 따라다니는 큰 구(반지름 380) 하나에 수직 그라디언트 `ShaderMaterial`(텍스처 없음, 드로우콜 +1) — `syncSky()`가 매 프레임 위치를, 바이옴·시간대·날씨가 바뀔 때만 위/아래 색(`lighten`/`darken`)을 갱신한다. 손잡이 `village3d.sky`(기본 1). (2) 반딧불이(앰비언트·정원 무리 둘 다)에 캔버스로 구운 방사형 발광 스프라이트 + 가산 블렌딩 + 정점색 기반 반짝임(위아래 흔들림과 다른 위상의 sin)을 얹었다 — 개수도 40→64/24→36 로 늘림. (3) 물(`waterMaterial()`) 재질 자체(PBR+HDRI 반사)는 그대로 두고 — "반사는 공짜로 얻는다"는 기존 결정이 맞다 — 같은 `onBeforeCompile` 자리에 해시 기반 반짝임(물비늘) 프래그먼트 항만 추가, 손잡이 `village3d.waterSparkle`(기본 1). 셋 다 `node -c`·vendor three 청크 대조까지만 확인, 실제 렌더는 실기 확인 대기(HANDOFF.md 2026-09-19 절).
- **주의 — 구면 투영과 3D 카메라**: 2D 의 굽은 지평선 감각을 3D 에서도 내려면 `camTiltMix`(기본 1, 3/4 부감) 를 낮추는 게 아니라 **원경 안개·하늘 그라디언트로 지평선을 밝게** 처리한다. 2D/3D 토글 시 카메라 중심·줌이 같은 타일을 가리켜야 한다(진단 `camPose` 항목 유지).
