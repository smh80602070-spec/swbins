# saga-web 맵 편집기

판마다 다른 "지도 데이터"를 브라우저에서 칠하고 옮기는 로컬 전용 도구. 지도 모양이 판마다 달라서
**어댑터**(`adapters/*.js`) 하나가 데이터 파일 한 가지를 맡고, 화면도 넷이다(위 줄에서 오간다).

```
run-map-editor.bat        → http://127.0.0.1:8800/   (끄기: 창 닫기 또는 Ctrl+C)
```

| 화면 | 어댑터 | 파일 · 고치는 것 | 지금 대상 |
|---|---|---|---|
| 글자 지도 `map.html` | `land` | `js/land.js` 땅의 `map`(글자 줄)·`places`(명소) | 사가만리 `hebei`(21×21칸·한 칸 48m) |
| 성 지도 `city.html` | `city` | `js/data-city.js` 성의 `x`·`y`·`land` 와 `LINKS`(길) | 사가천하 135성 |
| 사냥터 `side.html` | `side` | `js/data-side.js` `STAGES` 한 곳의 `width` · `plats`·`ropes`·`portals`·`npcs`·`gathers` | 사가종횡 11곳(마을 5·사냥터 6) |
| 3D 배치 `scene.html` | `deco` | `js/land.js` 땅의 `deco`(손으로 놓은 소품, 월드 미터) | 사가만리 `hebei` — 아래 "3D 배치" |

판 폴더에 그 파일이 생기면 저절로 목록에 뜬다(`/api/kinds`).

## 어댑터 공통

- **검사는 게임 데이터 그대로**: 고친 파일을 vm 에서 실행해 게임이 보는 그 객체(`DG.land`·`DG.cityData`·`DG.sideData`)로 본다.
  고칠 때마다 오른쪽에 바로 뜬다. 게임에 검사 함수가 있으면 그것을 부르고(`land.validate()` 등), 없으면 그 판 `_test.html` 진단과 같은 조건을
  어댑터가 본다 — 게임 파일은 안 고친다.
- **저장은 바뀐 구간만** 바꿔 쓴다(주석·줄 맞춤·다른 값 그대로). **안 바꾸고 저장하면 파일을 아예 안 쓴다**(바이트 동일, sw.js 도 안 올림).
- 막는 것: 그새 파일이 바뀜(md5 — 다른 세션·편집기) · 파일 구문 오류 · 어댑터 검사 오류 · 표시 글자 실명(`../content-editor/realname.js`).
  저장하면 그 판 `sw.js` VERSION 을 서버 실행당 한 번 올린다.
- 되돌리기 Ctrl+Z. git 은 건드리지 않는다.
- 이름·설명·수치 같은 **글자 칸은 여기서 안 고친다**(콘텐츠 편집기 `../content-editor/` 판별 표 몫). 그래서 성 지도·사냥터에는 실명 가드에 걸 글자가 없다.

## 글자 지도(사가만리)

- **도구**: 칠하기(끌기) · 채우기 · 스포이트 · 명소 옮기기 · 오른쪽/아래로 열·줄 늘리고 줄이기.
  왼쪽·위로는 안 늘린다(격자 원점 `ox/oy` 와 명소 좌표가 한꺼번에 밀린다). 흰 테두리 칸 = 격자 (0,0), 게임 시작 자리.
- **범례**는 그 땅의 `legend` 를 그대로 쓴다(새 글자·지형은 `land.js` 에서 코드로 먼저 정의).
- 검사는 그 판의 `validate()`·`roadIslands()`·`tally()`. 길이 끊긴 것(`roadIslands() ≠ 1`)은 막지 않고 경고만 한다.
- 게임 `_test.html` 땅 진단은 지형 갈래 개수·숨은 곳 넷 같은 **내용 조건**도 본다 — 편집기는 형식만 막으니, 크게 고쳤으면 진단을 한 번 돌린다.
- `tools/scene-layout/layout.mjs` 가 `server.js` 의 `evalLand` 를 가져다 쓴다(이름 그대로 내보낸다).

## 성 지도(사가천하)

- **도구**: 옮기기(끌기, 정수 칸에 붙는다) · 길 잇기·끊기(두 성을 차례로 누른다, 이어졌으면 끊는다) · 지형 칠하기. 주(州) 골라 보기·성 찾기·휠 확대.
  파란 점선은 물길(양쪽 다 `river`) — 지형 한 글자로 물길이 따라 움직이는 게임 규칙 그대로 보인다.
- **막는 것**: 없는 성을 가리키는 길(`_dropped`) · 길 없는 성 · 낙양에서 못 닿는 성 · 모르는 지형 · `ui-rtk.js` `MAP_VB`(지도 전체 범위) 밖의 성
  (범위를 넓히려면 `ui-rtk.js` 두 곳을 먼저 고친다 — 그 파일 주석). 같은 길이 두 번 적힌 것은 경고.
- 저장: 성 객체의 `x`·`y`·`land` 값 글자만 바꾼다. 길은 지운 쌍만 `LINKS` 에서 빼고(빈 줄·쉼표 정리), 더한 쌍은 배열 끝에 한 줄로 붙인다.
  길의 순서·방향만 달라진 것은 바뀐 게 아니다.
- 성을 새로 만들거나 없애지는 않는다(이름·내정 값·수비 무장이 딸려 있어 `data-city.js`·`data-force.js` 를 손으로).

## 사냥터(사가종횡)

- **도구**: 고르기·끌기 · 발판/줄/문/사람/채집 더하기 · 고른 것 지우기(Delete) · 폭. 10 단위로 붙기(끌 수 있음).
  발판 오른쪽 끝(흰 손잡이)을 끌면 폭, 줄은 위·아래 끝을 끌면 그 끝만(위 끝은 가까운 발판 윗면에 붙는다), 가운데를 끌면 통째로.
  흰 점선은 들어올 때 서는 자리(왼쪽 130 · 오른쪽 폭−160, `side.js` 그대로).
- **막는 것**: 줄 수 < 발판 수 · 문 없음(둘 다 `_test.html` "줄"·"문" 진단) · 없는 사냥터로 가는 문 · 폭 밖·바닥 아래 발판 ·
  위 ≥ 아래인 줄 · `rope`/`ladder` 가 아닌 줄 · `NPC_TALK`·`GATHERS` 에 없는 사람·채집 갈래 · 폭 400 미만.
  **경고만**: 되돌아오는 문이 없는 문(양쪽 사냥터를 같이 고칠 때 한쪽씩 저장하게), 어느 발판 윗면에도 안 닿는 줄 위 끝.
- 저장: 그 사냥터 객체에서 **바뀐 칸만** 다시 쓴다(100열에서 줄바꿈, `[` 다음 열에 맞춤). 없던 칸(싸움터에 `npcs` 등)은 `portals` 뒤에 붙인다.
  한 파일에 사냥터가 열한 곳이라, 저장하면 목록의 다른 사냥터 해시도 같이 새로 맞춘다(이어 고쳐도 충돌 안 남).
- `floor`(바닥 높이)는 안 고친다(지금 열한 곳 모두 560).

## 3D 배치(사가만리) — `scene.html`

사가만리 `land.js` 땅 객체의 `deco`(손으로 놓은 소품)를 3D 화면에서 놓고 옮기고 돌리고 키운다. 위 줄 "3D 배치" 또는 `/scene.html`.

- **게임 코드로 그린다**: 화면이 `/g/saga-go/__scene.html` 에 얹혀 그 판 js(`land`·`world3d`·`prop3d`·`relief3d` …)를 게임과 같은 상대 경로로 부른다.
  땅 높이 `relief3d.heightAt`, 해시 소품 `world3d.propPlan`, 모델·변종 `prop3d.parts`(같은 자리 해시 → 같은 모델), 키 배율 `prop3d.heightMul` 이 게임과 같다.
  편집 중인 배열을 `DG.land.region().deco` 에 끼워 게임 함수(`decoAt`·`propPlan`·`houseRects`·`validate`)를 그대로 부른다.
- **조작**(고돗 편집기 흉내): `Q` 선택 · `W` 이동(X·Z 화살표, 노란 판 = XZ) · `E` 회전(Y 고리) · `R` 크기(키, 집·탑은 폭·깊이도).
  `G` 붙이기 0.5m·15°·0.05배(Ctrl 누르면 반대) · 소품을 곧바로 끌면 땅 위로 옮김 · 빈 곳 끌기 = 사각형 고르기 · `Shift` 더해 고르기 ·
  `Ctrl+D` 복제 · `Delete` 지우기 · `Ctrl+Z`/`Ctrl+Y` · `Ctrl+A` · 화살표 0.5m(`Shift` 5m, 화면 방향 기준) · `F` 고른 것 보기 · `Home` 땅 전체 · `T` 위에서 · `Ctrl+S` 저장.
  카메라: 오른쪽 끌기 돌려 보기 · 가운데(또는 `Shift`+오른쪽) 끌기 옮겨 보기 · 휠.
- **놓기**: 왼쪽 팔레트(종류 10 = `land.js` `DECO_T`)를 누르고 땅을 클릭 — 계속 놓아지고 `Esc`·오른쪽 클릭으로 끝. 나무·바위·풀·갈대는 키 ±20%·돌림을 무작위로 준다.
- **인스펙터**: 종류 · x·z · 키 · 돌림(°) · 집·탑은 폭·깊이·벽 밝기. 모델(GLB)은 키로만 커지고 폭·깊이는 벽 충돌과 모델 못 받았을 때 상자 크기다.
- **검사**(저장을 막는다): 게임 `land.validate()` — 모르는 종류 · 값 범위(키 0~80m, 폭·깊이 0~60m) · 땅 밖.
  **살펴볼 것**(막지 않는다): 물 위 · 표식 칸(굴·다리 …) · 해시 집·놓은 집끼리 벽 겹침. 집·탑·우물·장터는 어느 칸에 놓아도 벽이다(마을 칸 밖이면 `houseRects` 가 그 칸 deco 만 본다).
- **저장**: `deco: [...]` 구간만, 한 소품 한 줄(`{ t, x, z, h, rot, w, d, shade }`, cm·0.001rad 로 반올림). 무변경이면 안 쓴다. 맵 편집기 공통 막는 것(md5 충돌 등) 그대로.
- **게임 쪽**: `land.decoAt(tx,ty)` 가 그 칸 소품을 `propPlan` 모양(칸 가운데 기준)으로 주고 `propPlan` 끝에 얹는다 — 모델·LOD·밤 등불·벽 충돌이 해시 소품과 같은 길로 선다.
  먼 풀밭·길 칸도 소품이 있으면 세운다(`hasDeco`). 손잡이 `land.deco`(0 이면 해시 소품만). 진단 "땅 — 손으로 놓은 소품(deco)…".
- `tools/scene-layout/` 배치표(Godot/Unity)로도 넘어간다 — `layout.mjs` 가 `deco:<종류>` 물건으로 얹고, 두 트랙 걷는 씬은 집·탑·우물·장터를 벽으로 막는다(그 README).

## 사가나락 마을 — `town.html`

손으로 지은 마을 넷(모루골·갈대나루·자작재·소금벌, `saga-dungeon/js/town.js`)을 위에서 본 방(560×380, 게임 BASE 좌표)으로 고친다. 어댑터 `adapters/town.js`.

- **고치는 것**: 장식(모루골 `DECOR_MORU`, 나머지 `TOWNS[id].decor` — 집·여관·마방·방앗간·대장간·종탑·우물·기둥·횃불·균열, dungeon3d 가 그리는 10종) ·
  사람(`TOWNS[id].npcs`, 직군은 `NPC_DEFS` 에서 고른다) · 표식(모루골 `MARKS` 자리만 — 굴혈은 방에 안 서서 못 끈다). 이름·테마·들길은 안 고친다.
- **도구**: 끌기(10 단위 붙기) · 방향키 1 / Shift 10 · 종류 골라 더하기(고른 것 바로 뒤에) · 본뜨기 `Ctrl+D` · 지우기 `Delete` · 되돌리기/다시 `Ctrl+Z`/`Ctrl+Y` · 저장 `Ctrl+S` · 확대·축소 · ▶ 실행.
  겹쳐 보기: 스폰 95(큰 건물 금지 원) · 대화 반경 · 소품 간격 55 · **게임에서 설 자리**(게임이 사람을 방 바깥쪽으로 최대 1.28배 퍼뜨린 자리 — `handTownNpcSpread` 같은 계산).
- **자동 장식(밀도 보강)**: 게임은 불러올 때 손 장식·사람·스폰에서 100 떨어진 곳에 집·기둥을 해시로 더 얹는다. 편집기 서버가 `town.js` `placePoints`·`core.js` `hash2` **원문을 vm 에서 그대로 돌려**
  같은 자리를 검사 결과 `auto` 로 싣고 화면이 점선으로 그린다 — 손 장식을 옮기면 같이 움직인다(갈대나루·자작재·소금벌은 게임을 vm 에서 돌린 결과와 자리·사람 퍼뜨림 12명까지 같음을 대조했다).
- **검사**(게임 코드·`_test.html` 규칙): 오류 — 모르는 종류 · 방 밖 · 큰 건물이 스폰(195,240) 95 안(카메라가 벽에 박히는 벨타워 함정) · 사람·표식이 통행 영역 밖 ·
  사람끼리·사람과 표식 80 안(한 자리에서 둘이 걸림) · 모르는 직군. 경고 — 사람이 소품 55 안 · 건물끼리 70 안 · 우물이 스폰 95 안 · 같은 직군 둘.
- **저장**: 대사·퀘스트 편집기의 `jslit` 로 바뀐 값 자리만 — 줄마다 붙은 날짜 주석이 산다. 횃불 `y: WALL - 4` 같은 식은 값이 안 바뀌면 그대로(옮기면 그 하나만 숫자로, `jslit` `rawToValue` 옵션).
  항목은 origin 으로 맞춰 가운데 끼우고 옮긴다. 저장하면 사가나락 `sw.js` 를 한 번 올린다.
- 마을 안에서 건물이 몸을 막는 코드는 게임에 없다(3D 는 모양만) — 편집기 몫이 아니라 게임 설계 몫이다.

## ▶ 실행 — 편집기 안에서 게임 띄우기

모든 화면(글자 지도·성 지도·사냥터·3D 배치·사가나락 마을, 콘텐츠 편집기도) 위 줄의 **▶ 실행**(`F5`)이 오른쪽에 게임 창을 연다. 맵 화면 다섯에는 **▶ 여기서**(`F6`)도 있다 — 고른 것(없으면 화면 가운데)에서 시작, 2D 화면은 `Alt+누르기`로 누른 자리에서.
글자 지도는 고른 명소 칸, 3D 배치는 고른 소품 곁, 사냥터·사가나락 마을은 고른 것 곁, 성 지도는 고른 성 시트를 연 채로.

- 편집기 서버가 `/play/<판>/` 로 판 폴더를 그대로 준다(`../lib/gameserve.js`). 판 파일은 안 고친다. 다만 실행 창에서는
  `sw.js` 대신 스스로 풀리는 빈 서비스워커를 주고(옛 캐시가 고친 것을 가리지 않게), `index.html` 끝에 시작 자리 스크립트(`?at=x,y`·`?in=곳` — 사가만리·사가종횡·사가나락·사가천하, `gameserve.js` START 표)를 붙인다.
- **세이브는 연습용**: 편집기 서버는 포트가 달라 localStorage 가 실제 게임(8791~)과 따로다. 창의 "세이브 비우기"는 이 편집기 출처의 그 판 세이브 키만 지운다.
- 저장하면 열려 있는 실행 창을 새로 띄운다. **저장 안 한 것은 안 보인다**(게임은 파일을 읽는다).
- 창: ⟳ 다시 · 폰(390×844) · 세이브 비우기 · 새 탭 · 닫기 · 왼쪽 끝을 끌어 폭 조절.

## 못 넣은 판

- **사가마을** — 마을(30×20 타일)·숲 고리·강·만남 격자가 전부 세이브 씨앗 해시로 **코드가 절차 생성**한다(`village.js`·`grid.js`·`terrain.js`).
  고정 지도 데이터가 없으니 편집할 표가 없다. 넣으려면 먼저 게임 쪽에 "손으로 정한 배치" 층을 만들어야 한다(설계 결정 — 사용자 몫).
- **사가나락 던전** — 로그라이크라 층마다 절차 생성(`dungeon.js`, 데이터는 층 테마·방 종류 표뿐). 절차 생성 마을 100여 개도 해시라 편집할 표가 없다.
  손으로 지은 마을 넷은 위 "사가나락 마을" 로 고친다 — 데이터가 로직 파일 안에 있지만 jslit 이 값 자리만 고치고, 방 배율(`DESK_SCALE`)은 균일하게 곱할 뿐이며
  손 마을은 앵커를 흔들지 않아(`TOWN_JITTER` 는 절차 생성 마을만) 편집기 BASE 좌표가 곧 게임 자리다(사람 퍼뜨림·자동 장식은 편집기가 같은 계산으로 보여 준다).

## 시험 요령

`SAGA_WEB_ROOT=<복사본의 saga-web 자리> node server.js` 로 켜면 그 복사본을 고친다(실제 판 파일을 안 건드리고 저장 경로까지 시험).
서버를 띄워 시험했으면 PID 로만 끈다(`taskkill //PID <n>`, `//IM node.exe` 금지).
