# 의상 = 아이템 (착용 교체 · 캐시 의상 · 펫 동행) — 설계

2026-09-30 사용자 지시: "의상만 따로 입히는 기능 — 디아블로처럼 아이템 착용에 따라 변경되듯이. 의상 개념이 있고, 펫 개념도 있고, 캐시템 같은 의상."
이 문서는 **설계 정본**이다. 진행 이력은 `README.md` 끝·HANDOFF 에 적는다(여기엔 규칙·모양만).

## 1. 개념 — 층 세 겹
| 층 | 뜻 | 능력치 | 보이는 것 |
|---|---|---|---|
| **장비** | 슬롯별 착용 아이템(디아블로식) | 있음 | 캐시 층이 비어 있으면 장비의 `look` |
| **캐시 의상** | 외형만 덮어쓰는 아이템(메이플식 캐시템) | 없음 | 있으면 그 슬롯은 항상 캐시 `look` |
| **동행(펫)** | 따라다니는 별개 개체(도감 펫) | 게임 규칙대로 | 몸 옆 자리·별도 모델 |

보이는 옷 = 슬롯마다 `캐시 look ?? 장비 look ?? 맨몸`. 능력치는 장비만 본다. 캐시 의상은 어느 장비와도 겹쳐 입는다(외형 층).

## 2. 슬롯 (공방 옷 조각과 1:1)
`head`(투구·모자·관) · `hair`(머리카락) · `body`(윗옷·갑옷·도포) · `legs`(바지·치마) · `hands`(장갑) · `feet`(신발) · `back`(망토) · `extra`.
`export_parts.py` 가 슬롯 이름을 파일 이름 앞에 붙여 내보낸다(`<슬롯>__<옷>.glb`). 한 슬롯에 옷 하나. 통옷(도포·기모노·갑옷 원피스)은 `body` 가 `legs` 까지 덮는다 — 아이템 표에 `covers: [legs]` 로 적어 그 슬롯의 아이템은 숨긴다.

## 3. 옷 조각의 몸 맞춤 — 정직한 제약
공방 옷은 MakeHuman `.mhclo` 로 **그 몸에 맞춰** 지어진다(체형 모프를 따라 늘어남). 조각 GLB 는 뼈대·스킨(53 표준 뼈)을 같이 싣지만 정점은 그 몸 크기다. 따라서:
1. **체형 칸(archetype)** — 성별 × 체격 4 × 키 5 를 다 만들지 않고, 게임 옷 아이템은 **체형 칸 몇 개(예: 남/여 × 보통·근육·육중)** 에 대해 조각을 빌드한다. 같은 칸의 몸끼리는 어긋남이 없다.
2. 체형이 다른 캐릭터에 입힐 땐 **그 몸을 옷만 바꿔 다시 짓는다**(레시피 `clothes`·`_garments` 만 교체 → `build_real.py`) — 오프라인 빌드, 배포는 GLB 로. 런타임에 자동 늘림은 하지 않는다(어긋남·찢김).
3. 위 둘 다 비용이 드는 아이템 수는 "옷 틀(garments.py 틀 스물둘) × 색 변형"이라, 아이템 = 틀 + 색 + 재질 `tints` 로 데이터화한다(색 변형은 GLB 재질 색만 바꾸면 되어 조각 재빌드가 필요 없다).

## 4. 아이템 데이터 (게임 공통 스키마 초안)
```json
{ "id": "cos_samguk_armor_red", "name": "가명 표시글자", "slot": "body", "covers": ["legs"],
  "kind": "gear | cash", "rarity": 1-5, "stats": {"def": 12},          // cash 는 stats 없음
  "look": { "piece": "body__samguk_armor", "archetype": "m_muscle", "tint": {"cloth_a": "#8a2f2a"} },
  "tags": ["동양", "갑옷"], "sources": ["drop", "shop", "cash"] }
```
- `look.piece` 는 `export_parts.py` 매니페스트 조각 이름, `tint` 는 재질 칸별 색.
- **이름 정책**: 표시 이름은 가명·일반명사. 원작 아이템·실명 금지(CLAUDE.md).
- 세이브: 착용 상태 `{gear:{slot:itemId}, cash:{slot:itemId}, pet:petId}` 를 각 판 세이브에 **새 키**로 추가(기존 키·진행 안 건드림 — 세이브 키 규칙).

## 5. 트랙별 구현 (각 판 PLAN 조각으로 나눈다 — 코드 공유 없음)
- **Godot(saga-godot)·Unity(saga-unity)**: 몸 GLB 의 `Skeleton3D`/`SkinnedMeshRenderer` 에 조각의 메시를 **같은 뼈 이름으로 다시 붙인다**. 슬롯 교체 = 그 슬롯 메시 노드만 바꿈. 캐시가 있으면 장비 조각 숨김.
- **웹 다섯 판(2D)**: 스프라이트가 통짜라 슬롯 레이어가 없다 → 초상·카드는 **아이템별 겹그림(오버레이) 또는 AI 그림 세트(장비 look 당 한 장)**. 3D 뷰가 있는 판(`asset3d.js`·`portrait3d.js`)은 GLB 조각 방식.
- **펫**: 도감 펫을 "동행 슬롯 1" 로 — 이미 있는 펫 모델/스프라이트를 몸 옆에 따라다니게 한다. 펫 외형 교체(펫 캐시)는 같은 스키마의 `slot: "pet_skin"`.

## 6. 순서 (각 단계는 끝나면 커밋)
1. ✅ `export_parts.py` — 몸 하나를 맨몸 + 슬롯 조각 GLB 로 내보내고 매니페스트를 낸다(시험: `hero_kr_yisunsin` → base·body(갑옷)·body(상투→head)·feet, 조각마다 53 뼈 동일).
2. 체형 칸 정하기 + 도감/장수 옷 틀을 칸별 조각으로 뽑기(`export_parts.py` 를 틀×칸으로 도는 러너).
3. 아이템 표(`items.json`) 생성기 — 옷 틀·색 → 아이템 id·슬롯·covers.
4. 트랙 하나(saga-godot 사가고)에서 착용 교체 프로토타입 — 슬롯 교체·캐시 덮어쓰기·세이브 키.
5. 상점/도감 UI(장비 창·캐시 창)·펫 슬롯·웹 초상 겹그림.
6. 나머지 트랙·판으로 이식.

## 7. 알려진 한계
- 조각마다 텍스처를 자기 GLB 에 품는다(시험 1인: 몸 8.7MB · 갑옷 15.6MB · 상투 2.3MB). 게임 반입 때 중복 합치기(`dedupe_forge_textures` 방식)·메시 압축을 쓴다.
- 통옷 아래 가려진 살은 `build_real.hide_under`(레시피 `under`)와 MakeHuman 옷의 마스크로 **지운 채** 굽는다 → 옷을 벗기면 구멍이 난다. `export_parts.py --keep-under` 는 둘 다 건너뛰어 맨몸을 온전히 낸다(09-30 시험: 삼국 갑옷 인물은 삼각형 수가 같았다 = 그 옷은 원래 살을 지우지 않는다. 지우는 옷(긴 도포·치마 등)으로 렌더 확인 필요).
