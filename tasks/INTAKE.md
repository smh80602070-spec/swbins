# 지시 받기 절차 — 짧게·거칠게 말해도 같은 뜻으로 알아듣기 (사용자 2026-10-05)

사용자는 세션 중간에 아이디어·변경·판정을 짧은 말로 던진다. 그걸 **그 자리에서 코드로 바꾸면** 큐가 흔들리고 진도가 안 난다(10-05 진단: 닷새 706커밋·완성도 0%). 그래서 모든 세션은 아래 셋을 지킨다.

## 1. 중간에 들어온 말은 수신함으로

- 지금 티켓과 무관한 아이디어·변경·"~도 있어야 해" 는 **`tasks/INBOX.md` 에 한 줄**(날짜 · 사용자 말 그대로 · 내가 읽은 뜻 · 갈래/판) 적고 **한 줄로 "수신함에 적었다"** 답한 뒤 하던 티켓을 계속한다. 코드·큐·티켓은 건드리지 않는다.
- 예외(바로 따른다): "멈춰" · "되돌려" · 지금 티켓의 범위 안 수정 · 안전(세이브·키·커밋 금지) 관련.
- 판정("허접"·"별로"·"좋아"·"○/×") 은 수신함이 아니라 **그 티켓 메모·features.json** 에 적는다. 판정은 닫기다.
- 수신함 처리는 R-0 세션(페이블 또는 Opus 5.5, 10-07)이 한다. 실행만 하는 세션은 수신함을 티켓으로 바꾸지 않는다.

## 2. 뜻 풀기 표 (거친 말 → 정확한 뜻)

| 사용자 말 | 뜻 | 하는 일 |
|---|---|---|
| "<갈래> 이어해" | 그 갈래 큐 맨 위 티켓 실행(플레이 아님) | tasks/README 절차 |
| "이어해"(갈래 없음) | 어느 갈래인지 한 번 묻는다 | 질문 한 줄 |
| "자동화 이어해" · "소넷 자동화 이어해" | 체제 티켓 실행 — 이 PC 에 `C:\swbins3` 가 있으면 **자체툴 큐**, 없으면 **웹 큐** 맨 위 | 그 큐의 1번 티켓 |
| "커밋해" | 커밋 + 푸시 | precheck → commit -- 경로 → push |
| "확인 대기" · "눈 확인" | 사용자가 봐야 함 → **시트 10줄**로만 요청 | status.mjs --sheet / 티켓 시트 |
| "허접" · "별로" · "다 별로" | × 판정. 재작업 아님 — **폐기** 후 방식 바꿈 | 티켓 메모 ×, 같은 방식 재시도 금지 |
| "산으로 간다" | 결정(ARCH §8)과 어긋나게 범위가 늘고 있다 | 멈추고 ARCH §8 대조 보고 |
| "자동화" | 사람 손(고르기·꽂기·확인)을 없애라 — 양 줄이기 아님 | 판정기·manifest·게이트 |
| "내 것" · "남의 것 안 씀" | 자체 생성·VRoid·CC0 만, 원작 에셋 금지. AI 생성은 내 것 | 출처 기록 유지 |
| "최적화" | **화질 안 깎고** 낭비만 제거 | 번들·압축·루프 통합 |
| "소넷으로 할 수 있게" | 명령 한 줄·본보기·검증·완료 조건이 티켓에 다 적혀 있게 | 티켓 틀 §6.2 |
| "~도 있어야 해" · "~하면 좋겠다" | 아이디어 — 수신함 | INBOX 한 줄 |
| "확인 전" · "실기 확인은 몰아서" | 재촉 금지, 시트에만 남긴다 | 시트 |
| "페이블급으로" | 판단을 미리 적어(티켓·게이트·키트) 실행 세션이 실행만 하게 | ARCH §6.4 |

표에 없는 말은 **한 줄로 되묻는다**("~라는 뜻으로 읽었다, 맞나"). 두 가지로 읽히는데 결과가 크게 다를 때만. 아니면 쉬운 해석이 아니라 **ARCH §8 결정과 맞는 해석**을 고른다.

## 3. 세션 시작 때 수신함을 본다 (읽기만)

큐 맨 위 티켓을 집기 전에 `tasks/INBOX.md` 의 미처리 줄 수를 세어 보고에 "수신함 n줄" 을 적는다. 10줄 넘으면 "R-0 세션 필요"라고 적는다. 처리는 하지 않는다.

## 4. 사람이 봐야 하는 것은 셋뿐 (사용자 10-05 "자동화인데 내가 꼭 봐야 하는 게 이해가 안 됨")

① 그림체·방향 **고르기**(후보 2~3 중 하나, 한 번) ② ~~재미·손맛 판정~~ → **10-08 부터 QC + Claude 눈으로 D3**(`verified: "<날짜> qc+claude"`, 사용자 "사람 확인은 자동화 하라 했는데 qc로" · W-0109) ③ **거부권**(판정기 모음표 한 장 — 답 없어도 진행). 배선·배치·버그·수치는 촬영·진단·판정기로 **D2 에서 끝**(W-0069). "사용자 눈 확인 대기" 라는 상태 글귀는 쓰지 않는다 — human 항목만 "시트 대기".

**QC 자동(사용자 10-07 "실기 요청할 때 자동으로 돌리는 거지")**: "실기 확인" 이 필요해지는 자리에서는 사람에게 묻지 않고 `node tools/qc.mjs --game <판>`(갈래면 `--branch`) 을 돌린다 — 번들·진단·재미표준·2D/3D 촬영·완성도·게이트를 한 번에 재고 `tools/_out/qc-last.md` 에 남긴다. 촬영 PNG 는 **세션이 Read 로 보고** ○△× 를 적는다(사람 눈은 ①②③ 뿐). autorun 은 티켓 세션 뒤 자동으로 돌리고, 대화 세션이 "실기 확인 대기" 로 끝내려 하면 Stop 훅 `qc-guard` 가 한 번 막는다.
