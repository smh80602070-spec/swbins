# 그래픽·게임성 에셋 툴 강화 기획

상태: 설계 제안(문서만). 구현·생성·배포 검증은 수행하지 않았고 큐 순서·티켓 상태는 바꾸지 않는다.

## 1. 목표와 첫 범위

툴의 성공 기준은 생성 장수가 아니라 **게임에서 필요한 행동과 상태를 읽을 수 있는 에셋을 재현 가능하게 공급하는 것**이다. 첫 대상은 2나락 대표 캐릭터 한 명의 방향·무기·기본 네 모션이고, K-0205의 그림 출처 혼용을 회귀 사례로 쓴다. 실행 전 현재 소비 자산을 다시 추적해 K-0205가 이미 적용한 `elf_001` 시트와 무기별 공격 배선은 재사용하고, 해결된 혼용을 결함으로 단정하지 않는다(혼용은 검증용 사본에서만 재현). 대표 검증 통과 뒤 UI·배경·환경 키트로 확장한다.

새 모델·외부 서비스 도입, 3D 인체 생성 재개, 원본 덮어쓰기, 대량 재생성은 범위 밖이다(GeForce 추가도 생성 분담일 뿐). 로컬 세 모델과 기존 코드·Blender 도구를 재사용하며 머신 배정은 실행 당시 자체툴 큐를 따른다.

### GeForce 환경의 실행 계획

- RTX 4060 8GB(CUDA ComfyUI·기존 세 모델 등록 확인). 실행 옵션·확인 명령은 [ai-art 실행 기준](../../tools/ai-art/README.md#geforce-실행-기준-2026-10-30-확인)을 따르고, Radeon 전용 ROCm 설정·측정 시간을 공통 기본값으로 쓰지 않는다.
- 티켓 시작 전 자체툴 큐에서 담당 PC·입출력 범위를 확인한다. `_out` 사슬 상태는 PC 로컬이라 다른 PC 진행률로 대신하지 않는다. 기존 산출물·라이선스를 먼저 대조하고 필요한 대상만 처리한다.
- 첫 검증은 대표 자산 한 세트로 제한하고 생성 시간·최대 메모리·실패를 기록한다. 모션은 idle·walk·run·attack GIF/영상과 게임 내 재생으로 확인한 뒤 확장한다. CUDA 인식·모델 목록만으로 품질 통과를 선언하지 않는다.

## 2. 현재 도구와 강화 지점

| 확인한 기존 도구 | 재사용 기능 | 추가 설계 |
|---|---|---|
| `prompt_kit.py` | 규격·스타일 조합, id seed, lint | 용도·방향·상태·기준 자산을 묶는 요청 규격 |
| `gen.py` | `--dry`·`--only`, 후보 생성·판정, 설정 기록 | 입력 해시별 이력·재개·부분 수정 |
| `judge/judge.py` | 기술 결함·내용·스타일·후보 비교 | 세트 일관성·용도별 필수 검증 |
| `k188_cutout.py`·`pack_cutout.py` | 컷아웃·조립·모션 프레임 | 관절·접지·방향 전환 대표 검증 |
| `asset-place/place.py` | 정본 배치·사본 검사 | 검증 버전만 배포·전후 해시·복귀 |

위 목록은 코드·문서로 확인한 것이지 저장소 전체 검색 결과가 아니므로, 구현 전 동등 기능을 다시 찾아 확장 지점을 정하고 새 공방·별도 판정기를 중복 제작하지 않는다.

## 3. 작업 흐름과 산출 계약

요청 → 재사용 검색 → 변경 계획 → 후보 생성/가공 → 기술 검사 → 세트·모션 검토 → 게임 문맥 검증 → 배포 후보 확정. 단계 결과를 따로 보관하고 실패 단계에서 멈춘다.

요청 규격의 필수 항목:

- 자산 id·판·트랙, 전달할 행동/상태, 소비 경로와 기존 규격 출처.
- 원본·기준 그림·라이선스 경로와 해시, 방향·클립·장비 대응표, 고정할 색·실루엣·손잡이.
- 크기·피벗·프레임 순서·재생 속도·루트 이동(소비 코드나 기존 통과 자산에서 가져온다).
- 출력과 검증 방법, 생성 대상 목록, 머신 소유권, 버전별 출력 경로.

작업 기록에는 입력·도구 버전·모델·seed·설정·출력 해시·실패 사유·검증 근거를 남긴다. 같은 seed가 기기 간 동일 이미지를 보장하지 않으므로 재사용 판정은 id와 입력 해시·규격 버전을 함께 비교한다.

상태는 `계획됨 / 생성됨 / 기술통과 / 시각검토완료 / 적용검증완료 / 배포됨 / 실패`로 구분하고, 시각검토는 판정·검토자·증거 경로가 있어야 한다. 단계 생략·미검증은 통과가 아니다.

## 4. 우선 강화 기능

### P0 — 방향·모션을 한 세트로 보장

기준 캐릭터·무기·손·팔레트를 고정하고 방향별 출처를 표로 보인다. 누락 방향을 다른 출처로 조용히 대체하지 않고, 뒤집기 대체는 비대칭 장비·문양·잡은 손의 예외를 명시한다.

대표 한 명의 idle·walk·run·attack GIF/영상과 방향 전환 영상을 같은 배율·바닥선으로 만든다. 실제 관절 피벗, 가려진 부위의 빈틈, 발 접지, 루프 이음새, 준비→접촉→회수, 장비 궤적을 눈으로 확인한다. 접지 수치는 보조 증거이고 자동 측정만으로 승인하지 않는다.

### P0 — 실패한 부위만 고치는 재작업

실패를 `빈 부위 / 방향 불일치 / 접지 / 피벗 / 프레임 누락 / 규격 / 출처 / 예산`으로 분류하고 실패 프레임·관절·방향·원본 좌표를 기록한다. 재사용 → 리깅 보정 → 패킹 → 부분 이미지 보정 → 재생성 순으로 범위를 좁히며, 단순 분류 실패가 전체 GPU 재생성을 부르지 않는다.

재개 시 완료 출력 해시를 확인하고, 입력이 달라지면 해당 단계와 의존 산출물만 무효화한다. 한 작업은 한 머신만 소유하며 오래된 잠금은 실행 상태 확인 뒤 푼다. 재시도 예산을 작업별로 명시하고 소진 시 실패 보고로 끝낸다.
