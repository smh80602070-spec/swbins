# 그래픽·게임성 에셋 툴 강화 기획

상태: 설계 제안. 사용자 요청은 툴 강화이며 이번 산출물은 문서만이다. 구현·생성·배포 검증은 수행하지 않았다. 기존 큐 순서와 티켓 상태는 변경하지 않는다.

## 1. 목표와 첫 범위

툴의 성공 기준은 생성 장수가 아니라 **게임에서 필요한 행동과 상태를 읽을 수 있는 에셋을 재현 가능하게 공급하는 것**이다. 첫 대상은 2나락 대표 캐릭터 한 명의 방향·무기·기본 네 모션이다. K-0205에 기록된 서로 다른 그림 출처 혼용을 회귀 사례로 사용한다. 이를 통과한 뒤 UI·배경·환경 키트로 확장한다.

새 모델·외부 서비스 도입, 3D 인체 생성 재개, 원본 덮어쓰기, 대량 재생성은 범위 밖이다. 로컬 세 모델과 기존 코드·Blender 도구를 재사용한다. 머신 배정은 실행 당시 자체툴 큐를 따르며 특정 추가 GPU를 필수 조건으로 만들지 않는다.

## 2. 현재 도구와 강화 지점

| 확인한 기존 도구 | 재사용 기능 | 추가 설계 |
|---|---|---|
| `tools/ai-art/prompt_kit.py` | 규격·스타일 조합, id 기반 seed, lint | 게임 용도·방향·상태·기준 자산을 묶는 요청 규격 |
| `tools/ai-art/gen.py` | `--dry`, `--only`, 후보 생성·판정, 생성 설정 기록 | 입력 해시별 작업 이력·재개·부분 수정 계획 |
| `tools/asset-audit/judge/judge.py` | 기술 결함·내용·스타일·후보 비교 | 개별 그림 점수와 별도로 세트 일관성·용도별 필수 검증 |
| `tools/ai-art/k188_cutout.py`, `pack_cutout.py` | 컷아웃·조립·모션 프레임 생성 | 관절·접지·방향 전환을 비교하는 대표 검증 묶음 |
| `tools/asset-place/place.py` | 정본 배치 계획과 사본 검사 | 검증된 버전만 선택·배포 전후 해시 확인·이전 버전 복귀 |

위 기능 목록은 코드·문서 확인 근거다. 추가 설계의 부재를 전체 저장소 검색으로 확정한 것은 아니므로 구현 전 동등 기능을 찾아 확장 지점을 정한다. 새 공방이나 별도 판정기를 중복 제작하지 않는다.

## 3. 작업 흐름과 산출 계약

요청 → 재사용 검색 → 변경 계획 → 후보 생성/가공 → 기술 검사 → 세트·모션 검토 → 게임 문맥 검증 → 배포 후보 확정 순서다. 각 단계 결과를 따로 보관하고 실패 단계에서 멈춘다.

요청 규격의 필수 항목:

- 자산 id, 적용 판·트랙, 게임에서 전달할 행동/상태, 소비 경로와 기존 규격 출처.
- 원본·기준 그림·라이선스 경로와 해시, 방향·클립·장비 대응표, 고정할 색·실루엣·손잡이.
- 크기·피벗·프레임 순서·재생 속도·루트 이동 방식. 값은 소비 코드나 기존 통과 자산에서 가져온다.
- 필요한 출력과 검증 방법, 생성 가능한 대상 목록, 실행 머신 소유권, 버전별 출력 경로.

작업 기록에는 입력·도구 버전·모델·seed·설정·출력 해시·실패 사유·검증 근거를 남긴다. 동일 seed만으로 기기 간 동일 이미지를 보장하지 않는다. 재사용 판정은 id뿐 아니라 입력 해시와 규격 버전을 함께 비교한다.

`계획됨 / 생성됨 / 기술통과 / 시각검토완료 / 적용검증완료 / 배포됨 / 실패`를 구분한다. 시각검토는 판정·검토자·증거 경로가 있어야 한다. 단계 생략과 미검증은 통과가 아니다.

## 4. 우선 강화 기능

### P0 — 방향·모션을 한 세트로 보장

기준 캐릭터·무기·손·팔레트를 고정하고 방향별 출처를 표로 보여준다. 누락 방향을 다른 출처로 조용히 대체하지 않는다. 뒤집기로 대체할 때 비대칭 장비·문양·잡은 손의 예외를 명시한다. 기존 컷아웃 경로를 기본으로 하고 일러스트 시트는 동일 검증 계약으로 들인다.

대표 한 명의 idle·walk·run·attack GIF/영상과 방향 전환 영상을 같은 배율·바닥선으로 만든다. 실제 관절 피벗, 가려진 부위의 빈틈, 발 접지, 루프 이음새, 준비→접촉→회수, 장비 궤적을 눈으로 확인한다. 접지 수치는 보조 증거이며 자동 측정값만으로 자연스러움을 승인하지 않는다. 공격 접촉 프레임과 게임 판정 시점의 대응은 소비 측 통합 검증 항목으로 남긴다.

### P0 — 실패한 부위만 고치는 재작업

실패를 `빈 부위 / 방향 불일치 / 접지 / 피벗 / 프레임 누락 / 규격 / 출처 / 예산`으로 분류한다. 실패 프레임·관절·방향과 원본 좌표를 기록하고, 재사용·리깅 보정·패킹·부분 이미지 보정·재생성 순으로 해결 범위를 좁힌다. 단순 분류 실패가 전체 GPU 재생성을 호출해서는 안 된다.

재개 시 완료 출력의 해시를 확인한다. 입력이 달라졌으면 해당 단계와 의존 산출물만 무효화한다. 한 작업에는 한 머신만 소유권을 갖고, 오래된 잠금은 실행 상태 확인 후 해제한다. 재시도 예산은 작업별로 명시하며 소진 시 실패 보고로 끝낸다.

## 5. 후속 티켓 작성 시 참조

[확장·실행·검증 기준](asset-tool-validation.md)을 함께 읽는다. 관련 티켓에는 이 기획의 적용 절, 기존 도구 재사용 경로, 대표 자산, 실패 검출 사례, 검증 증거 경로를 명시한다. 적용하지 않는 항목은 이유를 적는다. 기획을 읽었다는 표시만으로 구현·검증 완료를 대신하지 않는다. 기존 큐 순서와 정본 지침이 우선이며, 실행은 별도 티켓으로 넘긴다.
