# 에셋 툴 입력 규격과 후보 선택

[핵심 기획](asset-tool-strengthening.md)의 입력 설계 부록. 새 기능은 미구현이다. 기존 소비 규격·사용자 선택이 우선이다.

## 1. 입력을 세 층으로 분리

**게임 의미:** 어떤 행동·상태·대상을 구별해야 하는가. 예: 공격 준비와 회수, 선택과 비활성, 발판과 배경 장식. 게임 데이터 id와 연결하되 규칙·능력치를 이미지 생성기가 결정하지 않는다.

**시각 계약:** 기준 자산·팔레트·선·재질·카메라·조명·투명도·피벗·크기·방향·모션·장비. 반드시 유지할 특징과 변형 가능한 특징을 따로 적는다. 색만 바꿔 종·기능 차이를 대신하지 않는다.

**생산 설정:** 기존 도구·모델·seed·가공 순서·판정 규격·출력 버전. 시각 계약과 따로 버전 관리해 생산 설정 변경이 모든 자산의 자동 재생성을 뜻하지 않게 한다.

`prompt_kit.py`의 현재 입력은 subject·spec·style·view·palette·extra·init_image 등을 받는다. 게임 의미·세트 관계·검증 증거는 이 필드만으로 표현됐다고 가정하지 않는다. 추가 계약은 기존 입력에 호환되는 부가 정보로 설계하고, 생성 배치로 변환할 때 유실 여부를 검사한다.

## 2. 종류별 고정·변형·검사

| 종류 | 고정할 것 | 허용할 변형 | 반드시 비교할 장면 |
|---|---|---|---|
| 캐릭터 세트 | 얼굴·체형·의상 부품·무기·잡은 손·신체 기준점 | 자세·표정·가림 관계 | 방향 전환과 네 기본 모션, 실제 게임 크기 |
| 전투 적 | 공격 신호·실루엣·판정과 대응하는 부위 | 동일 종의 승인된 외형 | 배경·아군과 겹친 준비/접촉/회수 |
| 장비·스킬 아이콘 | 기능 의미·주요 윤곽·광원·여백 | 승인된 소재·장식 | 실제 슬롯·흑백·비슷한 아이콘 옆 |
| UI 키트 | 판별 모양 언어·9-slice 경계·본문 여백 | 상태별 강조·눌림 | 작은/큰 창, 긴 글자, 모든 상태 |
| 반복 타일 | 물리적 결 크기·광원·반복 주기 | 승인된 얼룩·마모 | 반복 배치·다른 타일과 경계·이동 화면 |
| 겹 배경 | 수평선·원근·광원·진행 경로의 여백 | 구름·원경·식생 | 전경·인물·효과·UI가 합쳐진 장면 |
| 3D 환경 소품 | 단위·원점·접합면·재질 규격 | 키트 안 부품 조합 | 배치 간격·충돌 위치·카메라 거리별 모습 |

알파·이음·9-slice·충돌체·관절은 프롬프트만으로 보장되지 않는다. 후처리·메타데이터·게임 문맥을 각각 검사한다. VFX는 기존 효과와의 구별만 검증한다.

## 3. 현재 생성 규격과 판정 규격을 잇기

생성기의 `SPECS`와 판정기의 `SPEC`은 같은 표가 아니다. 명시적인 대응을 두고 이름·이미지 크기 추정은 보조 수단으로만 쓴다. 아래는 대응 제안이다.

| 생성 입력 | 정적 후보 판정 | 별도로 필요한 검사 |
|---|---|---|
| character / character_tall / creature | sprite | 방향·체형·장비·모션·접지 |
| sprite | sprite | 소비 크기·투명 경계·피벗 |
| icon | icon | 기능별 구분·작은 크기·유사 후보 |
| portrait | portrait | 같은 인물의 몸·표정과 일치 |
| bg | bg | 겹 배치·진행 경로 가독성 |
| tile | tile | 반복 이음·결 크기·이웃 타일 |
| 코드 UI·3D 키트 | 기존 전용 검사 우선 | UI 상태·9-slice / 단위·접합·재질 |

한 배치에서 규격을 섞으면 **항목별 최종 설정**을 보고서에 남긴다. 파일 기본값·항목 override·실제 출력 크기가 일치하는지 확인한다. 특히 tile의 tiling 옵션을 비타일 항목이 상속하지 않는지 회귀 사례로 유지한다. 판정기가 지원하지 않는 규격은 generic으로 조용히 통과시키지 않고 미지원 사유를 기록한다.

## 4. 후보 선택 순서

1. 소비 규격·라이선스·파일 손상 등 필수 조건을 먼저 검사한다. 후보 중 최고점도 여기서 실패하면 탈락한다.
2. 같은 입력 계약·출력 목적의 후보끼리 비교한다. 초상과 전신, 서로 다른 방향을 한 경쟁 묶음으로 섞지 않는다.
3. 품질·스타일 점수는 통과 후보의 순위를 정하는 보조 근거다. 기준 그림 해시·선정 근거·평가 기능 사용 여부를 함께 기록한다.
4. 전후 비교는 게임 내 크기·배경·속도·카메라를 고정한다. 원본 확대에서 좋아 보여도 게임 화면에서 무기·행동을 읽지 못하면 보류한다.
5. 적합 후보가 없으면 문제 부위·원인·다음 수정 범위를 보고한다. 단순히 후보 장수를 늘려 다시 생성하지 않는다.

CLIP 미사용·기준 그림 없음·미지원 방향을 명시한다. 신규 모델은 추가하지 않는다.

## 5. 기존 결정 보존과 확장 순서

K-0202에는 2나락 돌판 UI와 나머지 네 판 UI 방향을 선택·생성한 기록이 있다. 새 기획을 이유로 다시 시안을 고르거나 모두 재생성하지 않는다. `uigen.py`·`uigen_styles.py`·`uigen_stone.py`와 `make_ui_icons.py`를 먼저 확인해 상태·판별 규격을 강화한다.

K-0193은 단순 타일 뒤집기·회전 변주를 실패로 기록했다. 이미 실패한 방식을 기본 재사용 전략으로 반복하지 않는다. 이음 수치가 좋아도 반복 패턴이 눈에 띌 수 있으므로 반복 시트와 이동 화면을 함께 본다. 기존 성공 결과와 실패 기록을 분리해 참조한다.

첫 도입은 대표 캐릭터 입력 계약 하나, 다음은 기존 UI 키트 하나의 상태 검사다. 그 뒤 필요한 종류만 확장한다. 그림체 변경은 새 버전의 신규 요청에 우선 적용하고, 기존 자산은 게임 내 불일치가 확인된 대상만 별도 변경 계획에 올린다. 대량 재생성은 자동 후속 동작으로 만들지 않는다.
