# 에셋 툴 강화 — 확장·실행·검증 기준

[핵심 기획](asset-tool-strengthening.md)의 후속 설계. 구현·생성 검증은 아직 수행하지 않았다.

### P1 — 게임 용도별 생성 규격

| 자산 | 게임성이 요구하는 차이 | 툴이 제공할 검사 화면 |
|---|---|---|
| 전투 인물·적 | 공격 준비·접촉·회수, 적/아군 구분 | 배경 위 실제 크기 재생, 방향·무기 비교 |
| 장비·스킬 아이콘 | 종류와 기능 구별, 등급 색만으로 구분하지 않기 | 실제 슬롯 크기·흑백·유사 아이콘 나란히 |
| UI 부품 | 기본·호버·눌림·비활성·선택 구별 | 동일 글자와 긴 글자를 넣은 상태 묶음 |
| 4종횡 배경·발판 | 설 수 있는 면과 장식을 구별 | 전경·중경·후경 및 이동 경로 겹쳐 보기 |
| 5천하 지형·소품 | 통행·엄폐·고저·점유를 구별 | 동일 카메라의 격자·선택 표시·병력 겹침 |

수치·전투 규칙을 생성기가 임의로 만들지 않는다. 게임 데이터의 의미를 입력받아 시각 규격에 연결한다. 장르별 기준은 기존 PLAN이 정본이며 본 문서는 툴의 입력·검사 기능을 제안한다.

### P1 — 배포 전 증거와 복귀

정적 판정 최고점도 필수 검사 실패면 배포하지 않는다. 기술·시각·게임 적용 결과를 분리한 보고서에 전후 비교, 실패 목록, 변경 파일, 예상 용량 차이, 소비 경로를 담는다. 성능 한도는 기존 판별 예산에서 읽고 없으면 기준선 미확정으로 표시한다.

승인된 후보는 별도 버전으로 보관한다. 배포는 대상 파일 목록을 먼저 제시하고 해당 경로만 반영하며 이전 버전과 해시를 유지한다. 중간 실패 시 부분 배포를 성공으로 기록하지 않는다. 엔진별 가져오기와 게임 배선은 해당 갈래의 후속 작업이며 소스 수정을 이번 기획에 포함하지 않는다.

## 5. 구현으로 넘길 작업 묶음

1. **요청 규격·재사용 계획**: 실제 소비 경로와 통과 자산으로 규격 작성. 생성 없이 재사용/가공/생성 목록이 나오는 드라이런부터 구현한다.
2. **대표 세트 검사**: K-0205 사례로 방향 출처·무기 대응·필수 클립 누락 검출 및 네 모션 프리뷰를 연결한다. 기존 K-0188·0198·0199와 중복 작업을 피한다.
3. **재개·부분 수정**: 중단·입력 변경·출력 손상·중복 실행을 주입해 필요한 대상만 다시 처리되는지 검증한다.
4. **배포 게이트**: 실패 후보 차단, 승인 버전 배포 계획, 중간 실패와 이전 버전 복귀를 임시 출력에서 검증한다.
5. **용도 확장**: 대표 통과 뒤 K-0202 UI, K-0196 아이콘, K-0193 배경에 계약을 적용한다. 첫 확장은 종류별 대표 세트만 수행한다.

각 묶음의 실행 티켓에는 실제 수정 파일·본보기·실행 가능한 검증 명령·완료 조건을 따로 확정한다. 본 문서의 작업 묶음은 실행 티켓이나 구현 완료 선언이 아니다.

## 6. 완료 판정과 측정

반드시 잡아야 할 회귀 사례는 방향 출처 혼용, 필수 클립 누락, 비대칭 장비의 잘못된 뒤집기, 빈 관절 부위, 프리뷰 없는 시각 통과, 해시가 다른 출력 재사용, 실패 후보 배포다. 정상 기준 자산의 오탐도 함께 기록한다.

도구 효과는 같은 대표 요청의 전후로 재사용 비율, 재생성 대상 수, 수동 수정 횟수, 검증된 세트까지 걸린 시간, 배포 뒤 발견된 결함 수를 비교한다. 목표 수치는 기준선 측정 뒤 정한다. 생성 성공률이나 이미지 점수만으로 게임성 향상을 주장하지 않는다.

이번 확인은 기존 경로·인터페이스·티켓 기록과 기획의 정합성 검토까지다. 프리뷰 시각 판정·실제 생성·게임 성능·복귀 실행은 미검증이다.
