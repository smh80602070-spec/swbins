# 에셋 툴 강화 — 확장·실행·검증 기준

[핵심 기획](asset-tool-strengthening.md)의 후속 설계(실행 미검증). [티켓 틀](asset-tool-ticket-template.md).

### P1 — 게임 용도별 생성 규격

| 자산 | 게임성이 요구하는 차이 | 툴이 제공할 검사 화면 |
|---|---|---|
| 전투 인물·적 | 공격 준비·접촉·회수, 적/아군 구분 | 배경 위 실제 크기 재생, 방향·무기 비교 |
| 장비·스킬 아이콘 | 종류·기능 구별(등급 색만으로 구분 금지) | 실제 슬롯 크기·흑백·유사 아이콘 나란히 |
| UI 부품 | 기본·호버·눌림·비활성·선택 | 긴 글자 포함 상태 묶음 |
| 4종횡 배경·발판 | 설 수 있는 면과 장식 구별 | 전·중·후경과 이동 경로 겹침 |
| 5천하 지형·소품 | 통행·엄폐·고저·점유 구별 | 같은 카메라의 격자·선택·병력 겹침 |

수치·전투 규칙은 생성기가 만들지 않고 게임 데이터의 의미를 받아 시각 규격에 잇는다(장르 기준은 PLAN이 정본).

### P1 — 배포 전 증거와 복귀

정적 판정 최고점도 필수 검사 실패면 배포하지 않는다. 보고서는 기술·시각·게임 적용 결과를 분리해 전후 비교·실패 목록·변경 파일·용량 차이·소비 경로를 담고, 성능 한도는 판별 예산에서 읽는다(없으면 기준선 미확정).

승인 후보는 별도 버전으로 보관한다. 배포는 대상 파일 목록을 먼저 제시하고 해당 경로만 반영하며 이전 버전·해시를 유지한다. 중간 실패를 부분 성공으로 기록하지 않고, 엔진별 가져오기·게임 배선은 각 갈래 몫이다.

## 5. 구현으로 넘길 작업 묶음

1. **요청 규격·재사용 계획**: 실제 소비 경로와 통과 자산으로 규격을 쓰고, 생성 없이 재사용/가공/생성 목록이 나오는 드라이런부터.
2. **대표 세트 검사**: K-0205 사례로 방향 출처·무기 대응·필수 클립 누락 검출과 네 모션 프리뷰(K-0188·0198·0199와 중복 금지).
3. **재개·부분 수정**: 중단·입력 변경·출력 손상·중복 실행을 주입해 필요한 대상만 다시 처리되는지.
4. **배포 게이트**: 실패 후보 차단·승인 버전 배포·중간 실패와 이전 버전 복귀를 임시 출력에서 검증.
5. **용도 확장**: 대표 통과 뒤 K-0202 UI·K-0196 아이콘·K-0193 배경에, 종류별 대표 세트부터.

실행 티켓마다 수정 파일·본보기·검증 명령·완료 조건을 따로 정한다(이 목록은 실행 티켓·완료 선언이 아니다).

## 6. 완료 판정과 측정

잡아야 할 회귀: 방향 출처 혼용·필수 클립 누락·비대칭 장비 잘못된 뒤집기·빈 관절 부위·프리뷰 없는 시각 통과·해시가 다른 출력 재사용·실패 후보 배포. 정상 자산의 오탐도 기록한다.

효과는 같은 대표 요청의 전후로 재사용 비율·재생성 수·수동 수정 횟수·검증 세트까지 걸린 시간·배포 뒤 결함 수를 비교한다. 목표 수치는 기준선 측정 뒤 정하며 생성 성공률·이미지 점수만으로 게임성 향상을 주장하지 않는다.

## 7. 실패 주입 검증표

검증용 사본에서만 결함을 만들고 정상 기준 자산도 같은 검사에 통과시킨다(시험 계약이지 실행 결과가 아님).

| 주입 사례 | 기대 결과 | 남길 증거 |
|---|---|---|
| 필수 방향·클립 누락 | 세트 검사 실패 | 누락 키·소비 경로 |
| 한 방향만 다른 무기/출처 | 혼용 검출 | 방향별 출처·무기 비교 |
| 접지 구간 발 이동 | 보정 대상 표시 | 궤적·영상 |
| 프리뷰 누락·입력 버전 불일치 | 시각검토완료 거부 | 입력 해시 |
| 완료 출력 손상 | 해당 출력·의존 단계만 무효화 | 재실행 목록·해시 |
| 같은 작업 동시 시작 | 두 번째 쓰기 차단 | 소유권 보고 |
| 배포 중 복사 실패 | 재배포 차단 | 전후 해시·복귀 결과 |
| 무기/망토의 의도된 분리 | 정상 예외 보존 | 예외 범위 |

미실행·미지원·측정 실패·0건은 `미검증`. 실제 검사 수를 기록하고 입력 변경 시 과거 승인을 재검토한다.

## 8. GeForce 실행 검증 기록

RTX 4060 8GB 실행 티켓용 양식이며 완료 결과가 아니다. Radeon 설정·기록은 유지한다. 재사용·CPU 가공만 하면 추론·GPU 메모리는 이유와 함께 `적용 제외`, 쓰는 모델만 검증한다.

- **담당·환경**: 티켓·담당 PC·GPU·VRAM, ComfyUI·PyTorch 버전, API·출력 경로. 세션의 장치 조회와 서버 단독 사용으로 확인하고 빈 큐만으로 소유권을 판정하지 않는다.
- **재사용 판단·입력**: 기존 출력·출처·라이선스와 새 생성이 필요한 이유, 배치 경로·해시, 모델·seed·크기·옵션이 실제 생성 요청과 일치.
- **사전 검사**: K-0213 `--dry`는 선택한 전 후보 검사. `GEN_RESULT` 기록. 0건·옛 출력의 입력 일치·추론·품질은 미검증(세부: ai-art README).
- **추론**: 요청·성공·실패·누락 후보 id, 장당 시간, 최대 메모리 측정 방법·값, OOM. 로그와 실제 PNG·라이선스 쌍을 대조하고 종료 코드 0이나 추정 수치로 완료 판정하지 않는다.
- **산출물·시각 검증**: 후보 경로·해시·라이선스·치수·투명도(기존 원본 보존), 대표 이미지 또는 네 모션 GIF/영상과 게임 내 비교, 검토한 파일·문제 프레임·판정 기록.
- **확장 판단**: 대표 통과 여부·남은 문제·다음 범위. 필수 항목에 실패·미검증이 있으면 확대를 보류하고 적용 제외 사유를 남긴다.

실측은 ai-art README GeForce 절 참조. 3D 인체 생성은 동결 유지.
