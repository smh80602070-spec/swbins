# 툴 강화 티켓 작성 틀

[핵심 기획](asset-tool-strengthening.md) · [검증 기준](asset-tool-validation.md)을 읽은 뒤 사용한다. 아래 빈칸을 채우기 전에는 상태를 `작성됨`으로 바꾸지 않는다. 이 문서 자체는 실행 티켓이 아니다.

생성·판정 관련 티켓은 [입력 규격과 후보 선택](asset-tool-input-profiles.md)의 종류별 계약·규격 대응표도 명시한다.

## 복사할 틀

```text
# K-번호 제목
상태: 초안 / 종류: 툴 강화
목표: 어떤 게임 장면의 어떤 에셋 결함을 도구로 예방하는가
기획 참조: 문서 경로 + 적용 절 / 제외 항목과 이유
선행 조건: 기존 K 티켓·자산 버전·소비 갈래·실행 머신
파일: 실제 확인한 수정 경로만 / 읽기 전용 경로 별도
본보기: 기존 함수 또는 통과 사례의 경로·위치
입력: 대표 id·원본 해시·규격 출처·방향/클립/장비 표
출력: 원본과 분리된 경로·보고서·프리뷰·변경 계획
단계:
  1. 기준선과 재사용 가능 항목 확인
  2. 기존 도구의 지정 지점 확장
  3. 정상·실패 사례를 동일 조건으로 비교
  4. 소비 측 연결 결과를 확인하거나 후속 티켓으로 분리
검증: 실제 실행 명령 + 기대 종료 코드/보고 필드/증거 경로
완료 조건: 정상 통과 + 지정 결함 검출 + 원본 불변 + 재실행 결과
메모: 실행하지 않은 항목·남은 결함·후속 갈래
```

`검증`에 아직 없는 명령·옵션을 현재 명령처럼 쓰지 않는다. 새 검증기를 만드는 티켓이면 생성할 파일과 호출 계약을 단계에 명시하고, 그 검증기 자체에 정상/오류 입력을 넣는 시험도 포함한다. CLI 종료 코드만 확인하지 말고 실제 출력·해시·소비 경로를 확인한다.

## 첫 티켓 권장 범위 — 생성 없는 요청 검사

**목표:** 대표 캐릭터 한 명을 요청했을 때 재사용 가능한 파일과 부족한 방향/클립을 정확히 보여주기. GPU 생성·배포를 호출하지 않는 작은 단위부터 시작한다.

읽기 후보는 `tools/ai-art/prompt_kit.py`의 `build`·`lint_batch`, `tools/ai-art/gen.py`의 `main`, `tools/asset-place/place.py`의 `plan`이다. 수정 파일은 실행 티켓 작성자가 중복 기능 검색 후 확정한다. 현재 게임이 실제로 소비하는 대표 id와 경로를 다시 추적하며, 티켓 기록만 보고 오래된 자산을 대표로 고정하지 않는다.

필수 결과는 입력 규격 오류 목록, 기존 자산 재사용 목록, 부족한 항목, 필요한 후속 단계, 쓰기 대상 0건이다. 필수 값 누락·소비 경로 없음·방향별 출처 혼용을 각각 분리해 보고한다. 원본 해시가 전후 같고 생성·배포가 호출되지 않았다는 증거를 남긴다.

## 기존 도구에서 확인한 주의점

- `gen.py --dry`와 `--only`가 있다는 사실만으로 전 파이프라인의 무수정 드라이런·안전한 재개가 보장되지는 않는다. 각 단계의 파일 쓰기와 호출 관계를 따로 확인한다.
- `k188/detach_check.py`는 옆 방향 팩을 읽고 시점을 표본 검사한다. 앞·뒤 전체 방향이나 모든 프레임 통과로 확대 해석하지 않는다. 기본 출력은 `tools/char-forge/_out/k199` 아래 고정 경로이므로 병렬 검사·지난 결과 덮어쓰기 문제를 먼저 확인한다.
- 위 검사의 `--noweapon`은 무기를 제외한다. 이를 사용한 통과 결과로 무기 이음새·궤적까지 통과 처리하지 않는다. 장식의 정상 분리와 결함을 구별할 정상 사례가 필요하다.
- `asset-place/place.py --write`는 대상 파일을 순차 복사한다. 검증 상태 확인·트랜잭션·자동 복귀가 이미 있다고 가정하지 않는다. 추가 기능은 임시 대상에서 중단 시험 후 기존 배치에 연결한다.

## 인계 보고 틀

완료한 도구 기능 / 적용 기획 절 / 대표 자산과 입력 버전 / 정상·실패 시험 결과 / 프리뷰 판정과 경로 / 변경 대상과 원본 불변 확인 / 게임 적용 검증 여부 / 남은 작업을 짧게 기록한다.

기획 완료, 도구 시험 통과, 에셋 품질 통과, 게임 적용 완료는 서로 다른 상태다. 다른 갈래가 끝내야 하는 배선을 자체툴 완료 보고에 섞지 않는다.
