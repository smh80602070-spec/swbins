# K-0022 VRoid 대량 들이기 — 인물 3D·2D 에셋을 이어하기로 자동 처리하고 진행표를 낸다
종류: 새기능 · 도구      상태: **작성됨**(R-0 2026-10-02, 사용자 결정으로 범위 확정) — 첫 VRM 1개 필요      등급 목표: D2

**목표(한 줄)**: 사용자 결정(2026-10-02) "**인물 에셋은 VRoid 로 다 한다**". 사람이 VRoid Studio 로 만든 VRM 이 폴더에 쌓이면 새로 들어온 것만 골라 인물마다 **3D 에셋(툰 GLB·CC0 동작 8, 웹 3D·Godot·Unity 동일)** 과 **2D 에셋(128px 시트)** 을 만들고, 인물별 진행표를 낸다. **도감은 VRoid 가 아니다** — 도감(데이터·초상)은 기존에 추가하던 방식(`data.js` 다섯 벌 md5 동일 + `tools/ai-art` 초상)으로 늘려 500명을 만든다(이 티켓 밖). 폐기: MakeHuman 실물풍 `_out/hero|realm`·VRoid CC0 몸+무작위 장비(10명이 거의 같아 보임)·범용 시트 20벌(임시).

**파일(확인함)**: `tools/char-forge/vroid_intake.sh`(1명: GLB 사본·얼굴 데칼 `tools/asset-forge/vroid_face_bake_project.py`·`bake_for_rig.py`+`verify.py`(`--map vroid`)·Godot `ual_lib_build.gd`·`cel_shader_apply.gd` 표) · `tools/char-forge/gear_sprites.py`+`bake_sprite_batch.py`(VRM 몸 2D 시트, `bodies` 맵에 인물별 glb) · 명단 `tools/char-forge/data/roster.json`(299, `make_roster.mjs`) · 놓기 K-0019 `tools/asset-place/`

**규약**: VRM = `tools/char-forge/_in/vroid/<id>.vrm`(git 밖). id 는 영문 소문자·숫자·`_`(명단 id 그대로, 명단에 없으면 "신규"로 표시). 산출 `tools/char-forge/_out/vroid/<id>/`, 통과분만 K-0019 로 `saga-assets/`.

**단계**
1. `vroid_status.py`: 명단 id + `_in/vroid` 의 신규 id × 단계(`vrm`·`glb`·`anim`·`sheet2d`) 표, 요약("n명 완료/들어옴/대기"), `--missing`.
2. `vroid_batch.sh`: `_in/vroid/*.vrm` 중 결과가 없는 것만 차례로 공통부(GLB 사본·동작 굽기+검증·2D 시트)를 돈다. 낮은 우선순위·`</dev/null`·실패는 로그에 남기고 계속·3회 실패면 건너뜀 표시.
3. Godot 부(`anim_cc0/<id>_lib.res` 등, Godot exe 필요)는 분리 — exe 가 없으면 "대기"로 두고 나머지 진행(압축 `scratchpad/keep/Godot.zip` 은 푼 뒤 `GODOT=` 지정).
4. 시험: 사용자 VRM 1개(또는 시험용 `saga-godot/assets/characters_vroid/AvatarSample_A.vrm`)로 3D·2D 가 나오고 `audit.py --quick` 🔴 0.

**검증**: `py tools/char-forge/vroid_status.py` 요약 · 시험 1명 산출 · 두 번째 `vroid_batch.sh` 는 아무것도 안 함(멱등).

**완료 조건**: 단계 1~4. 500명 들이기 자체는 사람(VRoid)과 이 도구의 반복 실행.

**불변 규칙**: VRM 원본 공개 저장소 금지 · 게임 폴더 직접 수정 금지(배치 K-0019) · 이름 정책(표시 글자) · VRoid 권리는 만든 사람(꾸미기 앱 배포만 금지) · 헤드리스 Godot 은 `</dev/null`.

**메모(체크포인트)**: 1~3 은 VRM 없이 가능. 도감 500 은 별도 일반 절차.
