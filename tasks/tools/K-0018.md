# K-0018 인물 몸 통일 — Unity 도 Godot 과 같은 공방 툰 몸으로
종류: 새기능 · 에셋      상태: **작성됨**(R-0 2026-10-01) — 사용자 판정 포함      등급 목표: D2

**목표(한 줄)**: 사용자 지시(2026-10-01) "유니티도 사가고돗과 동일하게, 파판식 사실풍은 불가" 에 따라 Unity 가 쓰는 Mixamo 사실 몸(61)을 Godot 이 쓰는 **공방 툰 몸 + VRoid**(`saga-godot/assets/characters_cf`·`characters_vroid`·CC0 동작 `anim_cc0`)와 같은 몸 계열로 맞춘다. 같은 인물·같은 모습 = 3 트랙 일관(웹 3D 모드도 같은 몸 GLB — 사용자 "3D 는 세 트랙 동일"), Mixamo 재배포 문제도 사라진다.

**파일(확인함)**: `tools/char-forge/`(들이기·옷 변형·`render/` 점검·`export_vrm_parts.py` — 몸 생성은 동결, **들이기·변형·점검만**) · `tools/char-forge/recipes/*.json`·`sources.json` · Godot 쪽 완성본 `saga-godot/assets/characters_cf/`(짝 쉰둘 OK) · Unity 쪽 현재 `saga-unity/Assets/Art/CharactersForge/`(FBX 166, `_cmp_real_*.fbx` 비교본)·`Art/CharactersRealistic/`(Mixamo, 로컬 전용) · 인물 대응 `tools/asset-audit/CHARACTER_UNIQUENESS.md`

**단계**
1. 현황표: Unity 인물 id 61 ↔ Godot 에 대응하는 공방/VRoid 몸 있는지(`saga-unity/features.json`·Godot `characters.gd`) — 없는 것만 목록.
2. Godot 몸(GLB, Meshopt 없음)을 Unity 가 읽는 형식(FBX/GLB + 리깅 Humanoid)으로 내보내는 경로를 `export_*` 로 확인·시험 1벌: 뼈 이름·동작 클립(CC0 8동작) 유지.
3. 시험 3벌(사람·괴물·동물)을 Unity 비교 장면 시트로 → **사용자 판정**("Godot 과 같아 보인다 / 아니다"). 아니면 중단하고 메모(되풀이 금지).
4. 통과 시 61벌 일괄 변환 계획표 `tools/char-forge/data/unity_bodies.json`(실행은 K-0019 배치 + U-0022 코드).

**검증**: 변환 시험 1벌이 Unity 임포트 로그 오류 0(`unity-batch.sh`) · 3벌 시트 · `audit.py --quick` origin 🔴 0.

**완료 조건**: 단계 1~3 + 사용자 판정 한 줄. 4 는 판정 "좋다" 일 때만.

**불변 규칙**: 몸 생성 동결(ARCH §4.5) · 이름 정책 · 비상업 몸 공개 저장소 금지 · Unity 프로젝트 직접 수정은 K-0019/U 티켓만.

**메모(체크포인트)**: 이전 결정(09-26 D5 "Unity = Mixamo 유지, 공방 사실 몸은 눈으로 보니 미달")은 **사실 몸** 기준이었다 — 이번엔 톤을 Godot 과 맞추는 쪽이라 판정 기준이 다르다.
