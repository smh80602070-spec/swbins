# K-0009 `scenario/README.md` §7 진행표를 코드의 장 표에서 세어 생성
종류: 통합 · 문서      상태: **닫음 2026-10-01**      등급 목표: D1 — 생성기 + 표 일치

**전제 정정(R-0)**: 초안은 "features.json 에서"라 했으나 확인해 보니 `features.json` 은 기능 단위(`dg.quest` 등)라 **장 수가 없다**. 장 수는 각 트랙의 장 표 코드에 있다 → 코드를 세어 표를 만든다(손표는 첫 실행의 정답지).

**목표(한 줄)**: `tools/scenario-count.mjs` 가 웹·고돗·유니티의 장 표를 세어 `scenario/README.md` §7 표의 "구현된 장" 칸을 생성한다(낡은 "사가고 웹 1~9장" 류를 없앰).

**파일(확인함)**: 웹 `saga-web/saga-{dungeon,forest,story,realm}/js/data-scenario.js`(IIFE, `global.DG.scenarioData.CHAPTERS` 꼴 — 네임스페이스는 판마다 다름, 실행 때 확인) · 사가고 웹 `saga-web/saga-go/js/story.js` · 고돗 `saga-godot/games/saga_go/data/story_chapters_{1..4}.gd`(순서가 곧 번호) · 유니티 `saga-unity/Assets/Games/Saga{Dungeon,Forest,Story,Realm}/Data/*ScenarioData.cs`(`RealmScenarioSideData.cs` 포함) · 새 `tools/scenario-count.mjs` · 고칠 곳 `scenario/README.md` §7 표만(마커 `<!-- scenario:begin/end -->` 를 표 둘레에 심는다)

**본보기**: `tools/status.mjs` 의 마커 블록 덮어쓰기(`status:begin/end`)·의존 없는 node 한 파일.

**단계**
1. 판·트랙 9곳에서 "장 하나"의 코드 모양을 확인해 세는 규칙을 정한다(웹: `vm` 으로 파일을 `window` 스텁에 돌려 CHAPTERS 길이 / 고돗·유니티: 정규식으로 항목 수). 규칙은 스크립트 머리말에 쓴다.
2. `scenario-count.mjs` 작성 — 출력 JSON(`tools/_out/scenario-counts.json`)과 표 마크다운. 못 세는 칸은 `?` 로 두고 **추측하지 않는다**.
3. 현재 손표(§7)와 대조해 차이를 표로 보고 → 손표가 낡은 칸만 생성값으로(예: 사가고 웹 1~9장).
4. `--write` 일 때만 §7 마커 블록을 덮어쓴다. 손으로 쓴 설명(5행 아래 "권장 구현 순서")은 마커 밖에 둔다.

**검증**
```
node tools/scenario-count.mjs            → 표 5행×3열, ? 개수 보고
node tools/scenario-count.mjs --write    → scenario/README.md §7 마커 블록 갱신(두 번째 실행은 diff 0)
bash tools/precheck.sh                   → OK
```

**완료 조건**: 단계 1~4 · `?` 0 또는 사유 기록 · 두 번 실행 diff 0.

**불변 규칙**: 게임 코드·features.json 은 읽기만 · 이름 정책(표에 실명 금지) · `scenario/` 장 설계 문서(§1~§6)는 안 건드림 · 의존 없는 node.
