# K-0080 몬스터 GLB 판정 결함 셋 — 원소색이 안 읽힘 · 종 이름과 모양 어긋남 · 네발이 옆을 봄 (K-0043 후속)
종류: 버그 · 에셋      상태: **끝**(10-07 — 고돗 연결은 G 짝)      등급 목표: D2

**목표(한 줄)**: 고돗 G-0059 가 몬스터 GLB(mon 20·boss 12)를 들판 적에 붙여 코드 짐승과 나란히 찍었더니 GLB 가 못했다(기본 꺼둠). 셋을 고쳐 고돗이 `monster_body.gd` `enabled()` 한 줄로 켤 수 있게 한다.

**지금 상태(확인함, 10-07)**
- ① 색: `tools/world-forge/build_monster.py` `mats()` 가 몸·어두운 곳·배를 사진 질감 × 계통 색(`SKINS`, 갈색·회색·이끼 위주)으로, 빛(`glow`)은 무작위 4색. 고돗 종(`games/saga_go/combat/field_enemy.gd`)은 종마다 `colors` 3색(몸·둘째·빛)을 갖고 코드 짐승은 그 색으로 칠한다 — GLB 엔 종 색이 들어갈 자리가 없다.
- ② 모양: 고돗 `monster_body.gd` 는 코드 모양 → 갈래(goblin→spir, serpent→serp …)만 보고 변형 01~04 를 **개체 이름 해시**로 고른다. 그래서 불도깨비(goblin)가 초록 해파리꼴 spir, 덩굴뱀(serpent)이 빨간 거미꼴 serp 를 받는다. 변형마다 무슨 꼴인지 표가 없다.
- ③ 방향: 생성기 머리말 "얼굴 = Blender −y(glTF +z)", 코드 짐승도 앞 = +Z(`creature_builder.gd`) — 서류로는 맞는데 촬영에선 네발이 옆을 본다. 내보낸 파일 실측이 없다.

**파일**: `tools/world-forge/build_monster.py`(재질 이름·중립 질감·방향) · 새 `tools/world-forge/data/monster_forms.json`(변형 id → 꼴 이름·꼴 갈래·앞 방향 실측) · 새 `tools/world-forge/data/monster_species.json`(고돗 종 id → 맞는 변형 id·보스 id, 색은 고돗 표를 가리킴) · 렌더 `tools/world-forge/_render_dir.sh` · 배치 `tools/asset-place/asset-place.json`(world-toon) · 수신함(고돗 짝 요청).

**단계**
1. **실측 표**: 32벌을 위·앞·옆 세 방향으로 렌더(축 표시) → 변형마다 꼴(늑대·멧돼지·고양이·황소 / 박쥐·새 … / 뱀·지렁이·거미 …)과 실제 앞 방향을 `monster_forms.json` 에. ③ 이 생성기 탓(축 뒤바뀜)이면 그 자리에서 고친다.
2. **종 ↔ 변형 표**: `field_enemy.gd` 종 23(들판·보스) 을 읽어 이름·모양에 맞는 변형을 손으로 고른 `monster_species.json`(실명 금지 — id 만). 맞는 꼴이 없는 종(예: 불도깨비 = 도깨비꼴 spir 가 없으면)은 표에 `없음` → 단계 3 에서 그 꼴 변형을 추가(같은 생성기, 새 id).
3. **칠할 자리**: 재질 이름을 `mon_body`·`mon_dark`·`mon_belly`·`mon_glow` 로 고정하고 질감을 무채색 쪽으로(채도 낮춤) — 고돗이 종 `colors` 를 곱해 칠하면 원소색이 읽히게. 무늬·질감 해상도는 그대로(화질 안 깎기). 렌더로 "종 색 곱했을 때" 미리보기 시트(종 23칸).
4. 다시 굽기 → 정본 `saga-assets/world/toon` → place(고돗·유니티) → 고돗 `.glb.import` 다시(가져오기, 바뀐 것만 `add -f`). 고돗 짝(수신함): `monster_body.gd` 가 해시 대신 `monster_species.json` 으로 변형을 고르고 재질 이름별로 종 색을 곱한다.

**검증**: 세 방향 시트 Claude 눈 — 32(+추가)벌 앞이 +z(실측 표 전부 `+z`) · 종 23칸 미리보기 시트에서 종 이름과 꼴이 맞고 원소색이 읽힘 ○ · `WORLDFORGE ok` 전부 · `place.py --check` 불일치 0 · `bash tools/precheck.sh` OK.

**완료 조건**: 단계 1~4 · 두 표 커밋 · 고돗 짝 요청 한 줄.

**본보기**: K-0043 산출·메모(같은 생성기) · `build_vehicle.py`(툰 내보내기) · 고돗 `creature_builder.gd`(코드 짐승 색 칠하기 규칙).

**불변 규칙**: id·파일 이름 그대로(새 꼴만 새 id) · 원작 몬스터 모양·이름 모사 금지 · 표시 글자 실명 금지 · 게임 폴더 직접 수정 금지(place 로만) · 3D 세 트랙 동일 · 화질 안 깎기.
