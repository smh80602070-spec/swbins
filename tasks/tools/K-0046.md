# K-0046 모바일 최적화 에셋 — LOD·텍스처 묶기·압축으로 폰 발열·용량을 줄인다(화질은 안 깎는다)
종류: 통합 · 도구      상태: **단계 1·2 끝(측정·LOD 도구), 3(일괄)·화질 게이트는 후속**(10-04)      등급 목표: D2

**목표(한 줄)**: 인물 299명 + 건물 + 소품이 쌓이면 폰에서 메모리·발열이 문제다. 사용자 방침("최적화 = 화질 안 깎기": 텍스처·그림자를 낮추지 말고 안 보이는 낭비만)에 따라 **LOD 단계·텍스처 아틀라스/묶기·중복 텍스처 합치기·압축**을 자동으로 처리하는 도구와 기준표를 만든다.

**파일(확인함)**: `tools/glb-compress/compress.mjs`·`vrm-slim.mjs`·`join-parts.mjs`·`seam-simplify.mjs` · `tools/graphics-gate/diff.mjs`(화질 비교 게이트)·`tools/asset-audit/audit.py`(용량 점검) · 새 `tools/glb-compress/lod.mjs`·`data/budget.json`

**단계**
1. 예산표: 트랙·기기 등급별 한 화면 삼각형·텍스처 메모리·드로콜 목표(현재 값은 측정으로 채운다 — 추측 금지).
2. LOD 도구 시험 3몸 + 건물 3 → `graphics-gate` 로 화질 차이가 기준 이하인지 확인.
3. 통과한 설정만 일괄 → 용량 감소율 보고 → K-0019 배치(원본은 로컬 보관).

**검증**: 예산표 항목 측정값 있음 · 화질 게이트 통과 · 용량 감소율 · `audit.py --quick` 🔴 0.

**완료 조건**: 단계 1~3.

**불변 규칙**: 화질을 낮추는 설정 금지(낭비 제거만) · 원본 삭제 금지 · 게임 폴더 직접 수정 금지(배치는 K-0019) · 이름 정책 · 상업 허용·CC0 에셋만 · PC 안 멈추게(GPU 작업은 다른 GPU 작업과 동시 금지)

**메모(체크포인트)**: ✔ 단계 1 (10-04, 사용자 "큐 순서대로 다 적용"): `tools/glb-compress/measure.mjs` → `data/budget_measured.json`(모델별 실측)·`data/budget.json`(분포·발견·권고·기기 등급 목표 **제안**). 실측: 인물 299 = 삼각형 중앙값 4.2만(최대 6.1만)·드로콜 18(최대 24)·압축 전 GPU 텍스처 61MB(최대 86MB) / 세계 298 = 삼각형 중앙값 130·p95 1.8k·텍스처 ≤1.7MB. → 최적화 대상은 인물(텍스처 GPU 압축 + 거리별 LOD). 
✔ 단계 2: `lod.mjs`(meshopt simplify, lockBorder, 원본 불변) 시험 — 인물 3몸 LOD1 0.56~0.67배·LOD2 0.25~0.32배, 건물·나무 4개는 0.96~1.00배(이미 저폴리·각진 면 → LOD 불필요). 산출 `tools/char-forge/_out/lod`(로컬).
✔ ① 화질 확인(10-06, 작업 중 헤드리스 촬영 금지라 Blender 렌더로 대신): 지금 몸 GLB 로 LOD 다시(1 = 0.56~0.65배·2 = 0.25~0.31배) → 원본과 몸 픽셀만 비교, LOD1@256px 평균 차 0.8~1.0/255·윤곽 ≤0.15%, LOD2@128px 2.4~3.8·윤곽 ≤1% — 얼굴 512px 에서도 구별 안 됨 → 통과.
