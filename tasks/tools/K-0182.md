# K-0182 precheck 가 작은 커밋에도 20분 — 경로 범위 밖 절은 건너뛰기·절마다 걸린 시간 찍기
종류: 도구(커밋 게이트) · 자체툴(tools/)      상태: **요청**(유니티 세션 10-22 밤 — 사용자 "왜 느린가 티켓도 만들어줘")      등급 목표: D1

**무엇이 느렸나(10-22 유니티 U-0164~0168 커밋 다섯 번)**: `PRECHECK_PATHS` 로 18개 파일만 넘겨도 precheck 단독 실행이 10~20분 넘게 걸리고, 이어지는 `git commit` 이 훅으로 precheck 를 **한 번 더** 돌려 한 커밋에 두 배가 든다. 10-22 21:23 에 시작한 precheck 가 21:46 까지도 끝나지 않아 사용자가 기다리다 멈췄다.
- 같은 시각 다른 세션 두 곳의 `tools/push.sh` 가 `git worktree remove --force C:/swt-…` 에서 13~17분 멈춰 있었다(큰 임시 worktree 지우기 — 디스크를 나눠 씀).
- 출력에서 오래 머문 곳: "문서 크기" 절(모든 문서 크기 줄) 뒤 · 에셋·크레딧·정본 범주 절(파이썬 — 유니티 .cs 만 바뀐 커밋과 무관).

**원하는 것**
1. 절마다 걸린 초를 `== 절 이름 (12.3s)` 로 찍는다 → 어디가 느린지 숫자로.
2. `PRECHECK_PATHS` 가 있으면 그 경로와 상관없는 절은 건너뛴다: 예) 바뀐 경로에 `saga-web/` 가 없으면 js 구문·도감 md5·shared 정본·manifest·world3d·sw.js·features 스키마(웹)·진단 수 건너뜀 · 에셋 경로(`saga-assets/`·`Resources/`·`.glb`·`.png`)가 없으면 asset-audit·credits·reflect 건너뜀 · 문서(.md)가 없으면 문서 크기 건너뜀.
3. 같은 트리 같은 경로 목록으로 방금 통과했으면(경로 목록 + 각 파일 해시가 같으면) 훅의 두 번째 precheck 는 캐시로 바로 통과(예: `tools/_out/precheck-pass.json`, 10분 유효).
4. `push.sh` 의 임시 worktree 지우기를 백그라운드로 넘기거나(푸시 성공 뒤엔 기다릴 이유 없음) sparse worktree 로 작게.

**불변**: 막아야 할 것은 그대로 막는다(경로 안 절은 다 돈다) · `--full` 은 지금처럼 전부 · 훅 우회 플래그 안 만듦(memory: commit 게이트 우회 금지).

**검증**: 유니티 .cs 다섯 개 + tasks md 하나 커밋에서 precheck 단독 ≤ 60초 · 같은 목록 두 번째(훅) ≤ 5초 · 웹 js 고친 커밋은 지금과 같은 절이 돈다 · 일부러 넣은 오류(웹 js 구문·문서 6144B 초과)가 여전히 막힌다.

**메모**: 10-22 요청 작성(유니티 세션). 이 갈래(K) 큐 줄은 K 세션 몫이라 안 고침.
