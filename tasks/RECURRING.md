# RECURRING — 반복 티켓 (큐가 비거나 비율이 기울면 여기서)

각 항목은 그 자체가 티켓이다(9필드 대신 고정 절차). 실행 기록은 커밋 메시지에 `[R-n]` 접두.
**전제**: R-1·R-2·R-3 은 T-0001~T-0004 가 끝난 뒤부터 돈다. 그 전에는 큐만.

## R-1 주간 상태 갱신 (매주 첫 세션)
- 돌린다: `node tools/test-web.mjs all` → `node tools/status.mjs` (Godot·Unity 는 각 러너 결과 파일이 있으면 읽는다).
- 고친다: 각 트랙 `STATE.md` 를 status 출력으로 **덮어쓴다**. 루트 README "현재" 절도 같은 표.
- 보고: 판별 완성도 %·D0/D1 개수·WIP 초과 판. 커밋 `-- <STATE 파일들> README.md`.

## R-2 확인 시트 (R-1 다음 세션)
- `node tools/status.mjs --sheet <판>` 으로 D1·D2 기능 10개 시트를 `tasks/sheets/<판>-<날짜>.md` 에 낸다. 플래그십 먼저.
- 사용자가 ○/× 를 적어 오면: ○ → `features.json` `level: "D3", verified: <날짜>` · × → `T-NNNN` 버그 티켓 초안(제목·재현 3줄·기대 1줄만, 나머지 칸은 페이블) 을 큐 "미작성"에 추가.
- 시트 없는 기능은 확인 요청 금지.

## R-3 닫기 세션 (비율 40%)
- `features.json` 에서 `level: "D0"` 중 가장 오래된 것 하나: 진단 항목을 `_test.html`(웹)·probe(Godot)·Playtest(Unity)에 붙여 D1 로.
- 규칙: 진단은 규칙 층 함수만 부른다(화면 없이). 이름은 `<기능id>: <무엇>` 으로. 러너 PASS 확인 후 `level: "D1"`.

## R-4 통합 세션 (비율 20%)
- 1,500줄 넘는 파일 목록(`node tools/status.mjs --big`)에서 하나: 주제별로 나눈다. 같은 네임스페이스에 붙이므로 호출부 변경 없음. 진단 수가 줄지 않았는지 러너로 확인.
- 또는 복제 파일 하나를 shared/core 로(ARCH §4.2~4.4 목록 순).

## R-5 코드 리뷰 (매 티켓 끝, 그리고 주 1회 플래그십 파일 하나)
- `/code-review` 를 돌리고 지적을 티켓 메모에 남긴다. 고칠 것은 같은 티켓 범위 안이면 바로, 아니면 큐 "미작성"에 제목만.

## R-6 문서 상한 점검 (월 1회)
- `bash tools/precheck.sh` 문서 절 WARN 목록. 상한 90% 넘은 문서는 끝난 절을 한 줄로 접는다(설계 층은 결정만 남긴다). 이력은 archive 로.
