# W-0071 옷 무늬 `patterns.json` 404 — `vroid-variant.js` 가 통일 에셋 뿌리가 정해지기 전에 판 폴더로 받는다(경주)
종류: 버그 · 웹(shared 정본 + 다섯 판 core.js)      상태: **작성됨**(페이블 2026-10-05, 수신함 K-0073 검사기 결과)      등급 목표: D2

**목표(한 줄)**: 무늬 표를 항상 있는 자리(`shared/assets/patterns/`)에서 한 번에 받게 해 404 를 없애고, 옷 무늬(W-0020)가 첫 로드에서도 입혀지게 한다.

**재현(확인함, 10-05)**: `saga-web/shared/js/vroid-variant.js:163~166` `patBase()` — `DG.assets3d` 가 뿌리를 찾았으면 `<뿌리>/patterns/`, 아니면 `DG.cfg.vroidPattern.base`(다섯 판 `core.js:501` = `'assets/patterns/'`). `assets3d.js` 는 `state 'init' → probing → ok` 로 **비동기** 탐색(16·47행)이라 `vroid-variant.js:179` 의 `fetch(patBase(c) + 'patterns.json')` 이 먼저 돌면 `<판>/assets/patterns/patterns.json` 을 받는데 그 폴더는 **없다**(무늬 64종은 `shared/assets/patterns/` 에만). → 404 + 무늬 없음.

**파일**: `saga-web/shared/js/vroid-variant.js`(정본) · `saga-web/shared/js/assets3d.js`(준비 콜백 1개 노출) · 다섯 판 `js/core.js` 501행 `base` 기본값 · `node tools/sync-shared.mjs` 로 다섯 벌 반영.

**단계**
1. `assets3d.js` 에 `whenReady(fn)` 추가: state 가 `ok`/`fail` 로 끝나면 fn(root|null) 호출(이미 끝났으면 즉시). 기존 `whenLoaded` 패턴 그대로.
2. `vroid-variant.js` 무늬 표 받기를 `DG.assets3d.whenReady` 안으로 옮긴다. 뿌리가 없으면(fail) `c.base` 로 간다.
3. 다섯 판 `core.js` `vroidPattern.base` 를 `'../shared/assets/patterns/'` 로(판 폴더엔 무늬가 없으니 기본값도 있는 자리로). `node tools/sync-shared.mjs`.

**검증**: `node saga-web/tools/playcheck/net-log.mjs saga-go --scenes=index` 결과 `tools/asset-audit/out/netlog_saga-go.json` 의 `missing` 에 `patterns.json` 없음 · `requested` 에 `shared/assets/patterns/patterns.json` 1건 · `node tools/test-web.mjs saga-go saga-forest` 858/858·410/410 그대로 · `node tools/sync-shared.mjs --check` OK.

**완료 조건**: 다섯 판 netlog `missing` 에 patterns 0 · 진단 수 그대로 · sync-shared OK.

**본보기**: `saga-web/shared/js/assets3d.js` `whenLoaded`(load 뒤 콜백) · `saga-web/saga-go/js/asset3d.js` `loader()`(준비 전엔 null 반환).

**불변 규칙**: 무늬 파일은 안 만지고(K 갈래) 코드 배선만 · shared 정본 → 다섯 벌 복사(md5) · 세이브 없음.
