# W-0026 사가국지 진단 10분 시간 초과 — 한 달을 넘길 때 `changed` 가 ~60번 나가 지도를 그만큼 다시 그린다
종류: 버그 · 웹(사가국지)      상태: **끝**(2026-10-03)      등급 목표: D1 유지(진단이 돌아야 D1 이 의미가 있다)

**목표(한 줄)**: `node tools/test-web.mjs saga-realm` 이 전부터 10분 하드 타임아웃으로 `0/0` 이라 사가국지 진단 272개가 하나도 안 돌았다. 원인을 찾아 고친다.

**원인(측정)**
- 크롬에 `t()` 시작 로그를 심은 임시 사본으로 보니 한 항목이 수십~수백 초: ④ 백지 24달×5씨앗 58s · 특성·야망 60달 96s · 사연 60달 188s+.
- 같은 24달을 node vm(규칙 층만)으로 돌리면 5씨앗 28s — 크롬이 5배 느린 이유는 **화면 그리기**였다. `rtk.endMonth()` 한 번이 `core.emit('changed')` 를 약 59번(24달 1411번) 내고, `ui-rtk.js` 의 `changed` 수신자는 매번 `renderTop·renderMap(성 135곳 SVG)·renderSheet·syncDock` 을 다 돈다. 진단뿐 아니라 실제 게임에서도 월말 한 번에 지도를 ~60번 그린 셈이다.
- 부수 발견: `rtk.state()` 가 부를 때마다 `migrateNewCities` 가 성 135곳을 훑었다(24달 CPU 의 ~50%).

**파일(확인함)**: `saga-realm/js/core.js`(`emit`) · `src/rtk/01.js` `migrateNewCities` · `src/rtk/02.js` `endMonth`(→ `js/rtk.js`, `tools/build-parts.mjs`) · `sw.js`

**단계**
1. `core.batch(fn)` — 안에서는 `changed` 를 모았다가 끝에 한 번만 낸다(다른 이벤트는 바로). `endMonth` 를 `core.batch(endMonthRaw)` 로 감싼다.
2. `migrateNewCities` 는 다 채운 `st.cities` 객체 + 성 수가 같으면 바로 돌아온다(`setup()` 이 `st.cities = {}` 로 새 객체를 만들므로 낡은 표를 못 쓴다).
3. 줄 수는 안 늘린다(`js/rtk.js`가 큰 파일 목록에 있다) — 한 줄 안에서 고쳤다.

**검증**
```
node tools/test-web.mjs saga-realm --runs=2   → RESULT 272/272 runs=2 SAME   (전: 10분 시간 초과 0/0)
bash tools/precheck.sh → OK
```
전체 진단 시간 > 10분 → 30초. node 규칙 층 24달: 28s → 12s(캐시만), 크롬 전체는 batch 로.

**완료 조건**: 단계 1~3 · 러너 272/272 SAME · precheck OK · `sw.js` VERSION.

**불변 규칙**: 세이브 키·id 불변 · 시뮬레이션 결과(난수 순서·수치) 불변 — 진단 272개가 그대로 통과 · 화면은 한 달이 끝난 뒤 한 번 새로 그린다(중간 상태는 안 그림).

**메모**: 사용자 눈 확인 하나 — 월말(턴 넘기기) 때 지도·성 목록이 제대로 갱신되고 예전보다 덜 버벅이는지. 같은 꼴(`changed` 연타)이 다른 판에도 있는지는 안 봤다(큐 "미작성" 후보: 사가고·사가의숲 월·일 단위 루프).
