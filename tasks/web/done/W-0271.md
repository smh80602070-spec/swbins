# W-0271 운영툴 — 운영 콘솔(saga-web/tools/ops :8802) + 라이브옵스 수신(shared/js/ops-client.js)
종류: 체제(운영) · 웹(도구+다섯 판 배선)      상태: **끝**(페이블 10-17 — 사용자 "운영툴도 설계해서 만들어 놔봐 상용화해서 팔게 되면 운영툴을 필요로 할테니")

**목표(한 줄)**: 다섯 판은 서버 없는 정적 웹(세이브·오류 로그가 브라우저 저장소)이라 "운영" 이 지금은 사람이 파일을 뒤지는 일이다 — 운영자가 한 화면에서 ① 판별 상태(버전·배포·번들·완성도·QC·플레이 QC) ② 라이브옵스(공지·점검·최소 버전·이벤트 기간)를 **코드 안 고치고** 내보내고 ③ 플레이어 지원(세이브·오류 로그 붙여넣어 읽기) ④ QC·플레이 QC·배포 확인을 단추로 돌리는 **운영 콘솔**을 두고, 다섯 판이 부팅 때 `shared/ops/live.json` 을 읽어 공지·점검 띠·새 버전 띠를 띄우는 수신 스크립트를 단다.

**설계(상용화 때 어디까지가 이 도구 몫인가)**:
- 지금 구조(정적 호스팅·브라우저 저장소)에서 할 수 있는 운영 = **배포물에 실리는 데이터 파일**(live.json)로 하는 운영이다. 공지·점검·최소 버전·이벤트 기간이 그것. 적용 지연은 Pages 배포 시간(몇 분).
- 서버가 있어야 되는 운영(계정·세이브 동기화·결제·실시간 지표·개별 플레이어 조치·치트 감지)은 이 도구가 **자리만** 둔다: `DG.ops.track(event, data)` 링버퍼(100건, localStorage) — 서버가 생기면 그 버퍼를 보내는 한 줄만 바꾼다. 콘솔의 "지원" 탭은 사용자가 보낸 JSON(세이브·오류·track)을 붙여넣어 읽는다(_admin "세이브 내보내기"·"오류 기록" 과 짝).
- 이벤트 기간의 배율(경험치·드롭)은 데이터 자리(`events[].tunes`)만 두고 판 코드 적용은 각 판 티켓 몫(판의 `core.setTune` 은 저장돼 이벤트 끝난 뒤 남는다 — 메모리만 적용하는 길을 판마다 봐야 한다).
- 보안: 콘솔은 로컬(127.0.0.1)만 듣는다. live.json 은 공개 파일이라 비밀 없음. 콘솔은 push 를 안 한다(푸시는 사람이 `bash tools/push.sh`).

**파일**: 새 `saga-web/tools/ops/ops.mjs`(node 한 파일, :8802, 의존 없음) · 새 `saga-web/tools/ops/index.html` · 새 `saga-web/shared/ops/live.json` · 새 `saga-web/shared/js/ops-client.js` + `tools/sync-shared.mjs` 표 한 줄 + 다섯 판 `js/ops-client.js` 사본·`js/manifest.json`(menu-grid.js 뒤)·`index.html`(gen-index)·`dist/app.js`(bundle)·`sw.js` VERSION · `saga-web/tools/run-tools.bat`(:8802 줄) · `saga-web/tools/index.html`(도구 목록 줄, 있으면).

**단계**:
① `ops.mjs` — GET `/` 콘솔 · GET `/api/overview`(판마다 로컬 sw VERSION·배포 VERSION(results/pw-deploy.json)·번들 최신(bundle --check)·완성도(features.json: 전체/끝/D0/D1, status.mjs 와 같은 셈)·마지막 QC(tools/_out/qc-last.json)·플레이 QC(results/pw-play.json)·바로가기) · GET/PUT `/api/live`(live.json 읽기·쓰기, 꼴 검사) · POST `/api/run`({cmd: qc|play|deploy, games}) 한 번에 하나, GET `/api/run/log` · GET `/shots/…`(playcheck/shots 사진).
② `index.html` — 탭 넷: 현황 / 라이브옵스(공지·점검·최소 버전·이벤트 편집 → 저장) / 지원(세이브·오류·track JSON 붙여넣기 → 요약 표) / 실행(QC·플레이 QC·배포 확인 단추 + 로그).
③ `ops-client.js` — 부팅 3초 뒤 `../shared/ops/live.json`(no-store) → 공지 카드(본 id 는 localStorage `saga-ops/seen/<판>`) · 점검 띠 · 최소 버전 띠(`sw.js` VERSION 과 비교, "새로 고침" 단추) · `DG.ops = { live, track, dump }`. 실패는 조용히(게임을 절대 막지 않는다).
④ 배선: sync-shared 표 → 다섯 판 복사 → `gen-index --add <판> js/ops-client.js --after js/menu-grid.js --index` → `gen-index` → `bundle.mjs <판>` ×5 → sw VERSION ×5.

**검증**: `node saga-web/tools/ops/ops.mjs --check`(서버 안 띄우고 overview 를 한 번 찍고 종료 0) · `node tools/sync-shared.mjs --check` · `node saga-web/shared/build/bundle.mjs <판> --check` ×5 · `node tools/gen-index.mjs --check` · 플레이 QC `pw-play.mjs saga-go --pc` 예외 0(수신 스크립트가 게임을 안 깨뜨림) · live.json 에 공지 하나 넣고 `pw-play` 사진에 카드가 보임.

**완료 조건**: 콘솔 네 탭이 돌고 · 다섯 판이 live.json 을 읽어 공지·점검·새 버전 띠를 띄우고 · 서버 필요 운영은 설계 절에 경계가 적혀 있고 · done/.
