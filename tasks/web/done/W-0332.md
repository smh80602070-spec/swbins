# W-0332 배포 — Pages 가 푸시마다 5~6분 동안 404 로 떨어진다 → 웹만·겹치지 않게 배포(GitHub Actions Pages)
종류: 체제(배포) · 웹(루트 `.github/workflows/`·`tools/push.sh`·README)      상태: **끝**(오퍼스 10-19 — 사용자 Source 전환 뒤 워크플로·첫 배포 실측)

**원인(10-19 측정)**: 저장소가 74,000 파일(saga-web 28k · saga-assets 22k · godot 11k · unity 11k)이라 Pages 기본 배포("pages build and deployment", 브랜치 소스)가 **한 번에 5.5분**(05:51~07:19 사이 8번 = 88분 중 44분이 배포 중). 배포 중엔 판 폴더가 `Page not found`(07:17~07:18 실측 — 다섯 판 전부 404, 루트는 200) 로 떨어지고, 푸시가 겹치면 앞 배포가 **취소**된다(07:13 44e16534d cancelled). 네 갈래 세션이 각자 푸시하니 공개 주소가 낮 동안 절반은 안 열린다. 사용자 스크린샷 07:11 = 07:09 배포 중.

**목표(한 줄)**: 배포를 ① **웹 파일만**(루트 `index.html` + `saga-web/` — `tools/playcheck/chrome-prof*`·`results`·`shots` 제외) ② **겹치지 않게**(`concurrency: group: pages, cancel-in-progress: false`) ③ **웹이 바뀐 푸시에만**(`paths: [saga-web/**, index.html]` — 고돗·유니티·자체툴·tasks 푸시는 배포 안 함) 하는 GitHub Actions 워크플로(`actions/configure-pages`·`upload-pages-artifact`·`deploy-pages`)로 바꾼다. 배포 시간 목표 ≤ 2분, 404 창 0(deploy-pages 는 새 배포를 통째로 바꾼다 — 실측으로 확인).

**사용자 결정(필요)**: 저장소 Settings → Pages → Build and deployment → Source 를 **"GitHub Actions"** 로 바꿔야 한다(사람만 할 수 있는 클릭 한 번). 바꾸기 전엔 워크플로를 올려도 기본 배포가 같이 돈다.

**파일**: 새 `.github/workflows/pages.yml` · `tools/push.sh`(배포 재확인 5분 → 워크플로 끝 기다리기: `curl api.github.com/repos/<o>/<r>/actions/runs?per_page=1` status 로, `--deploy-later` 그대로) · `saga-web/tools/playcheck/pw-deploy.mjs`(배포 버전 비교 그대로) · 루트 `README.md` "어디서 도는가" 한 줄 · `tasks/README.md` 는 안 건드림

**단계**: ① 워크플로 작성(artifact 에 `index.html`·`saga-web/` 만, `.nojekyll` 포함, 제외 목록) ② 사용자 Source 전환 ③ 첫 배포 시간·404 창 측정(배포 중 10초마다 다섯 판 curl) ④ push.sh 배포 대기 줄 ⑤ README 한 줄 ⑥ 고돗·유니티 푸시로 배포가 안 도는지 확인

**검증**: 배포 중 `curl` 다섯 판 전부 200 유지 · 배포 ≤ 2분 · `node saga-web/tools/playcheck/pw-deploy.mjs` 다섯 판 같음 · 고돗 전용 푸시 뒤 워크플로 안 돎

**완료 조건**: 웹 푸시 → 2분 안 배포 · 배포 중 404 0 · 다른 갈래 푸시는 배포 없음 · done/.

**불변 규칙**: `.nojekyll` 유지(`_` 파일) · 세이브 키 안 바꿈 · 워크플로에 비밀 없음(Pages 기본 토큰만) · 기본 배포 끄기는 사용자(Settings) · 실패하면 Source 를 브랜치로 되돌리면 그대로(되돌림 길).
