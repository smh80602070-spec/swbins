# W-0490 2나락 들판을 열린 구역 격자로(W-0488 ③ — 설계 R-0 먼저)
종류: 구조·게임성 · 웹(2나락)      상태: R-0 끝(10-28) — 쪼갠 W-0493·W-0494 가 실행      등급 목표: D2

**배경**: 2나락은 방 하나 = 700×440 논리 크기(dungeon.js ROOM_W·ROOM_H)에 문(doors)·복도로 잇는 방 단위 진행이고 필드 몹은 방 안에 얹힌다(spawnFieldEncounters). 1만리처럼 열린 구역 격자(576m 칸)가 아니다. 방 단위 전투·세이브·층 구조를 안 뜯고 "들판"만 열린 지도로 바꿔야 한다 — 크다.
**R-0 에서 정할 것(설계 한 장)**: ① 열린 들판의 단위(구역 크기·몇 구역·구역 자료 = 시드 해시인지 고정인지) ② 방 문·던전 입구를 구역 안 입구로 놓는 법(들어가면 지금 방 진행 그대로) ③ 구역 경계 넘김 = 공용 zoneCut.hookKey·walls(W-0414·0417) + 위/아래 연출(W-0487 ④ 「위로 하늘·아래로 화면 안 보일 때」— 어느 화면인지 사용자 재현 필요) ④ 2D·3D(dungeon-view·dungeon3d) 같은 규칙 ⑤ 몇 장으로 쪼갤지.
**파일**: saga-web/saga-dungeon/js/dungeon.js·dungeon-view.js·dungeon3d.js·dungeon-room.js · saga-web/shared/js/zone-cut.js. **검증**(R-0 후 확정): `node tools/test-web.mjs saga-dungeon`·`qc.mjs --game saga-dungeon`.
**완료 조건**: R-0 설계 한 장 + 쪼갠 실행 티켓들 커밋. **불변**: 세이브 키·id · 방 단위 전투·층 세이브 · 에셋 안 만듦.

**R-0 설계 한 장(10-28, 오퍼스)**
- **전제 정정**: 2나락엔 이미 열린 들판이 있다 — world-map.js(칸 CHUNK=200, ±BOUND240칸, WORLD_LIMIT 60000)·dungeon.js boundPlayer ctx.noRoom(방 없는 열린 들판)·field3d(칸 지형)·regionAt(지역 구분)·마을 발판(앵커). 방 700×440 은 던전 안 몫일 뿐 **들판을 새로 격자로 짜지 않는다**(세계 지도 그대로 = 시드 고정). 모자란 것 = ① 구역(region) 경계를 걸어 넘을 때 연출(zoneCut 이 2나락 들판엔 안 걸림 — load-veil 만 netBusy 를 봄) ② 2D 판 들판 몹·진영 밀도가 칸 단위로 안 읽힘.
- ① 단위 = 기존 regionAt(wx,wy).idx(지역) — 새 구조 없음. ② 던전 입구 = 기존 placeSpot/bossSpot/clueSpot 자리(들어가면 지금 방 진행 그대로, 안 건드림). ③ 경계 넘김 = DG.zoneCut.hookKey(()=>regionAt(p.x,p.y).idx, {wait: 3D 짓는 중}) 한 줄 + 3D 는 walls 로 안 지은 땅 가림, 위/아래 연출(W-0487 ④)은 사용자 답 오기 전까지 만들지 않음. ④ 필드 몹 = spawnFieldEncounters 를 칸 단위로 세는 진단 먼저(밀도 측정 → 모자라면 조정). 세이브·방 단위 전투·층 세이브 불변.
- 쪼갠 티켓: **W-0493**(들판 구역 넘김 막) · **W-0494**(들판 몹 밀도 측정·조정).

**메모**: 10-28 R-0 — 위 설계. 사용자 W-0487 ④ 답 오면 위/아래 연출 티켓 추가.
