**목표(한 줄)**: 웹 네 판에 남은 D1 21개 중 3D 그림·연출 기능을 장면별로 실제 띄워 찍고(헤드리스 swiftshader), Claude 가 1차로 눈 판정해 시트 한 장에 ○/△/× 와 메모를 남긴다. 그림이 서고 콘솔 오류 0 이면 D2, 사람 재미·손맛 판정은 시트로 넘긴다.

- 사가블로: `dg.dungeon3d`·`dg.dungeon3d-2`·`dg.dungeon-2`(그림) · `dg.dungeon-8`(들판 확률 사건) · `dg.game-2`(부팅 예외 배너 — 범위 밖)

- 사가스토리: `st.side-view3d`·`st.asset3d`·`st.post3d`·`st.portrait3d`(그림)

**파일**: `saga-web/tools/playcheck/pw-visual-close.mjs`(새 — 판·장면별 촬영 + 그림 지표: 캔버스 크기·그리기 호출·로드 GLB 수·콘솔 오류) · `saga-web/tools/playcheck/shots/visual-20261007/*.png`(생성물, 커밋 안 함 — .gitignore 확인) · `tasks/sheets/web-visual-<날짜>.md`(새 시트, ≤16KB) · 네 판 `features.json`(해당 항목 level·note 만)

**단계**
1. 장면 목록: 판마다 그림 기능 하나당 장면 하나(예: 사가고 마을 3D·인물 가까이·전투 연출 한 합 / 사가블로 던전 방·들판·장비 겉모습 바꾸기 전후 / 사가의숲 2D 구면·3D 마을·초상 / 사가스토리 3D 사냥터·후처리 HIGH↔LOW·초상). 준비는 각 판 `pw-*-close*.mjs` 의 boot 와 같다.
2. 장면마다 1280×720 PNG 한 장 + 지표(`renderer.info` 가 있으면 calls·triangles, 아니면 캔버스 비어 있지 않음 — 가운데 몇 점 픽셀 평균이 단색 아님).
3. Claude 가 PNG 를 Read 로 직접 보고 1차 판정: ○(그림 정상) / △(서지만 어색 — 메모) / ×(깨짐·빈 화면 — 버그 초안 W-NNNN). 시트에 장면·판정·메모·PNG 경로.
4. 그림이 서고 콘솔 오류 0 인 기능은 features `level: "D2"`, note `D2: pw-visual-close.mjs + Claude 눈 1차(시트 web-visual-<날짜>)`. 재미·손맛은 D3 몫이라 시트에 "사람" 칸으로 남긴다.
5. `fs.auto`·`fs.admin` 은 같은 스크립트에 기계 확인 한 줄씩(사가블로 W-0098 의 🤖·사가스토리 W-0097 의 어드민 꼴).

**검증**: `cd saga-web/tools/playcheck && (node serve.mjs C:/swbins/saga-web 8871 &) && node pw-visual-close.mjs` 실패 0(그 서버 PID·크롬 PID 만 끔) · 네 판 `node tools/test-web.mjs <판>` RESULT n/n · precheck OK · `node tools/status.mjs` 에서 네 판 D1 합 21 → 6 이하(net·expansion·game-2·dungeon-8·rogue-action 정도만 남음).
