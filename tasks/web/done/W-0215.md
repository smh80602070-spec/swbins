**목표(한 줄)**: 폰(CPU 느림)에서 GLB 하나 조립(GLTFLoader parse)이 1~6초 걸리는 동안 받기 칸을 쥐어 다음 받기가 늦게 나간다 — 줄 앞 몇 개는 바이트를 미리 받아 두고, 칸이 나면 받은 바이트로 곧장 조립해 네트워크와 CPU 가 서로 기다리지 않게.

**잰 것(R-0, 10-14)**
- `PROBE_INIT`(fetch 감시) 로 폰 흉내 30초: sl_hosang 받기 12.8→16.4초, 다음 받기 시작 22.5초(그 사이 조립) · house_stone 다 받음 26.3초 → 다음 시작 32.0초 · 45초에 GLB 열 개 남짓.

**파일**: `saga-web/saga-dungeon/js/asset3d.js` · `_test.html` · `sw.js` · `features.json` · 번들

**단계**

2. 칸이 나서 그 url 을 시작할 때 bytes 가 있으면 `ld.parse(buf, 그 url 의 폴더, onLoad, onError)`, 없거나 받기 실패면 옛 `ld.load`. 쓴 bytes 는 지움.
3. 진단 +1: prefetchBytes 1 이면 줄에 넣은 가짜 주소 앞 N 개가 바이트 받기를 시작(prefetchState) · 0 이면 안 함.
