# W-0003 `tools/status.mjs` + 트랙 `STATE.md` 생성
종류: 통합      판: 전 트랙(첫 판은 웹 다섯)      등급 목표: (체제) — 완성도 % 가 숫자로

**목표(한 줄)**: `features.json` 다섯 벌과 러너 결과를 읽어 판별 완성도 %·D0/D1 개수·WIP 초과·큰 파일 목록을 표로 찍고, `saga-web/STATE.md` 를 덮어쓴다.

**파일**: `tools/status.mjs`(새) · `saga-web/STATE.md`(생성물, 8KB 상한) · `README.md` "현재" 절(표 한 개로 교체) · `tools/README.md`(한 줄)

**본보기**: 출력 형식은 `SAGA-ARCH.md` §1.1 표. 코드는 `tools/hooks/syntax-check.js` 처럼 의존 없는 node 한 파일.

**단계**
1. 입력: `saga-web/*/features.json` · `tools/_out/test-web.json`(있으면; W-0001 산출). 없으면 러너 열은 `-`.
2. 러너 결과 반영: `tests` 의 이름이 러너 `fails` 에 있으면 그 기능은 표시 열에 `FAIL`(파일의 `level` 은 바꾸지 않는다 — 사람이 R-3 에서 고친다).
3. 표 열: 판 | 기능 수 | D0 | D1 | D2 | D3+ | 완성도 %(D3+ ÷ 전체) | WIP(D0+D1) | WIP>10 ? `초과` : `-` | 러너 n/m.
4. `--big`: js 1,500줄 초과 파일 목록(`saga-web/*/js/*.js`, vendor 제외)과 줄 수. R-4 가 쓴다.
5. `--json`: 같은 내용을 `tools/_out/status.json` 에.
6. `saga-web/STATE.md` 를 통째로 다시 쓴다: 머리 2줄(생성 시각·"손으로 고치지 않는다") + 표 + 큰 파일 상위 10 + `초과` 판 목록. 8KB 넘으면 큰 파일 목록을 5개로 줄인다.
7. 루트 `README.md` "현재" 절의 표를 같은 표로 바꾼다(그 절만, 다른 절 손대지 않음).
8. `--sheet` 는 이 티켓 범위 밖(W-0005).

**검증**
```
node tools/status.mjs               → 다섯 줄 표 + "STATE.md 갱신" 한 줄
node tools/status.mjs --big | head -3
wc -c saga-web/STATE.md              → 8192 미만
```

**완료 조건**: 위 셋 · README "현재" 절이 표로 바뀜 · precheck 통과(README 는 상한 없음, STATE 는 W-0004 가 상한 추가).

**불변 규칙 확인**: features.json 을 쓰지 않는다(읽기만) · 게임 코드 수정 0.
