# W-0067 폰 렌더 예산 — 보이는 품질은 그대로, 안 보이는 비용만(그림자 카메라·AA 중복·픽셀비)
종류: 통합(웹 최적화) · 웹(사가고 먼저)      상태: **작성됨**(페이블 2026-10-05) — W-0065·0066 뒤      등급 목표: D2

**목표(한 줄)**: `world3d.js` 렌더 설정 중 **화질에 안 보이면서 비싼 것**만 조정한다. 사용자 규칙: 텍스처·그림자 품질·해상도를 낮추지 않는다. 그래서 이 티켓은 "낮추기"가 아니라 "같은 그림을 더 싸게" 세 가지만 다룬다.

**지금 상태(확인함, 10-05)**
- `world3d.js:311~319` — `antialias: true`, `setPixelRatio(min(dpr, 1.5))`, `shadowMap.enabled = true`. `post3d.js:83` 주석: 캔버스 AA 는 기본 프레임버퍼에만 걸린다 → 후처리(SSAO·톤) 패스를 쓸 때 **AA 가 중복이거나 무효**일 수 있다.
- 그림자 카메라 범위(`shadow.camera left/right/top/bottom`)·`shadow.mapSize`·`shadow.bias` 가 지역 크기와 맞는지 측정된 적 없다. 범위가 넓으면 같은 mapSize 에서 그림자가 흐려지고(품질 손해) 좁히면 **같은 비용으로 더 선명**해진다.
- 사가고 마을 PERF 예산(Godot 쪽 G-0023 과 별개) 웹은 측정값 없음.

**파일**: `saga-web/saga-go/js/world3d.js`(렌더러·빛·그림자 설정 자리만) · `saga-web/shared/js/post3d.js`·`ssao3d.js`(정본, AA 중복 판단) · `saga-web/tools/playcheck/`(촬영 전후 비교 스크립트, 있으면 재사용) · `_test.html` 항목 "그림자 카메라가 지역 바운드 안".

**단계**
1. 측정: 헤드리스(SwiftShader) 로 마을·포구·고원 3장면 각각 `renderer.info`(draw calls·triangles)·프레임 ms·그림자 카메라 범위 vs 장면 바운드를 표로.
2. 그림자 카메라를 **장면 바운드 + 여유 10%** 로 맞춤(mapSize 는 그대로 — 선명해지면 선명해진 대로 둔다). 흔들림 방지 bias 는 그대로.
3. AA: 후처리 패스가 켜진 설정(MEDIUM 이상, `DG.cfg.ssao`)에서 캔버스 `antialias` 가 무효면 끄고 후처리 쪽 FXAA/SMAA 로 **같거나 더 나은** 가장자리를 확인(촬영 비교). 후처리가 꺼진 설정은 손대지 않음.
4. 픽셀비: 1.5 상한은 유지. 다만 `dpr ≥ 3` 폰에서 1.5 가 아니라 **정수 배율 아님으로 생기는 흐림**이 있는지 촬영으로 보고, 있으면 1.5 → 2 또는 1 중 **더 선명한 쪽**(비용이 아니라 선명도 기준).
5. 전후 촬영 3장면 차이 수치 + 프레임 ms 표를 티켓 메모에.

**검증**: `node tools/test-web.mjs saga-go` 전후 같음(+1 진단) · 촬영 전후 차이가 README 그래픽 게이트 문턱 안(선명해지는 방향은 허용) · 프레임 ms 전후 표 · `bash tools/precheck.sh` OK.

**완료 조건**: 단계 1~5 · 흐려지거나 거칠어진 장면 0 · 수치 표.
