**목표(한 줄)**: 판 폴더에 **빌드 산출물** `dist/app.js` 하나를 놓아 폰이 116번 요청·파싱하던 것을 1번으로 줄인다. 복사(sync-shared)도 참조(../shared)도 아니고 산출물이라 `sw.js`·GitHub Pages 하위 경로·`run.bat` 제약을 다 만족한다. 화질·동작 변경 0.

**지금 상태(확인함, 10-05)**
- 사가고 `index.html` script 태그 116(module 0), JS 4.5MB, `js/vendor/three.iife.js` 740KB 가 다섯 판에 각각. `js/manifest.json`(`index`·`test` 두 목록) ↔ html 의 script 줄은 `tools/gen-index.mjs --check` 가 지킨다.
- `saga-web/shared/build/build-single.mjs` 가 이미 css/js 를 한 html 에 녹이는 방식을 안다(단독판). esbuild 는 설치 안 됨(npm 은 됨 — `tools/glb-compress/node_modules` 있음).
- 코드는 전역(`DG`·`THREE`) IIFE 스타일이라 **이어 붙이기 + 압축**만 안전하다. three 트리쉐이킹(ESM import 전환)은 범위 밖.

**파일**: 새 `saga-web/shared/build/bundle.mjs`·`package.json`(esbuild devDependency, `node_modules` 는 .gitignore) · `tools/gen-index.mjs`(번들 모드: manifest `"bundle": "dist/app.js"` 면 index 의 script 줄을 그 하나로 검사) · 사가고 `js/manifest.json`·`index.html`·`sw.js`(캐시 목록 113 → `dist/app.js` + VERSION) · 산출물 `saga-web/saga-go/dist/app.js`(커밋 — ARCH §8-4 산출물 커밋) · `tools/precheck.sh`(번들이 manifest 보다 낡으면 FAIL 한 줄).

**단계**
1. `bundle.mjs <판>`: manifest `index` 목록 순서대로 파일을 읽어 esbuild `transform`(minify, target es2018, sourcemap 외부)으로 **순서 보존 이어 붙이기** → `dist/app.js`·`app.js.map`. vendor 도 포함. 끝 줄 `BUNDLE_OK 크기`.
2. `gen-index.mjs` 번들 모드 + `--check` 가 `dist/app.js` 의 mtime/해시가 manifest 의 원본들보다 새것인지 본다(낡으면 FAIL "node saga-web/shared/build/bundle.mjs saga-go").
3. 사가고 적용: manifest 에 `bundle` 칸, index.html script 줄 1개, `sw.js` 캐시 목록을 `dist/app.js` 로, VERSION +1. `_test.html` 은 **원본 파일 그대로**(진단은 파일 단위로 깨진 자리를 찾아야 하므로).
4. 검증·측정: `node tools/test-web.mjs saga-go` 전후 같음 · 헤드리스로 index 열어 콘솔 오류 0 · 요청 수·전송 KB 전후 표(티켓 메모).
5. 넷 확장: 사가블로·숲·스토리·국지 같은 절차(판마다 커밋 하나). `precheck.sh` 에 번들 신선도 검사.

**검증**: `node saga-web/shared/build/bundle.mjs saga-go` → BUNDLE_OK · `node tools/gen-index.mjs --check` OK · `node tools/test-web.mjs saga-go` RESULT 전후 동일 · `bash tools/precheck.sh` OK.

**완료 조건**: 다섯 판 index 의 script 태그 ≤ 3 · 전송 KB 30% 이상 감소(압축만으로, 못 미치면 수치만 적는다) · 동작·화질 변경 0 · 단독판(build-single) 깨지지 않음.
