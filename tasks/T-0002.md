# T-0002 웹 다섯 판 `features.json` 첫 채우기
종류: 측정      판: 웹 다섯      등급 목표: (체제) — 완성도 % 의 분모

**목표(한 줄)**: 각 판 PLAN §3 "현재 시스템 지도" 표를 `saga-web/<판>/features.json` 으로 옮겨, 기능마다 등급(D0~D4)·파일·진단 이름을 기계가 읽게 한다.

**파일**: `saga-web/saga-go/features.json` · `saga-dungeon/…` · `saga-forest/…` · `saga-story/…` · `saga-realm/…`(다섯 새 파일) · `tools/features-schema.json`(새, 1개)

**본보기**: `SAGA-ARCH.md` §3.1 의 JSON 한 줄. 그 키만 쓴다.

**단계**
1. 스키마 `tools/features-schema.json`: 배열, 원소 = `{id, name, files[], tests[], level, verified, fun{}, ticket, since}`. `id` 는 `<판약자>.<kebab>`(go·dg·fs·st·rk). `level` 은 `"D0"|"D1"|"D2"|"D3"|"D4"`.
2. 판마다 PLAN §3 표만 읽는다(`grep -n "^## 3" → 그 절만 sed -n`). 행 하나 = 기능 하나. `files` 는 표의 "주 파일" 열, `name` 은 시스템 이름.
3. `tests`: `_test.html` 에서 `grep -n "t('"` 로 그 기능 이름이 든 진단 이름을 찾아 넣는다(정확히 매칭되는 것만, 추측 금지). 하나도 없으면 `[]`.
4. `level` 규칙: `tests` 가 비어 있으면 `"D0"`. 있으면 `"D1"`(러너 결과는 T-0003 이 다시 판정). D2 이상은 이 티켓에서 주지 않는다. `verified: null`, `fun: {}`, `ticket: null`, `since`: PLAN §3 "상태" 열에 날짜가 있으면 그 날짜, 없으면 `"2026-09-30"`.
5. 표에 "미검증"·"부분" 이라 적힌 행은 `level` 그대로 두되 `name` 끝에 붙이지 않고 `fun` 옆에 `"note": "PLAN §3: 미검증"` 한 칸만.
6. 다섯 파일을 `node -e` 로 스키마 검사(키 누락·level 값·id 중복 0).

**검증**
```
node -e "for (const g of ['saga-go','saga-dungeon','saga-forest','saga-story','saga-realm']) { const a=require('./saga-web/'+g+'/features.json'); const ids=new Set(a.map(x=>x.id)); if(ids.size!==a.length) throw g+' dup'; for(const x of a){ if(!/^D[0-4]$/.test(x.level)) throw g+' '+x.id; } console.log(g, a.length, 'D0', a.filter(x=>x.level==='D0').length) }"
```
→ 다섯 줄, 예외 없음.

**완료 조건**: 다섯 파일 · 각 판 기능 수 ≥ PLAN §3 행 수 · 스키마 파일 · 검증 한 줄 통과.

**불변 규칙 확인**: PLAN 수정 0 · 게임 코드 수정 0 · 세이브 키 무관.
