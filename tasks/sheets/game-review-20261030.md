# 게임 개선점 점검 — 2026-10-30

사용자 요청: 남은 사용량 안에서 게임들의 개선점 확인. Codex와 Astra가 웹 다섯 판의 기획·티켓·관련 소스를 정적으로 검토하고, Godot·Unity는 상태와 검증 기록을 확인했다. 이번에 게임 실행·촬영·성능 측정·소스 수정은 하지 않았다. 아래 우선도는 검토 제안이며 기존 큐를 재배정하지 않는다. Radeon 설정·에셋 생성 작업은 범위 밖이다.

## 먼저 확인할 세 가지

### 1. 5천하 — 장 흐름 복귀 뒤 3D 지도 렌더 중지 (우선 높음)

- **정적 경로 확인:** `saga-web/saga-realm/js/campaign-view.js`의 `backBtn()`은 복귀 시 `open()`만 호출한다. `open()`은 장 흐름 화면을 열지만 3D를 끄지 않는다. `toMap2d()`에는 3D 끄기가 있으나 복귀에는 없다. `src/realm3d/01.js`의 `active()`는 ON·ready만 보고, `02.js`의 `tick()`은 탭 숨김·포커스를 검사한 뒤 렌더한다.
- **영향 추정:** 지도 위에 진영·노선도 화면이 덮여도 숨은 지도 렌더가 지속될 수 있다. 발열·배터리·프레임 경쟁의 실제 크기는 미측정이다.
- **개선 방향:** 장 흐름 진입/이탈과 3D 활성 상태의 수명을 맞춘다. 재진입 시 중복 루프나 카메라 초기화를 만들지 않는다.
- **검증:** 3D 지도 → 장 흐름 → 지도 왕복 중 렌더 호출 증가 여부를 계측하고, 장 흐름 뒤에는 멈추며 지도 재진입 뒤에는 하나의 루프만 재개되는지 확인한다. 2D 복귀도 비교한다. W-0487 ⑤ 후속 검증으로 연결하며 새 3D 기능을 추가하지 않는다.

### 2. 2나락 — 실제 장비와 공격 모션 대응 (우선 높음)

- **확인된 제한:** `saga-web/saga-dungeon/js/actor2d.js:22`는 무기 look 중 staff·gauntlet만 staff·fist로 옮긴다. 칼·창 등은 기본 attack으로 간다. `saga-web/shared/js/mode2d.js`의 `factRole()`에도 공격 시트 폴백이 있다. K-0205 최신 기록도 이 제한과 실제 아이템 장착 장면 미검증을 명시한다.
- **개선 방향:** 이미 적용된 `elf_001` 시트를 먼저 재사용한다. 무기 look → 보유 클립 → 폴백 사유를 표로 만들고, 없는 시트만 K 요청으로 분리한다. 전 무기 지원 완료로 표시하지 않는다.
- **검증:** 실제 장착으로 지팡이·장갑·칼·창을 각각 바꾸고 방향 전환, idle/walk/run/attack, 파손 무기·맨손을 비교한다. 공격 자세와 표시 장비가 같은 행동으로 읽히는지 확인한다. 장비를 코드로 주입한 확인과 실제 장착 흐름을 구분한다.

### 3. Unity 4종횡 — 마지막 파도 성능 예산 (우선 높음, 기존 대기)

- **기존 실패 근거:** `tasks/unity/U-0247.md`의 10-28 최종 기록은 렌더러 79/197 통과, 삼각형 702313/347007 실패다. HUD 겹침과 적 위치 뭉침은 수정 기록이 있으므로 다시 새 결함으로 제안하지 않는다.
- **개선 방향:** 기존 K-0203 LOD 산출과 배선 상태를 먼저 확인한다. 현재 큐의 성능 대기를 유지하고 적 수·모델 전체 재생성을 임의로 선택하지 않는다.
- **검증:** 동일 카메라·품질·마지막 파도 8마리 조건에서 예산을 재측정하고, 양쪽 필드 끝 스폰과 전신 실루엣도 확인한다. 기능 진단 성공만으로 성능 실패를 닫지 않는다. 이번에는 Unity 실행이나 LOD 적용 여부를 새로 검증하지 않았다.

## 완료율 해석과 중복 작업 방지

- `tools/status.mjs:24`는 D2·D3·D4를 모두 완료율에 포함한다. Godot 상태표 100%를 모든 실제 화면·기기·시나리오가 통과했다는 뜻으로 읽지 않는다. G-0426은 네 판의 신규/구 저장·첫걸음 진행 probe를 확인했지만, 해당 기록의 전체 precheck 실패와 건너뛴 항목도 별도로 남아 있다. 이번 점검만으로 Godot 기능 결함을 새로 확정하지 않는다.
- Godot의 다음 확인은 기존 첫걸음 5단계가 실제 화면에서 읽히는지와 중간 저장 후 이어하기다. 이미 구현된 튜토리얼을 다시 만드는 제안은 제외한다. Unity U-0250~0252 장 흐름은 기존 큐를 따른다.
- 5천하의 옛 재미 격차표 후보인 ZOC·용병 고용·전직 분기·엔딩 분기는 현재 `tactics.js`, `campaign.js`, `realm-class.js`에 구현이 확인됐다. 신규 기능으로 재제안하지 않고 저장/재개·보상 중복·화면 흐름 검증 대상으로 취급한다.
- 1만리 W-0472의 NPC 막대·모래 이음은 최신 메모상 에셋에 구워진 문제/이음 타일 부재다. 폐기된 cutout 무기 숨김 가설을 다시 구현하지 않는다. 기존 K 산출 유무 확인이 먼저다.

이번 산출물은 개선점 검토다. 기능 완료·시각 통과·성능 통과를 새로 선언하거나 티켓을 닫지 않는다. 소스 수정은 각 기존 티켓의 담당 갈래에서 검증 조건을 확정한 뒤 진행한다.
