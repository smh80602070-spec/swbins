# U-0001 `Editor/PlaytestKit.cs` — 세이브 격리·Check·오류 카운트
종류: 닫기      판: DUNGEON 먼저      등급 목표: (체제) — Playtest 가 흔들리지 않게

**목표(한 줄)**: Playtest 107개가 각자 하는 일(세이브 파일 백업·복원, PASS/FAIL 집계, 로그 오류 세기)을 `PlaytestKit` 하나로 모으고, 세이브 잔존으로 갈리던 `PlaytestDungeonHeadless` 에 먼저 적용한다.

**파일**: `saga-unity/Assets/Editor/PlaytestKit.cs`(새) · `Assets/Editor/PlaytestDungeonHeadless.cs`(호출 교체) · `docs/HOW_TO_PLAYTEST.md`(한 절)

**본보기**: `Assets/Editor/PlaytestMobileGraphics.cs`(73줄 — `Run()`·`Fail()`·`Debug.Log($"{T} OK …")` 꼴). `PlaytestGoAchieve.cs` 49행 `Path.Combine(Application.persistentDataPath, "save.json")` 이 격리 대상.

**단계**
1. `PlaytestKit`(static, namespace `Saga.EditorTools`):
   - `IDisposable IsolatedSaves(params string[] names)`: `persistentDataPath` 의 `save*.json`(인자 없으면 전부)을 임시 폴더로 옮기고 Dispose 에서 되돌린다(try/finally 보장). 실행 중 만들어진 파일은 지운다.
   - `void Check(bool cond, string msg)` + `int Fails` + `string Tag`; `Fail(msg)` 는 `Debug.LogError($"{Tag} FAIL {msg}")`.
   - `IDisposable ErrorCounter()`: `Application.logMessageReceived` 로 `LogType.Error|Exception` 을 세고 Dispose 에서 `Fails += count`(단, `[PlaytestHeadless]`·`FAIL` 접두는 중복 세지 않는다).
   - `void Summary(string name)`: `Debug.Log($"[{name}] {(Fails==0?"OK":"FAIL "+Fails)}")`.
2. `PlaytestDungeonHeadless.Run()`: 맨 앞 `using var s = PlaytestKit.IsolatedSaves("save_dungeon.json"); using var e = PlaytestKit.ErrorCounter();` 로 감싸고, 기존 Fail 집계는 `PlaytestKit.Check` 로 바꾼다. 다른 Playtest 는 손대지 않는다(U-0010).
3. `HOW_TO_PLAYTEST.md` "Playtest 쓰는 법" 절에 Kit 세 함수 5줄.

**검증**
```
cd saga-unity && bash tools/unity-batch.sh -- "/c/Program Files/Unity/Hub/Editor/6000.3.24f1/Editor/Unity.exe" -batchmode -nographics -projectPath . -executeMethod Saga.EditorTools.PlaytestDungeonHeadless.Run -logFile .utmp/u0001.log ; grep -E "PlaytestDungeonHeadless\] (OK|FAIL)|error CS" .utmp/u0001.log
```
→ `OK` 한 줄, `error CS` 0. **실제 `save_dungeon.json` 이 있는 채로** 돌려도 OK(격리 효과). 실행 전후 세이브 파일 mtime 이 같다.

**완료 조건**: 위 · Kit 150줄 안 · 다른 Playtest 컴파일 그대로.

**불변 규칙 확인**: 사실 몸 묶음 없는 PC 면 `Missing Prefab` FAIL 은 코드 탓 아님(메모에 적고 그 항목만 기준선 비교) · `-quit` 는 Playtest 규칙대로(PROJECT_STATE 알려진 오류) · 설정 4파일은 unity-batch 가 원복 · 다른 세션이 Unity 를 쓰는 중이면 배치 실행을 미룬다.

**메모(체크포인트)**: ✔ 단계 1~3 (2026-10-01). 검증 OK — `[PlaytestDungeonHeadless] OK - 10 frames, no errors`, error CS 0, 실제 save_dungeon.json mtime·md5 전후 동일. Kit 131줄. 편차: `_hadError` 121곳은 그대로 두고 프로퍼티(PlaytestKit.Mark)로 받음 · ErrorCounter 는 접두 대신 Kit 자신의 Fail 로그만 제외(접두 로그는 놓치지 않으려 센다) · 실패 수는 Dispose 가 아니라 실시간 합산. 함정: `using System;` 을 넣으면 `Object` 모호(CS0104) — 완전 이름 사용.
