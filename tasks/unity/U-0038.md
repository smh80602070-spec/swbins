# U-0038 Unity 무기 3D — 코드로 짓는 칼날을 K-0030 무기 세트로(DUNGEON `WeaponVisual`·GO 무기 모양)
종류: 새기능 · 유니티      상태: **점검 끝 · 방향 선택 대기**(R-0 2026-10-04) — 시작 조건: 없음(GLB 이미 `Resources/World/wpn_*`) — 소켓 시험 판정은 K 쪽      등급 목표: D1

**목표(한 줄)**: DUNGEON `WeaponVisual` 은 무기 메시가 없어 자루+칼날을 코드로 짓는다(주석: "무기 메시 자산이 없어"). 자체툴이 `Resources/World/wpn_*`(axe·bow·… 등급 common·rare·legend)를 올렸으니 장착 무기를 이 GLB 로 쥐게 한다. 소켓·등급 림은 기존 규칙을 따른다.

**파일(확인함)**: `saga-unity/Assets/Games/SagaDungeon/Player/WeaponVisual.cs`(`CharacterVisual.FindOrCreateWeaponSocket`) · `Data/ItemData.cs`(`WeaponShape`·`Grade`) · GO 쪽 무기 모양 `Games/SagaGo/Data/GoWeapons.cs`(`Type`)와 무기를 손에 쥐는 코드(`grep -rn "Weapon" Games/SagaGo/Combat Games/SagaGo/World` 로 먼저 확인) · `Resources/World/wpn_*.glb`.

**단계**
1. `wpn_*` 이름 표(종류·등급)와 `ItemData.WeaponShape`/`GoWeapons.Type` 대응표(맞는 것만, 없으면 기존 코드 칼날).
2. `WeaponVisual` 이 대응 GLB 를 소켓에 붙인다(크기·방향 맞춤, 등급 림은 재질 값만), 없으면 기존.
3. GO 무기도 같은 표로(쥐는 코드가 이미 있을 때만, 없으면 이 티켓 밖으로 메모).
4. 진단: 표 id 가 읽힘·소켓 부모 확인, GUI 촬영 한 장(손에 쥔 모양).

**검증**
```
bash saga-unity/tools/unity-batch.sh -- "<Unity.exe>" -batchmode -nographics -projectPath saga-unity -logFile <로그> -executeMethod Saga.EditorTools.<새 진단>.Run   → [..] OK, 컴파일 오류 0
기존 관련 Playtest 같은 값 · bash tools/precheck.sh → OK
```

**완료 조건**: 단계 1~4 · 장착 무기가 GLB 로 보인다 · 맞는 모델 없는 무기는 기존 칼날.

**불변 규칙**: 에셋(GLB·그림·`.meta`)은 만들거나 고치지 않는다(K 갈래·K-0019 몫) · 세이브 키·id 불변 · 이름 정책 · 다른 세션이 엔진을 쓰는 중이면 먼저 확인.

**메모(착수 전 점검, 2026-10-04)**: `WeaponVisual` 은 칼날 **한 개**를 등급·모양(Blade·Lance·Gauntlet)에 따라 `localScale` 만 바꾸는 구조이고, 이 이름(`WeaponBlade (generated)`)과 길이를 진단이 직접 읽는다(`PlaytestHeadless`·`PlaytestDungeonHeadless` "칼날 길이 0.55→0.71", `PlaytestGoPartyBodies` 가 `FindDeep(hero, "WeaponBlade (generated)")`). GLB 로 바꾸면 이 진단 셋과 소켓 방향·손잡이 위치(손 본 근사)를 함께 손봐야 하고, 쥔 모양은 화면으로만 확인된다. **결정 필요**: (A) GLB 를 "칼날 자리의 시각"으로만 얹고 `WeaponBlade (generated)` 오브젝트는 숨겨 유지(진단·길이 규칙 불변, 추천), (B) 전면 교체 + 진단 수정. 방향을 정하면 소켓 확인 GUI 촬영부터.
