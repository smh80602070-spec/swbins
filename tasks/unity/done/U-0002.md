# U-0002 asmdef 셋(SagaStory·SagaRealm·SagaTitle)
종류: 통합      판: STORY·REALM·Title      등급 목표: (체제) — 재컴파일 범위·참조 방향

**목표(한 줄)**: asmdef 가 없어 Assembly-CSharp 에 섞이는 Story·Realm·Title 에 SagaGo 와 같은 꼴의 asmdef 를 만들어 판별 어셈블리로 나눈다.

**파일**: `saga-unity/Assets/Games/SagaStory/SagaStory.asmdef`·`SagaRealm/SagaRealm.asmdef`·`SagaTitle/SagaTitle.asmdef`(새 3, `.meta` 는 Unity 가 만든 것을 커밋)

**본보기**: `Assets/Games/SagaGo/SagaGo.asmdef`(references: SagaCore·TextMeshPro·Cinemachine·Timeline·InputSystem·RP Core·URP Runtime).

**단계**
1. SagaGo.asmdef 를 복사해 `name`·`rootNamespace`(`Saga.Story`·`Saga.Realm`·`Saga.Title`) 만 바꾼다. references 는 같게 시작.
2. 배치 컴파일(`-quit` 만, executeMethod 없음) → 로그 `error CS` 를 본다. 판 코드가 다른 판 타입을 부르면 그 판 asmdef 의 `references` 에 상대 어셈블리를 더한다. **순환 참조가 나오면** 그 호출을 메모에 적고 되돌리고 멈춘다(설계 판단).
3. Editor 코드(Assembly-CSharp-Editor)는 autoReferenced 로 판 어셈블리를 본다 — 컴파일 오류가 없으면 손대지 않는다.
4. 판별 Playtest 하나씩(STORY `PlaytestStorySlice.Run`·REALM `PlaytestRealmSlice.Run`·Title `PlaytestSagaCredits.Run`) 돌려 OK.

**검증**
```
cd saga-unity && bash tools/unity-batch.sh -- "<Unity.exe>" -batchmode -nographics -quit -projectPath . -logFile .utmp/u0002.log ; grep -c "error CS" .utmp/u0002.log   → 0
(위 Playtest 셋 각각) grep -E "\] (OK|FAIL)" → OK
```
