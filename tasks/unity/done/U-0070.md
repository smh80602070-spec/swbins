# U-0070 사가만리 지상 탈것 속도 배율이 Windows 대상에서 안 먹음(안드로이드 대상은 OK)
종류: 버그 · 유니티(사가만리)      상태: 끝(2026-10-09) · 작성 R-0 2026-10-09 — 초안은 같은 날 R-5 가 U-0068 재검증 중 발견)      등급 목표: 없음(un.go 탈것 진단 회귀 지움)

**목표(한 줄)**: 활성 빌드 대상이 Windows 여도 `PlaytestGoMount.CheckSpeed` 가 탄 채 걷는 거리 ×2.1 을 재게 한다 — 원인이 시험의 경계값이면 시험을, 게임 판정이면 게임을 고친다.

**재현(10-09 확인)**
1. `-buildTarget StandaloneWindows64` 로 `PlaytestHeadless` → `mount FAIL - 흰 말 걷는 거리 배율 1.00 ≠ 2.1 (안 탄 3.00m · 탄 3.00m)`. TryRide 는 참(R-5 진단 보강으로 확인).
2. 같은 코드 `-buildTarget Android` → mount OK·판 전체 OK.

**원인 후보(코드 읽기, 미측정)**: `Walked()`(PlaytestGoMount.cs 138행)가 `start = GoStory.GridPos(3.7, 4.1) + 0.3m` 로 `Teleport` → `PlayerController.Teleport`(193~205행)는 `HeightAboveGround() < 0.3f` 일 때만 Ground, 아니면 Air + **탈것에서 내림**(203행). 시작 높이 0.3 이 그 경계와 같고, `GridPos` 는 **반올림한 칸**(3·4)의 `GroundHeight` 라 3.7·4.1 의 실제 충돌면과 어긋날 수 있다 → 대상별로 그 자리 충돌면(지형 메시·소품 콜라이더·품질별 LOD)이 조금만 달라도 판정이 뒤집힌다. 안 탄 채 거리는 3.00m 로 같으니 걷기 자체는 정상.

**파일**: `saga-unity/Assets/Editor/PlaytestGoMount.cs`(Walked·CheckSpeed) · 원인이 게임 쪽이면 `Assets/Games/SagaGo/Player/PlayerController.cs`(Teleport 202~203행) · 새 `saga-unity/docs/playcheck/d2-u0070-<날짜>.json`

**단계**
1. 측정: Walked 의 Teleport 직후 `HeightAboveGround()`·발밑 레이캐스트가 맞은 콜라이더 이름·`GridPos` y 를 `Debug.Log` 로 남기고 Windows·Android 대상 각각 `PlaytestHeadless` 한 판(대상을 바꾸면 첫 판에 재가져오기 몇 분).
2. 갈래: ① 높이가 0.3 근처이고 맞은 것이 같은 땅이면 = **시험 경계값** → 시작 높이를 발밑 레이캐스트로 잰 실제 땅 + 0.05m 로(또는 Teleport 뒤 한 Step 으로 내려앉힌 다음 TryRide). 게임 코드 무변경. ② 대상마다 맞은 콜라이더가 다르면 = **게임 판정** → 그 콜라이더가 대상별로 왜 다른지 찾아 고침(Teleport 의 0.3 판정·Dismount 규칙은 109-15 설계라 유지).
