# U-0008 PLAN 372KB → `PLAN.md`(≤100KB) + `docs/spec/`
종류: 통합 · 문서      등급 목표: (체제) — 새 세션이 PLAN 을 통째로 읽지 않아도 되게

**목표(한 줄)**: 장 번호·제목은 PLAN 에 두고, 긴 본문과 표 상태 칸을 `docs/spec/*.md`(각 <30720B)로 **원문 그대로** 옮긴다. 내용은 지우지 않는다.

**조사(R-0)**: 372,475B 중 `# 109` 가 169,650B — 표 하나(32줄)이고 **14번 줄 하나가 111,950B**(상태 칸 111,786B, 세션 기록 한 덩어리), 10·11·12·13·15·16번 줄 상태 칸이 합 42.7KB. 나머지: `# 110` 27.7KB · `## 101-2` 31.5KB · `## 101-3` 8.5KB · `106-1~10` 34.7KB · `107-1~8` 23.2KB · `## 3.1` 14.7KB. 이 합 ≈292KB 를 옮기면 PLAN ≈ 83KB. `docs/spec/` 는 아직 없다.

**파일**: `saga-unity/tools/plan-split.py`(새) · `saga-unity/PLAN.md` · `saga-unity/docs/spec/*.md`(새) · `saga-unity/CLAUDE.md`(크기 문장 한 곳)

**본보기**: 없음(새 도구). G-0005 도 같은 도구를 쓸 수 있게 `PLAN.md` 경로를 인자로 받는다.

**단계**
1. 착수 때 `BASE=$(git rev-parse HEAD)` 를 메모에 적는다. `plan-split.py` 세 명령 — `chapter <시작정규식> <끝정규식> <spec이름>`: 그 사이 줄을 spec 으로 옮기고 PLAN 엔 시작 제목 한 줄 + `> → docs/spec/…` 한 줄만(30720B 넘으면 줄 경계에서 `-1`·`-2`) · `cell <표 줄 정규식> <spec접두>`: 마지막 칸을 ` · ` 경계에서 ≤28KB 로 쪼개 `…-1..n.md`, 칸엔 `→ spec` 과 맨 끝 "다음 = …" 문장만 · `verify <BASE>`: BASE PLAN 의 모든 줄이 PLAN+spec 에 원문 그대로(cell 은 조각 이어붙여) 있고 `^#{1,2} ` 제목이 PLAN∪spec 에 다 있나. spec 첫 줄은 `<!-- 옮김: PLAN.md <장> · BASE <해시> -->`(제목 아님). PLAN.md 는 Edit/Write 대신 이 스크립트로만 고친다(훅이 날짜 세션 문단을 막는다).
2. 1커밋씩, 매번 `verify` OK: ① 109 14번 줄(`cell`) ② 109 10·11번 줄 ③ 109 12·13·15·16번 줄 ④ `# 110` ⑤ `## 101-2`~`## 102-1` 앞 ⑥ `## 101-3` ⑦ `## 106-1`~`## 107-1` 앞 ⑧ `## 107-1`~`# 108` 앞 ⑨ `## 3.1`~`## Phase 1` 앞.
3. `CLAUDE.md` 의 "PLAN.md`(372KB — ≤100KB 로 줄이는 중, U-0008)" → "PLAN.md`(≤100KB, 긴 스펙은 docs/spec/)".
