# U-0022 Unity 를 Godot 과 같은 툰 노선으로 — 셰이더·재질 규칙(코드 배선만)
종류: 새기능 · 유니티      상태: **진행중**(R-0 2026-10-01, 사용자 2026-10-02 "유니티는 툰 전환으로 변경")      등급 목표: D1→D2

**목표(한 줄)**: 사용자 지시(2026-10-01) "유니티도 사가고돗과 동일하게 간다. 파판식 사실풍은 불가" 를 코드로 받는다. K-0017(툰 GLB 건물·지물·지형·탈것)·K-0018(공방 툰 몸)이 `Assets/` 에 놓이면 Unity 가 그것을 Godot 과 같은 모양으로 그린다. **에셋 파일은 이 티켓이 안 고친다**(자체툴 몫, K-0019).

**파일(확인함)**: 새 `saga-unity/Assets/Shaders/CelToon.shader`(URP, 본보기 = Godot `saga-godot/saga_core/shaders/cel_vertex_color.gdshader`·`cel_outline.gdshader` — Unity 에는 지금 툰 셰이더가 없다) · 재질 규칙 `Assets/Editor/` 의 씬 빌더(`BuildFromLayout.cs` 등)가 툰 재질을 쓰게 하는 한 줄 · `PLAN.md` 106·110 의 사실풍 문장(날짜 세션 기록 금지 — 규칙만) · ARCH §4.5 표의 "Unity(파판16)" 줄은 공통 파일이라 안 고침(메모로 알림)

**단계**
1. 본보기 두 셰이더를 읽고 Unity URP 로 옮길 수 있는 범위(셀 단계 3·외곽선·정점색/바탕색 한 장)를 정한다. Shader Graph 리플렉션은 09-22 에 막혔으니 **HLSL 로 직접** 쓴다.
2. `CelToon.shader` + 재질 1개 → `unity-batch.sh` 로 컴파일 오류 0 확인 → 비교 장면 한 곳(사가고 마을)에서 Godot 스크린샷과 나란히(시트, 사용자 판정).
3. 판정 통과 시 씬 빌더가 K-0017 GLB 에 툰 재질을 입히도록 규칙 추가(기존 사실 에셋은 그대로 둬 되돌릴 수 있게).

**검증**: `bash tools/unity-batch.sh -- …` 컴파일 오류 0 · Playtest 기존 값 전후 같음 · 시트 1장 · `precheck.sh` OK.

**완료 조건**: 단계 1~2 + 사용자 판정 한 줄(Godot 과 같아 보인다 / 아니다). 3 은 "같다" 일 때만.

**불변 규칙**: 에셋(GLB·텍스처·FBX) 수정 0 · PlayerPrefs 키·세이브 불변 · 컴파일 확인은 배치 로그로만 · 다른 세션이 Unity 를 쓰는 중이면 기다린다.

**메모(체크포인트)**: 이전 ARCH §8 "Unity 툰 전환: 안 한다 — 사실풍 유지"는 이 사용자 지시로 바뀐다(공통 파일은 R-1 에서 정리).
2026-10-02: 사용자가 툰 전환을 확정했다. U-0021(진행중, 다른 세션)이 끝나는 대로 다음 차례. 그 전까지 Unity 에디터·배치가 쓰이는 중이면(`Unity Hub\Editor` 프로세스) 기다린다 — 셰이더 컴파일 확인은 배치 로그로만.
