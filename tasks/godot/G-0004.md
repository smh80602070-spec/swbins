# G-0004 `saga_core/data/save_base.gd` — 다섯 세이브가 extends
종류: 통합      판: 다섯      등급 목표: (체제) — 마이그레이션 계약 한 벌

**목표(한 줄)**: 다섯 `*_save_state.gd` 가 복사해 가진 `_migrate/_migrate_step/SAVE_VERSION/version 거부` 계약을 `save_base.gd` 하나로 올리고, 다섯 파일은 `extends` 로 자기 `_migrate_step` 만 남긴다.

**파일**: `saga-godot/saga_core/data/save_base.gd`(새) · `games/saga_go/data/save_state.gd`·`saga_dungeon/data/dungeon_save_state.gd`·`saga_forest/data/forest_save_state.gd`·`saga_story/data/story_save_state.gd`·`saga_realm/data/realm_save_state.gd`

**본보기**: `dungeon_save_state.gd` 213행 `_migrate()`(가장 짧음) — 이 본문이 base 로 간다.

**단계**
1. 다섯 파일의 `_migrate` 본문을 `diff` 로 대조("GO와 완전히 같은 계약" 주석). 다르면 차이를 메모에 적고 **가장 엄격한 쪽**(높은 version 거부·null 반환)을 base 에.
2. `save_base.gd`: `class_name SagaSaveBase extends Node`. `const` 는 못 물려주니 `func save_version() -> int` 가상 + `func save_path() -> String` 가상 + `func _migrate(data)`(base 본문, `save_version()` 호출) + `func _migrate_step(from:int, data:Dictionary) -> Variant: return null`(기본).
3. 다섯 파일: `extends SagaSaveBase`, `SAVE_VERSION`·`SAVE_PATH` 상수는 그대로 두고 `save_version()`·`save_path()` 가 그걸 반환, 자기 `_migrate` 는 지운다. 한 판 바꿀 때마다 probe 돌리고 커밋. `realm_save_state.gd` 는 `_migrate` 만 손댄다(분리는 G-0006).
4. project.godot autoload 는 그대로(경로 안 바뀜).

**검증**
```
GODOT=… bash saga-godot/tools/probe_all.sh --only=save_dungeon,save_forest,save_story,save_realm,story   → fails=0
bash saga-godot/tools/godot_regress.sh   → REGRESS OK
grep -c "^func _migrate(" saga-godot/games/*/data/*save_state.gd   → 다섯 다 0
```

**완료 조건**: 위 셋 · base 60줄 안.

**불변 규칙 확인**: SAVE_VERSION 값 변경 0 · 세이브 파일 이름 변경 0 · 실제 세이브 파일 안 건드림.
