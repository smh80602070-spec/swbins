# G-0120 네 판 세이브 점검을 진짜 왕복으로 — save()·try_load() 를 부르게
종류: 점검 · 고돗(사가나락·사가마을·사가종횡·사가천하)      상태: 닫음 D2(10-09)      등급 목표: D2

**목표(한 줄)**: G-0118 감사(소넷 9f4b97d7c). `tools/probe_save_base.gd` 의 "왕복"은 임시 사전을 SafeFile 로 쓰고 읽을 뿐, 판 세이브의 `save()`·`try_load()` 를 안 부른다(주석도 인정) → 저장 필드가 빠지거나 키가 틀려도 `gd.dg/fs/st/rk.save` 가 통과. 사가만리처럼 경로를 갈아 끼워 진짜 왕복을 본다.

**파일**: `saga-godot/tools/probe_save_base.gd` · 네 판 세이브 스크립트(`games/saga_dungeon/data/dungeon_save_state.gd`·`saga_forest/.../forest_save_state.gd`·`saga_story/.../story_save_state.gd`·`saga_realm/data/realm_save_state.gd` — 실제 이름은 `grep -l "func try_load"` 로) · `saga-godot/saga_core/data/saga_save_base.gd`(있으면 path_override 한 곳에) · 이 티켓

**단계**
1. 사가만리 세이브가 쓰는 점검용 경로 바꾸기(path_override 또는 비슷한 것)를 찾아 같은 꼴을 네 판에(공용 SagaSaveBase 에 두면 한 번).
2. probe_save_base: 새 인스턴스에 판별 값 몇 개를 넣고 → save() → 새 인스턴스 try_load() → 같은 값인지(판마다 v1_check 처럼 필드 목록을 넘김). 진짜 user://save_* 는 안 건드림(앞뒤 파일 해시 같음).
3. 일부러 필드 하나를 저장에서 빼 보면 점검이 FAIL 하는지 한 번 확인(되돌림).

**검증**: `GODOT=<콘솔 exe> bash saga-godot/tools/probe_all.sh --only=save_dungeon,save_forest,save_story,save_realm,save_slots,save_transfer4` fails=0 · `bash tools/precheck.sh` OK.

**완료 조건**: 네 판 점검이 save()·try_load() 를 거쳐 필드를 비교 · 진짜 세이브 안 바뀜.

**불변 규칙**: 세이브 키·버전·경로(실사용) 안 바꿈 · 마이그레이션 동작 안 바꿈.
