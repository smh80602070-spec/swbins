# G-0114 사가만리 마을 그리기 예산 — draw call 최대 275(예산 ≤260)를 화질 안 깎고 줄이기
종류: 측정 · 고돗(사가만리)      상태: 닫음(10-09) — 275→267, 예산 미달은 사용자 결정 대기      등급 목표: D2(probe_perf 창 모드 수치)

**목표(한 줄)**: G-0112 전체 점검에서 창 모드 probe_perf 가 마을 draw call 최대 275·평균 260 으로 PLAN 104-7 예산(≤260)을 넘었다. 어느 노드가 몫을 차지하는지 재고(probe_perf 에 그리기 몫 재기 추가), 같은 메시를 한 MultiMesh 로 묶기·안 보이는 그림자 끄기처럼 **화질을 안 깎는** 낭비만 줄여 마을 최대 ≤260 으로.

**파일**: `saga-godot/tools/probe_perf.gd`(SAGA_PERF_DRAWSHARE — 씬 바로 밑 노드를 하나씩 숨겨 draw call 몫) · 원인 노드의 빌더(측정 뒤 확정, 메모에 적음) · `saga-godot/features.json`(perf 줄 note) · 이 티켓

**단계**
1. probe_perf 에 SAGA_PERF_DRAWSHARE=1: 마을 자리(v_statue) 한 방향에서 씬 바로 밑 노드마다 visible 끄고 draw call 차이를 찍는다.
2. 몫 큰 노드 2~3 을 읽고, 화질 그대로 줄일 수 있는 것(같은 메시 MeshInstance 여럿 → MultiMesh, 멀리서 안 보이는 것 visibility_range, 의미 없는 그림자)을 고른다. 고르는 것은 메모에.
3. 고친 뒤 창 모드 probe_perf 전후 · 촬영 v_statue 등 마을 컷 전후가 같아 보이는지 Claude 판정.

**검증**: `SAGA_PERF_PROBE=1 "$GODOT" --path saga-godot --rendering-method mobile --position -4000,0 --resolution 1280x720 res://games/saga_go/world/TestVillage.tscn` 마을 draw_calls max ≤260 · 손댄 빌더의 probe fails=0 · `bash tools/precheck.sh` OK.

**완료 조건**: 마을 최대 ≤260(아니면 몫 표와 남은 이유를 메모에) · 화면 전후 차이 없음 판정.

**불변 규칙**: 화질 설정·그림자 품질·식생 밀도·시야 거리 안 깎음 · 에셋 안 고침 · 세이브 안 건드림.
