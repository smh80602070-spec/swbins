# G-0010 판별 autoload → `GameBoot` 지연 로드
종류: 통합 · 다섯      상태: **닫음 — 하지 않음(측정·실험 결과, 2026-10-01 R-0)**

**원안**: project.godot autoload 중 판별 것을 빼고 공통 `GameBoot` 하나가 진입 씬을 보고 그 판 것만 `add_child` + `Engine.register_singleton` 한다(참조 이름 그대로). 근거 SAGA-BACKLOG §3.2 "메모리·부팅".

**왜 안 하나 — 둘 다 성립하지 않는다**

1. **안 된다(실험)**: 임시 프로젝트(`boot.gd` 가 `_init` 에서 `Engine.register_singleton("Foo", node)` + `add_child`, 다른 스크립트가 `Foo.hi()` 호출)를 `godot --headless` 로 돌리면 `Parse Error: Identifier "Foo" not declared in the current scope` 로 스크립트 로드가 실패한다. GDScript 파서는 `project.godot [autoload]` 항목만 전역 이름으로 인정한다 — `register_singleton` 은 파서를 못 속인다. 원안의 "위험" 칸이 걱정한 대로다. 되게 하려면 autoload 이름을 쓰는 모든 코드(수백 곳)를 `GameBoot.get("SaveState")` 식으로 바꿔야 해서 "참조 이름은 그대로" 조건이 깨진다.
2. **얻을 게 없다(측정)**: 24개 autoload(공통 1·GO 6·DUNGEON 12·FOREST 1·STORY 2·REALM 1…)를 새 인스턴스로 만들어 `add_child` 하는 비용을 쟀다 — **합계 14.0ms · 206KB**. 첫 프레임까지 부팅 1,659ms · 정적 메모리 59.3MB 이므로 각각 **0.8%·0.35%**. 그중 REALM 하나가 12.4ms·153KB(`_ready` 가 성·적·문답을 채움), 나머지 23개는 개당 0.04~0.15ms·1.4~7.6KB.

**남는 옵션(권하지 않음)**: REALM 등 무거운 `_ready` 를 "진입 씬이 그 판일 때만" 돌게 가드. 이득 ≤12ms 에 세이브·초기화 순서 위험(G-0006 의 `_ready` 순서)을 얹는다 — 하려면 그때 새 티켓.

**조치**: 코드·project.godot 수정 0. SAGA-BACKLOG §3.2 의 해당 줄은 공통 파일이라 이 갈래에서 안 고친다 — 갈래 큐 소유자가 "측정 결과 이득 없음" 으로 정리하면 된다. 재측정이 필요하면 스크래치 SceneTree 스크립트로 `ProjectSettings` 의 `autoload/*` 를 돌며 `load(path).new()` + `add_child` 시간·`Performance.MEMORY_STATIC` 차를 잰다.

**메모**: 임시 프로젝트·측정 스크립트는 스크래치패드에서 지움(저장소에 안 남김).
